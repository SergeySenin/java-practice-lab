# Инициализация и изменение полей объекта

Как поле получает значение при создании объекта и как его можно изменить позднее.
Примеры в таблице показывают отдельные варианты, а не один готовый класс.

| Способ                | Когда                           | Пример                         |
|-----------------------|---------------------------------|--------------------------------|
| Значение по умолчанию | При создании объекта            | `String playerName;` → `null`  |
| При объявлении поля   | При создании объекта            | `String playerName = "Гость";` |
| Прямое присваивание   | Когда поле доступно             | `player.playerName = "Анна";`  |
| Конструктор           | При создании объекта            | `new Player("Анна")`           |
| Сеттер                | При вызове метода               | `player.setPlayerName("Иван")` |
| Другой метод          | При вызове метода               | `player.resetName()`           |
| Нестатический блок    | При создании объекта            | `{ playerName = "Гость"; }`    |
| Делегирование         | При вызове другого конструктора | `this("Гость");`               |

## В каком порядке поле получает значения

Посмотрим на один конкретный класс:

```
class Player {
    String playerName = "Гость";

    {
        playerName = "Анна";
    }

    Player() {
        System.out.println(playerName);
    }
}
```

При вызове `new Player()`:

| Шаг | Что происходит                                    | Значение `playerName` |
|-----|---------------------------------------------------|-----------------------|
| 1   | Поле получает значение по умолчанию               | `null`                |
| 2   | Выполняется присваивание рядом с объявлением поля | `"Гость"`             |
| 3   | Выполняется отдельный блок `{ ... }`              | `"Анна"`              |
| 4   | Конструктор печатает значение поля                | На экране `Анна`      |

Присваивания рядом с полями и отдельные блоки выполняются сверху вниз, как записаны в классе.
Затем выполняются команды конструктора. Это повторяется для каждого нового объекта.

При наследовании конструктор родительского класса
выполняется раньше присваиваний и блоков текущего класса.

## Что важно помнить

* Поля объекта получают значения по умолчанию: например, ссылка — `null`, `int` — `0`,
  `boolean` — `false`. Локальную переменную нужно инициализировать перед чтением.
* `new Player("Анна")` вызывает конструктор.
  Чтобы имя попало в поле, конструктор должен
  выполнить присваивание, например `this.playerName = playerName;`.
* Сеттер и другой метод меняют поле только благодаря своему коду. Например,
  `setPlayerName(String playerName)` может выполнить `this.playerName = playerName;`,
  а `resetName()` — `playerName = "Гость";`. Само название метода ничего не присваивает.
* `this("Гость")` передаёт выполнение другому конструктору этого же класса.
  Это не отдельное присваивание полю. В Java 17 такой вызов должен быть первым оператором
  конструктора. При делегировании инициализаторы полей и нестатические блоки выполняются
  один раз для создаваемого объекта, а не повторно для каждого конструктора в цепочке.

Статические поля и блоки относятся к инициализации класса; в таблице речь о полях объекта.
