# 2. Инициализация и изменение полей

## 2.1. Какие поля и когда получают значения?

**Поле** — переменная, объявленная непосредственно в классе, а не внутри метода или конструктора.

| Вид поля                        | Кому принадлежит и когда создаётся           |
|---------------------------------|----------------------------------------------|
| Поле экземпляра  (без `static`) | Каждому объекту; при создании нового объекта |
| Статическое поле (`static`)     | Классу;          при подготовке класса       |

Любое поле сначала получает **значение по умолчанию** (`0`, `false`, `null` и т. д.).
Если предусмотрен инициализатор, он может заменить это значение при инициализации.

**Инициализация** — получение начального значения при подготовке класса или создании объекта.
**Изменение**     — последующее присваивание другого значения уже существующему полю.

## 2.2. Способы инициализации полей экземпляра

| Способ                           | Где задаётся значение                          |
|----------------------------------|------------------------------------------------|
| Значение по умолчанию            | Автоматически до остальных присваиваний        |
| Инициализатор при объявлении     | `private String name = "Неизвестный";`         |
| Нестатический блок `{ ... }`     | При создании каждого объекта                   |
| Конструктор                      | В теле конструктора после инициализаторов      |
| Конструктор через `this(...)`    | Значение задаёт вызываемый конструктор         |
| Конструктор родительского класса | Инициализирует поля родительской части объекта |

```
class BasePlayer {
    protected int level;                   // ← По умолчанию 0

    BasePlayer() {
        level = 1;                         // ← Конструктор родителя
    }
}

class Player extends BasePlayer {
    private String name = "Неизвестный";   // ← Инициализатор поля
    private int    score;                  // ← По умолчанию 0

    {
        score = 10;                        // ← Нестатический блок
    }

    Player() {
        this("Гость");                     // ← Вызов другого конструктора
    }

    Player(String name) {
        this.name = name;                  // ← Присваивание в конструкторе
    }

    void show() {
        System.out.println(name + ": " + score + ", уровень " + level);
    }
}
```

```
new Player().show();         // ← Гость: 10, уровень 1
new Player("Анна").show();   // ← Анна: 10, уровень 1
```

Как здесь показаны все шесть строк таблицы:

1. `level` и `score` сначала получают `0` по умолчанию.
2. `name = "Неизвестный"` — инициализатор при объявлении.
3. Блок `{ score = 10; }` задаёт счёт каждому новому объекту.
4. Конструктор `Player(String name)` присваивает имя полю.
5. Конструктор `Player()` вызывает другой конструктор через `this(...)`.
6. Конструктор `BasePlayer()` задаёт значение унаследованному полю `level`.

Что именно означает `this.name = name`:

* `this.name` — поле создаваемого объекта.
* `name`      — параметр конструктора.
* `=`         — присваивание полю значения параметра.

Сам по себе параметр `name` не изменяет поле: нужно выполнить присваивание.

**Это означает**: у каждого объекта свои значения нестатических полей.
Инициализаторы и нестатические блоки выполняются при создании каждого объекта.
Конструкторы `this(...)` и `super(...)` определяют порядок вызовов,
но не создают дополнительных объектов или способов присваивания.

## 2.3. Способы инициализации статических полей

| Способ                            | Где задаётся значение               |
|-----------------------------------|-------------------------------------|
| Значение по умолчанию             | Автоматически при подготовке класса |
| Инициализатор при объявлении      | `static int limit = 100;`           |
| Статический блок `static { ... }` | При инициализации класса            |

```
class ApplicationSettings {
    static int    limit = 100;    // ← Инициализатор статического поля
    static String mode;           // ← Сначала null

    static {                      // ← Статический блок
        mode  = "production";
        limit = 200;              // ← Заменяет ранее заданное 100
    }
}
```

При обращении к `ApplicationSettings.limit` после инициализации класса
значение равно `200`, а `ApplicationSettings.mode` равно `"production"`.

Статические инициализаторы выполняются
**один раз при инициализации класса**, а не при каждом вызове `new`.
Инициализация происходит при первом активном использовании класса, а не обязательно при загрузке.

**Это означает**: статические поля общие для объектов данного класса в одном загрузчике классов.
В статическом блоке нельзя использовать `this`, поскольку текущего объекта здесь нет.

## 2.4. Как изменять значения после инициализации?

| Способ                       | Как выполняется присваивание                 |
|------------------------------|----------------------------------------------|
| Напрямую из доступного кода  | `user.nickname = "Игрок";` — доступ разрешён |
| Через метод объекта (сеттер) | `user.setName("Мария");`                     |
| Через другой метод объекта   | `user.addScore(5);`                          |
| Статическое поле напрямую    | `ApplicationState.version = 2;`              |
| Через статический метод      | `ApplicationState.increment();`              |

```
class UserProfile {
    public String  nickname = "Гость";        // ← Прямой доступ разрешён
    private String name;
    private int    score;

    UserProfile(String name) {
        this.name = name;                     // ← Первоначальное присваивание
    }

    void setName(String newName) {
        this.name = newName;                  // ← Сеттер: изменение имени
    }

    void addScore(int points) {
        score += points;                      // ← Другой метод: изменение счёта
    }

    String getName() {
        return name;                          // ← Геттер: только чтение
    }

    int getScore() {
        return score;                         // ← Геттер: только чтение
    }
}
```

```
UserProfile user = new UserProfile("Анна");
user.nickname = "Игрок";                      // ← Прямое присваивание public-полю
user.setName("Мария");                        // ← Изменение через сеттер
user.addScore(5);                             // ← Изменение через другой метод
System.out.println(user.nickname);            // ← Игрок
System.out.println(user.getName());           // ← Мария
System.out.println(user.getScore());          // ← 5
```

**Уточнение о прямом доступе**: поле с `private` нельзя изменять из другого класса
через `user.name`. Для этого предоставляют метод, если изменение допустимо.
Поле `nickname` сделано `public` только для примера прямого присваивания.
В обычном коде открытые изменяемые поля часто лучше скрывать за методами.

```
class ApplicationState {
    public  static int version = 1;                // ← Прямой доступ разрешён
    private static int count;

    static void increment() {
        count++;                                   // ← Изменяем поле класса
    }

    static int getCount() {
        return count;
    }
}
```

```
ApplicationState.version = 2;                      // ← Прямое изменение static
ApplicationState.increment();                      // ← Изменение через метод
System.out.println(ApplicationState.version);      // ← Вывод: 2
System.out.println(ApplicationState.getCount());   // ← Вывод: 1
```

Присваивания из конструкторов и блоков уже показаны в разделах 2.2–2.3.
Они относятся к подготовке объекта или класса, а не к отдельному способу изменения после неё.

**Это означает**: поле может изменяться напрямую либо через методы, если доступ разрешён.
Геттер лишь возвращает значение; сеттер и другие методы могут выполнять присваивание.

## 2.5. Общий порядок инициализации

**Главное правило**: объявления инициализаторов полей и соответствующие блоки
внутри одного класса выполняются в порядке их расположения в исходном коде.
Статические и нестатические действия образуют две разные последовательности.

| Этап                           | Что происходит                                    |
|--------------------------------|---------------------------------------------------|
| 1. Подготовка класса           | Статические поля получают значения по умолчанию   |
| 2. Инициализация родителей     | Сначала инициализируются родительские классы      |
| 3. Статическая часть класса    | Статические инициализаторы и блоки по порядку     |
| 4. Выделение памяти под объект | Поля экземпляра получают значения по умолчанию    |
| 5. Конструктор родителя        | Выполняется создание родительской части           |
| 6. Поля и блоки экземпляра     | Инициализаторы и блоки текущего класса по порядку |
| 7. Тело конструктора           | Выполняются его оставшиеся инструкции             |

Этапы 1–3 не повторяются при каждом `new`, если класс уже инициализирован.
Этапы 4–7 относятся к созданию **каждого нового объекта**.
При наследовании шаги 5–7 выполняются последовательно для каждого уровня иерархии:
сначала родительская часть, затем дочерняя.

### Проверка порядка на примере

```
class Parent {
    static int parentStatic = log("1. Parent: статическое поле");

    static {
        log("2. Parent: статический блок");
    }

    int parentValue = log("5. Parent: поле объекта");

    {
        log("6. Parent: блок объекта");
    }

    Parent() {
        log("7. Parent: конструктор");
    }

    static int log(String message) {
        System.out.println(message);
        return 1;
    }
}

class Child extends Parent {
    static int childStatic = log("3. Child: статическое поле");

    static {
        log("4. Child: статический блок");
    }

    int childValue = log("8. Child: поле объекта");

    {
        log("9. Child: блок объекта");
    }

    Child() {
        log("10. Child: конструктор");
    }
}
```

Первый вызов `new Child()` выведет:

В образце добавлены пробелы для выравнивания подписей.

```text
1. Parent: статическое поле
2. Parent: статический блок
3. Child:  статическое поле
4. Child:  статический блок
5. Parent: поле объекта
6. Parent: блок объекта
7. Parent: конструктор
8. Child:  поле объекта
9. Child:  блок объекта
10. Child: конструктор
```

При **втором** вызове `new Child()` будут выведены только строки 5–10:
статическая часть уже выполнена, а поля нового объекта инициализируются заново.
Этапы присваивания значений по умолчанию (1 и 4) не выводятся в консоль:
это автоматические действия Java, происходящие до пользовательских инициализаторов.

**Это означает**: порядок определяется не только тем, где написана строка,
но и тем, относится она к классу или объекту и есть ли родительский класс.

## 2.6. Уточнения и ограничения

* **Конструктор и `this(...)`**.

  В Java 17 вызов другого конструктора через `this(...)` должен идти первым.
  Цепочка конструкторов заканчивается вызовом конструктора родителя.
  Поля и блоки экземпляра одного класса выполняются только один раз для объекта.
  Пример `Player()` и `Player(String name)` уже приведён в разделе 2.2.

  **Это означает**: `this(...)`
  не создаёт второй объект и не выполняет повторную инициализацию полей.

* **Наследование и `super(...)`**.

  Родительский конструктор выполняется до инициализаторов и тела дочернего конструктора.
  Если явного `super(...)` или `this(...)` нет, Java пытается вызвать `super()`.
  Если у родителя нет доступного конструктора без параметров, нужен подходящий `super(...)`.

  ```
  class Parent {
      Parent(int level) {
          System.out.println(level);
      }
  }

  class Child extends Parent {
      Child() {
          super(5);                    // ← Вызов конструктора родителя
      }
  }
  ```

  **Это означает**: конструктор дочернего класса должен обеспечить вызов
  подходящего конструктора родителя до инициализации дочерних полей.

* **Сложные инициализаторы**.

  Справа от `=` может находиться не только литерал, но и выражение или вызов метода:

  ```
  class Settings {
      static int maxConnections = readLimit();   // ← Результат метода

      static int readLimit() {
          return 20;
      }
  }
  ```

  **Это означает**: вызов метода — источник значения, а
  место и порядок инициализации определяются расположением присваивания.

* **`final`**.

  Поля `final` нельзя повторно присваивать после допустимой однократной инициализации.
  Для полей без инициализатора действуют особые правила
  завершения конструкторов или статической инициализации.

* **Ссылки и изменяемые объекты**.

  Полю можно присвоить ссылку на объект, а затем изменить сам объект.
  Изменение содержимого объекта и присваивание другой ссылки — разные действия.

  ```
  class Basket {
      java.util.List<String> items = new java.util.ArrayList<>();
  }

  Basket basket = new Basket();
  basket.items.add("Книга");                    // ← Изменён список, не поле items
  basket.items = new java.util.ArrayList<>();   // ← Полю присвоена другая ссылка
  ```

  **Это означает**: важно различать
  изменение поля-ссылки и изменение объекта, на который эта ссылка указывает.

* **Потоки и общие поля**.

  Изменяемое `static`-поле разделяется между обращающимся к нему кодом.
  Если несколько потоков записывают значения одновременно, нужны правила потокобезопасности.
  Сходная проблема возможна и с одним общим объектом, имеющим изменяемые поля экземпляра.

  **Это означает**: `static` не означает «автоматически потокобезопасно».

* **Фабрики, сеттеры и фреймворки**.

  Фабричный метод может вызвать `new`, конструктор и последующие методы настройки.
  Spring и рефлексия могут записывать доступные им поля отдельными механизмами.
  Это не меняет базовый порядок работы конструкторов и блоков при обычном создании объекта.

### Что это означает на практике?

**Инициализация поля** отвечает на вопрос «откуда берётся первое значение»,
а **изменение поля** — «какой код может присвоить другое значение позднее».

* Для полей экземпляра главное — инициализаторы, блоки и конструкторы.
* Для статических полей        — инициализаторы при объявлении и `static`-блоки.
* Для дальнейших изменений     — прямое присваивание или методы с нужным доступом.
* При наследовании сначала выполняется инициализация родителя, затем потомка.
* При повторном `new` создаётся новый набор полей экземпляра, но не набор `static`-полей.

**Итог**: чтобы определить текущее значение поля, сначала учитывайте значение по умолчанию,
затем присваивания при инициализации класса или создании объекта,
а после — все изменения, выполненные доступным кодом.
