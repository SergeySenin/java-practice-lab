# 3. Модификатор `final` в Java

## 3.1. Что означает `final`?

`final` — модификатор, который ограничивает присваивание переменным,
переопределение методов или наследование классов.
Его действие зависит от того, к чему он применяется.

**Зачем нужен `final`**: он задаёт ограничения, которые проверяет компилятор,
и защищает от случайного переназначения значений или изменения поведения через наследование.

| Где используется `final`              | Что запрещает                             |
|---------------------------------------|-------------------------------------------|
| Поле экземпляра                       | Повторно присваивать значение полю        |
| Статическое поле (`static final`)     | Повторно присваивать значение полю класса |
| Локальная переменная                  | Повторно присваивать значение             |
| Параметр конструктора, метода, лямбды | Переназначать параметр внутри тела        |
| Параметр `catch` и переменная цикла   | Переназначать соответствующую переменную  |
| Метод                                 | Переопределять или скрывать его в потомке |
| Класс                                 | Создавать от него классы-наследники       |

**Главное правило для переменных**: `final` допускает одно присваивание значения.
Оно не обязательно должно происходить прямо в объявлении.

## 3.2. Инициализация полей `final`

Поле с `final` можно инициализировать при объявлении или позднее,
но к моменту завершения необходимой инициализации оно должно получить значение.

Поле `final` **без инициализатора** называют *blank final*.

| Способ                                     | Разрешено и при каком условии                  |
|--------------------------------------------|------------------------------------------------|
| Поле экземпляра — при объявлении           | Да; после этого присваивать снова нельзя       |
| Поле экземпляра — в блоке `{ ... }`        | Да; поле должно быть ещё не присвоено          |
| Поле экземпляра — в конструкторе           | Да; каждый путь создания объекта               |
|                                            | должен обеспечить присваивание                 |
| `static final`  — при объявлении           | Да; после этого присваивать снова нельзя       |
| `static final`  — в блоке `static { ... }` | Да; поле должно быть ещё не присвоено          |
| `static final`  — в конструкторе           | Нет; конструктор не инициализирует поле класса |
| Поле `final`    — из обычного метода       | Нет; для blank final это слишком поздно        |

Пример показывает основные допустимые способы одновременно:

```
class UserSession {
    final int    timeout = 30;                    // ← Инициализация при объявлении
    final long   createdAt;                       // ← Пока без явного значения
    final String owner;                           // ← Пока без явного значения

    static final int    MAX_USERS = 100;          // ← Инициализация static final
    static final String MODE;                     // ← Будет задано в static-блоке

    static {
        MODE = "production";                      // ← Присваивание static final
    }

    {
        createdAt = System.currentTimeMillis();   // ← Блок экземпляра
    }

    UserSession(String owner) {
        this.owner = owner;                       // ← Присваивание в конструкторе
    }

    UserSession() {
        this("Гость");                            // ← Делегирование конструктору
    }
}
```

Здесь `timeout`, `createdAt`, `owner`, `MAX_USERS` и `MODE` получают значения
разными способами, но каждому полю `final` присваивание выполняется только один раз.

Важно: значения по умолчанию (`0`, `null` и т. д.) не считаются тем
обязательным явным присваиванием, которое требуется для blank final.
Оставить такое поле без инициализации нельзя.

**Это означает**: инициализировать `final`-поле можно не только в объявлении.
Но после присваивания изменить его уже нельзя, даже через сеттер.

## 3.3. Локальные переменные и параметры `final`

Локальной `final`-переменной разрешено присвоить значение сразу или позднее.
Если присваивание отложено, компилятор проверяет все возможные пути выполнения.

```
final int first = 10;           // ← Значение задано сразу

final int second;               // ← Пока без значения
          second = 20;          // ← Первое присваивание разрешено
//        second = 30;          // ← Нельзя: второе присваивание

final int discount;
boolean premium = true;

if (premium) {
    discount = 15;              // ← Один возможный путь
} else {
    discount = 5;               // ← Другой возможный путь
}

System.out.println(discount);   // ← 15
```

Два присваивания в разных ветвях `if` допустимы, поскольку при одном выполнении
используется только одна ветвь. Без `else` компилятор мог бы обнаружить путь без значения.

Для параметров правило строже по форме записи:
значение уже передано при вызове, поэтому присваивать его повторно нельзя.

```
class Calculator {
    int add(final int number, final int bonus) {
        //     number = 20;                        // ← Нельзя: параметр final
        return number + bonus;
    }
}
```

`final` разрешён для параметров методов, конструкторов, лямбда-выражений
и `catch`, а также для переменной `for-each`.

```
for (final String name : new String[]{"Анна", "Мария"}) {
    System.out.println(name);                               // ← Читать можно
    // name = "Гость";                                      // ← Нельзя: переменная final
}
```

**Это означает**: `final` запрещает повторное присваивание, но не запрещает
повторное чтение значения и использование переменной в вычислениях.

## 3.4. Примитивные значения, ссылки, массивы и коллекции

**Для примитивного типа** `final` фиксирует само значение переменной.
**Для ссылочного типа**   `final` фиксирует ссылку, а не состояние объекта.

```
final int limit = 10;
//        limit = 20;                                               // ← Нельзя: изменить значение

final java.util.List<String> items = new java.util.ArrayList<>();
items.add("Книга");                                                 // ← Можно: изменить список
items.set(0, "Ручка");                                              // ← Можно: изменить элемент
// items = new java.util.ArrayList<>();                             // ← Нельзя: заменить ссылку

final int[] numbers = {1, 2, 3};
numbers[0] = 50;                                                    // ← Можно: изменить элемент
// numbers = new int[3];                                            // ← Нельзя: заменить массив
```

При этом `final` не запрещает вызывать методы объекта.
Вопрос о том, допускает ли конкретный объект изменение состояния,
зависит от его класса, а не от `final` у переменной.

**Это означает**: `final` не превращает `ArrayList` в неизменяемую коллекцию
и не запрещает изменять элементы массива. Запрещено только заменить ссылку.

## 3.5. Методы и классы `final`

| Конструкция              | Что разрешено и запрещено                                     |
|--------------------------|---------------------------------------------------------------|
| `final`-метод экземпляра | Вызывать и перегружать можно; переопределять в потомке нельзя |
| `static final`-метод     | Вызывать и перегружать можно; скрывать в потомке нельзя       |
| `final`-класс            | Создавать объекты и реализовывать интерфейсы                  |
|                          | можно; наследоваться от него нельзя                           |

```
class BaseService {
    final void save() {                                   // ← Запрещено переопределение
        System.out.println("Сохранено");
    }

    static final void log() {                             // ← Запрещено скрытие в потомке
        System.out.println("Лог");
    }

    void print() {
        System.out.println("Базовый вывод");
    }
}

class UserService extends BaseService {
    @Override
    void print() {                                        // ← Можно: обычный метод
        System.out.println("Вывод пользователя");
    }

    void save(String path) {                              // ← Можно: перегрузка save(String)
        System.out.println(path);
    }

    // void save() {}                                     // ← Нельзя: переопределение final
    // static void log() {}                               // ← Нельзя: скрытие static final
}

final class UserToken implements java.io.Serializable {   // ← Интерфейс разрешён
}

// class TokenChild extends UserToken {}                  // ← Нельзя: UserToken — final
```

Метод `final` при этом может менять доступные ему поля объекта.
Он запрещает изменение реализации через переопределение, а не изменение данных.

**Это означает**: `final` у класса и метода управляет наследованием,
а `final` у переменной — присваиванием. Это разные ограничения.

## 3.6. Особые случаи и ограничения

* **`effectively final` — переменная, которую фактически не переназначают**.

  Локальная переменная или параметр может использоваться как `final`
  для захвата в лямбде, даже если ключевое слово `final` не написано.
  Для этого переменная должна оставаться *effectively final*.

  ```
  int bonus = 10;                                                      // ← Нет слова final
  java.util.function.IntUnaryOperator calc = value -> value + bonus;

  System.out.println(calc.applyAsInt(5));                              // ← 15
  // bonus = 20;                                                       // ← Нельзя в таком захвате
  ```

  Если переменная переназначается, захватить её в лямбде или локальном либо
  анонимном классе нельзя. К полям экземпляра это ограничение не относится.

  **Это означает**: для захвата локальной переменной важно
  отсутствие переназначений, а не обязательное присутствие слова `final`.

* **Переменные образца `instanceof`**.

  В Java 17 переменную образца можно явно объявить с `final`:
  `value instanceof final String text`. Тогда переназначать `text` нельзя.
  Без `final` переменная может быть *effectively final*, если её не переназначают.

* **`final var`**.

  `var` определяет тип, а `final` запрещает последующее присваивание.
  Эти возможности совместимы.

  ```
  final var count = 10;   // ← Тип int, переназначать нельзя
  //        count = 20;   // ← Ошибка компиляции

  java.util.function.IntUnaryOperator twice = (final var n) -> n * 2;
  // Параметр n тоже нельзя переназначить
  ```

  `final var` также допустим для параметров лямбды в Java 17.

* **Неявный `final` в Java 17**.

  В некоторых конструкциях модификатор действует без явного написания:

  | Конструкция                         | Что становится `final`                      |
  |-------------------------------------|---------------------------------------------|
  | Поле интерфейса                     | Неявно `public static final`                |
  | Новый ресурс в `try-with-resources` | Переменная ресурса неявно `final`           |
  | Параметр `multi-catch`              | Неявно `final`                              |
  | Компонент `record`                  | Соответствующее поле неявно `private final` |

  ```
  interface Limits {
      int MAX = 100;                                           // ← public static final
  }

  record Point(int x, int y) {                                 // ← Поля x и y являются final
  }

  try {
      Integer.parseInt("abc");
  } catch (NumberFormatException | NullPointerException e) {
      // e = new RuntimeException();                           // ← Нельзя: параметр multi-catch
  }
  ```

  Типы в `multi-catch` не должны быть подклассами друг друга.

* **`record` и `enum`**.

  Класс `record` неявно является `final`, а
  его поля компонентов нельзя переназначать после создания объекта.
  Ссылочный компонент при этом может указывать на изменяемый объект.

  `enum` нельзя явно объявить `final`: Java сама ограничивает его наследование.
  Здесь **константа `enum`** — одно из именованных значений, например `DEV` или `PROD`.

  ```
  enum Mode { DEV, PROD }   // ← Неявно final: обычные константы без тел
  ```

  Иногда отдельной константе задают **собственное тело `{ ... }`**,
  например чтобы изменить поведение метода только для неё:

  ```
  enum Action {
      START {
          @Override
          public String toString() {
              return "Старт";
          }
      },                               // ← START имеет собственное тело
      STOP
  }
  ```

  В первом случае `Mode` неявно `final`: наследовать от него нельзя.
  Во втором `Action` неявно `sealed`: Java разрешает только служебные подклассы,
  создаваемые для констант с собственным телом, например `START`.
  **Обычному классу наследоваться от `enum` нельзя в обоих случаях.**

* **Константы времени компиляции**.

  Это значения, которые компилятор способен вычислить **без запуска программы**.
  Не каждое поле `static final` подходит: тип должен быть примитивным или `String`,
  а выражение справа — состоять из констант, вычисляемых при компиляции.

  ```
  static final int     MAX   = 100;                        // ← Константа времени компиляции
  static final String  MODE  = "dev";                      // ← Константа времени компиляции
  static final Integer BOXED = 100;                        // ← Нет: Integer — ссылочный тип
  static final int     PORT  = Integer.parseInt("8080");   // ← Нет: вызов метода
  ```

  Например, другой класс использует `Settings.MAX`, равное `100`.
  Компилятор может записать прямо число `100` вместо обращения к полю.
  Если потом изменить `MAX` на `200`, старый скомпилированный класс
  может продолжить использовать `100`, пока его не пересоберут.

  **Это означает**: `static final` запрещает повторное присваивание,
  но не гарантирует вычисление значения при компиляции.

* **Недопустимые сочетания `final`**.

    * `final` у конструктора или блока инициализации — нельзя:
      эти конструкции не являются переопределяемыми методами.
    * `abstract final` у класса или метода — нельзя:
      `abstract` требует реализации наследником, а `final` её запрещает.
    * `final volatile` у одного поля — нельзя:
      `volatile` служит для видимости изменений поля между потоками,
      а `final` запрещает повторное присваивание этому полю.
    * `final` у интерфейса или его методов — нельзя:
      интерфейс предназначен для реализации другими типами,
      а модификатор `final` для его методов не предусмотрен Java.
    * `private final` у метода класса — можно, но обычно избыточно:
      `private`-метод и без `final` нельзя переопределить.

  **Это означает**: некоторые сочетания противоречат назначению `final`,
  а некоторые разрешены, но не дают дополнительного ограничения.

## 3.7. Что разрешено и что запрещено?

| Действие                                       | Результат                      |
|------------------------------------------------|--------------------------------|
| Один раз присвоить значение blank final        | Можно, если все пути корректны |
| Повторно присвоить значение `final`-переменной | Нельзя: ошибка компиляции      |
| Вызвать метод через         `final`-ссылку     | Можно                          |
| Изменить элемент            `final`-массива    | Можно                          |
| Заменить массив через       `final`-ссылку     | Нельзя                         |
| Переопределить              `final`-метод      | Нельзя                         |
| Перегрузить                 `final`-метод      | Можно: другая сигнатура        |
| Создать объект              `final`-класса     | Можно                          |
| Унаследоваться от           `final`-класса     | Нельзя                         |
| Захватить effectively final в лямбде           | Можно                          |

### Что это означает на практике?

**Итог**: `final` фиксирует конкретное ограничение: переменной нельзя присвоить
другое значение, метод нельзя переопределить или скрыть, а класс нельзя наследовать.
Для ссылок `final` не гарантирует неизменяемость самого объекта.
При отложенной инициализации компилятор проверяет, что присваивание выполнено корректно.
