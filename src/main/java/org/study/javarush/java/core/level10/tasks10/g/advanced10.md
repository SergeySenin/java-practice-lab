Задание 10. Система управления развёртыванием приложения (Deployment Control System)

Вы разрабатываете консольную утилиту для подготовки и запуска развёртывания Java-приложения.

Программа получает параметры конфигурации в текстовом виде, преобразует их в необходимые типы,
определяет целевое окружение, выбирает системные настройки, обрабатывает команду оператора и
формирует итоговый отчёт о развёртывании.

Основная цель задания — закрепить:

* классы-обёртки (wrapper classes);
* упаковку (boxing) и распаковку (unboxing);
* автоупаковку (autoboxing) и автораспаковку (unboxing);
* возможность хранения `null` в обёртках;
* ключевое слово `var`;
* локальные неизменяемые переменные (`final`);
* константы класса (`static final`);
* классический оператор выбора (`switch`);
* перечисления (`enum`);
* современное `switch`-выражение (switch expression);
* стрелочный синтаксис (`->`);
* объединение нескольких значений `case`;
* возврат значения из блока через `yield`.

Задание рассчитано на Java 17 или Java 21.

## 1. Структура проекта

Создайте три Java-файла:

```text
Solution.java
DeploymentEnvironment.java
DeploymentSettings.java
```

Класс `Solution` содержит главный метод программы (`main`).

Перечисление `DeploymentEnvironment` описывает допустимые окружения.

Класс `DeploymentSettings` содержит общие константы системы.

## 2. Этап 1. Перечисление окружений

В файле `DeploymentEnvironment.java` создайте перечисление:

«окружение развёртывания» (`DeploymentEnvironment`).

Оно должно содержать четыре значения:

```
DEVELOPMENT
TESTING
STAGING
PRODUCTION
```

Имена элементов перечисления должны быть записаны заглавными буквами.

Не заменяйте перечисление строками вроде:

```
"development"
"testing"
"production"
```

после того как пользовательский ввод уже был преобразован в `DeploymentEnvironment`.

## 7. Этап 5. Использование var

После чтения данных создайте несколько **локальных** переменных с помощью ключевого слова:

```
var
```

Например, через `var` должны быть объявлены:

* «нормализованное имя окружения» (`normalizedEnvironmentName`);
* «нормализованная команда» (`normalizedCommand`);
* «все доступные окружения» (`availableEnvironments`).

Тип каждой такой переменной должен быть очевиден по правой части выражения.

Например:

```text
результат toUpperCase() → String
результат DeploymentEnvironment.values() → DeploymentEnvironment[]
```

Не используйте `var`:

* для полей класса;
* для параметров методов;
* без начального значения;
* с одним только `null`.

## 16. Этап 14. Автоупаковка и автораспаковка Integer

Создайте ещё две переменные.

«Количество попыток как объект» (`automaticRetryCount`) типа:


После этого создайте:

«количество попыток как примитив» (`automaticRetryCountValue`) типа:

То есть необходимо практически показать:


без явных вызовов `valueOf()` и `intValue()` во второй паре переменных.

## 25. Этап 23. Выбор автоматического порта через современный switch


### STAGING

Результат:


Внутри блока:

1. выведите диагностическую строку:

```text

```

2. верните:

```

```

с помощью:

```

```

Для основного теста:

```text

```

## 29. Этап 27. Классический switch для команды оператора

Создайте:

«категория команды» (`commandCategory`) типа `String`.

Обработайте `normalizedCommand` **классическим оператором `switch`**.

Используйте синтаксис:

```
case ...:
break;
default:
```

Правила:

### build и test

Эти две команды должны быть сгруппированы:

```text
build
test
```

Для них:

```text
commandCategory → PREPARATION
```

### deploy

```text
commandCategory → DEPLOYMENT
```

### status

```text
commandCategory → INFORMATION
```

### любая другая команда

Через:

```
default
```

присвойте:

```text
UNKNOWN
```

Для основного теста:

```text
normalizedCommand → deploy
commandCategory → DEPLOYMENT
```

В каждой рабочей ветке классического `switch` должен присутствовать необходимый `break`.

## 30. Этап 28. Современное switch-выражение для сообщения

Создайте:

«сообщение команды» (`commandMessage`) типа `String`.

Определите его **современным `switch`-выражением** по `normalizedCommand`.

Правила:

```text

test   → Test process selected.
deploy → Deployment process selected.
status → Status information requested.

```

Используйте:


В этом `switch` не используйте `break`.

Результат всего выражения должен быть непосредственно присвоен переменной `commandMessage`.

## 35. Диагностический эксперимент 1. Integer и equals()

После создания рабочей программы выполните отдельный эксперимент.

Создайте:

```
Integer firstSmallValue = 100;
Integer secondSmallValue = 100;

Integer firstLargeValue = 200;
Integer secondLargeValue = 200;
```

Выведите результаты:

```
firstSmallValue == secondSmallValue
firstSmallValue.equals(secondSmallValue)

firstLargeValue == secondLargeValue
firstLargeValue.equals(secondLargeValue)
```

Зафиксируйте наблюдение.

Для проверки **значений** обёрток используйте:

```
equals()
```

Не стройте рабочую логику на результате `==`.

Вы должны уметь объяснить, что `==` для объектов проверяет ссылки, а небольшие `Integer` могут
использовать кэшированные объекты.

## 36. Диагностический эксперимент 2. null и автораспаковка

Для основного теста:

```
manualPort == null
```

Поэтому строка вида:

```
int port = manualPort;
```

привела бы к попытке автораспаковать `null`.

Не оставляйте такой код активным в рабочей версии.

Вы должны уметь объяснить, почему такая операция приводит к:

```
NullPointerException
```

Именно поэтому перед распаковкой nullable-обёртки выполняется проверка:

```
manualPort != null
```

## 37. Диагностический эксперимент 3. final-примитив

Внутри `main` создайте временную переменную:

```
final int TEST_LIMIT = 10;
```

Временно попробуйте затем присвоить:

```
TEST_LIMIT = 20;
```

Код должен перестать компилироваться.

После наблюдения удалите или закомментируйте неправильную строку.

## 38. Диагностический эксперимент 4. final-ссылка

После создания:

```
final var deploymentLog = new StringBuilder();
```

добавление:

```
deploymentLog.append(...)
```

должно компилироваться.

Временно попробуйте:

```
deploymentLog = new StringBuilder();
```

Это должно привести к ошибке компиляции.

После эксперимента верните программу в рабочее состояние.

Объясните разницу между:

```text
изменить объект
```

и:

```text
заменить final-ссылку
```

## 39. Диагностический эксперимент 5. var нельзя использовать без значения

Временно попробуйте:

```
var unknownValue;
```

Код не должен компилироваться.

После этого попробуйте:

```
var unknownValue = null;
```

Этот вариант также не должен компилироваться, потому что компилятор не может определить конкретный
тип переменной.

После эксперимента удалите ошибочные строки.

## 40. Диагностический эксперимент 6. var фиксирует определённый тип

Создайте:

```
var temporaryValue = 10;
```

Компилятор должен определить её тип как `int`.

Временно попробуйте затем:

```
temporaryValue = "ten";
```

Код должен перестать компилироваться.

`var` не означает «тип может меняться».

Он означает:

> тип определяется компилятором во время объявления.

## 41. Диагностический эксперимент 7. fall-through классического switch

В рабочей версии классического `switch` после необходимых веток стоят `break`.

Для эксперимента временно удалите один `break` из подходящей ветки.

Запустите программу и посмотрите, выполняется ли код следующего `case`.

После наблюдения верните `break`.

Итоговая версия задания не должна содержать случайного проваливания (`fall-through`).

## 49. Требования к `var`

Используйте `var` только для локальных переменных.

Не используйте его:

```text
как тип поля класса
как тип параметра метода
без инициализации
с единственным значением null
```

После объявления тип переменной остаётся фиксированным.

`var` не является динамическим типом.

## 50. Требования к `final`

Вы должны различать:

```
final
```

и:

```
static final
```

Локальное `final` фиксирует значение конкретной локальной переменной.

`static final` используется для общей константы класса.

Для ссылочного типа `final` запрещает заменить ссылку, но не обязательно запрещает изменение
состояния объекта.

## 51. Требования к `enum`

Используйте `DeploymentEnvironment` как отдельный тип.

После преобразования пользовательского ввода не храните целевое окружение в виде магических чисел:

```
0
1
2
3
```

и не стройте бизнес-логику на:

```
ordinal()
```

Для проверки конкретного значения `enum` допустимо использовать:

```
==
```

## 52. Требования к классическому `switch`

Классический `switch` должен использоваться для обработки команды оператора.

В рабочей версии:

* нужные ветки завершаются через `break`;
* присутствует `default`;
* две команды объединены последовательными `case`.

Он не должен использоваться там, где требуется сравнивать диапазоны чисел.

## 53. Требования к современному `switch`

Современный `switch` должен использоваться как **выражение, возвращающее значение**.

В задании он должен продемонстрировать:

```
case ... -> значение
case A, B -> значение
case X -> {
    ...
    yield значение;
}
```

Для современного стрелочного синтаксиса не добавляйте `break` после каждой ветки.

## 54. Что должно быть понято после выполнения

### Примитив и обёртка

Вы должны различать:

```
int
Integer
```

Примитив хранит конкретное значение.

Обёртка является объектным ссылочным типом и может дополнительно хранить:

```
null
```

### Boxing и unboxing

Вы должны понимать четыре формы:

```text
int → Integer.valueOf(...) → Integer
Integer → intValue() → int

int → Integer
Integer → int
```

В последних двух случаях преобразование добавляет компилятор.

### `null` и unboxing

Вы должны понимать, почему:

```
Integer value = null;
int number = value;
```

опасно.

Проблема возникает не из-за самого `null`, а при попытке автораспаковать его в примитив.

### Сравнение `Integer`

Для сравнения числового содержимого объектов:

```
Integer
```

используйте:

```
equals()
```

Не полагайтесь на `==`, даже если для некоторых небольших значений он неожиданно возвращает `true`.

### `var`

Вы должны понимать, что:

```
var value = 10;
```

эквивалентно определению конкретного типа компилятором.

Тип не становится изменяемым или динамическим.

### `final`

Вы должны различать:

```
final int value
final StringBuilder builder
```

В первом случае нельзя изменить сохранённое примитивное значение.

Во втором нельзя присвоить переменной другой объект, но состояние существующего объекта может
изменяться.

### `enum`

Вы должны понимать назначение:

```
values()
valueOf()
name()
ordinal()
```

и почему ограниченный набор состояний лучше моделировать через `enum`, а не через произвольные
строки или числа.

### Два вида `switch`

Вы должны различать:

```text
классический switch
```

и:

```text
switch-выражение
```

Классический вариант выполняет команды и обычно требует `break`.

Современный вариант может возвращать значение, использует `->` и не имеет обычного fall-through
между стрелочными ветками.
