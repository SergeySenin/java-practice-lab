Введение в лямбда-выражения

## 1. Знакомство

Если коротко: **лямбда-выражение** — это способ быстро создать реализацию
функционального интерфейса «на лету», не объявляя отдельный именованный или
анонимный класс. Это как мини-метод без имени, который можно передать как
аргумент или сохранить в переменную функционального интерфейса.

Java долгое время была «классическим» ООП-языком. Если вы хотели передать
кусочек поведения, например, что делать при нажатии кнопки, нужно было писать
анонимные классы:

```
button.setOnClickListener(new OnClickListener() {
    @Override
    public void onClick() {
        System.out.println("Кнопка нажата!");
    }
});
```

С Java 8 появилась лямбда-магия:

```
button.setOnClickListener(() -> System.out.println("Кнопка нажата!"));
```

Здесь `() -> System.out.println("Кнопка нажата!")` — лямбда-выражение.
Оба фрагмента иллюстрируют условный API кнопки: предполагается, что
`OnClickListener` — функциональный интерфейс с методом `void onClick()`,
а переменная `button` уже объявлена.

**Формально**: лямбда-выражение — это компактная форма записи реализации
единственного абстрактного метода функционального интерфейса.

### Почему это важно?

* Передавать поведение как значение (например, что делать с каждым элементом списка).
* Писать компактный и читаемый код.
* Использовать современные API Java: Stream API, обработку событий,
  асинхронные задачи и многое другое.

## 2. Синтаксис лямбда-выражений

### Общий вид

```
(параметры) -> выражение
// или
(параметры) -> {
    // блок кода
}
```

### Примеры для разных интерфейсов

1\. Без параметров (например, `Runnable`):

```
Runnable r = () -> System.out.println("Привет, лямбда!");
r.run();
```

2\. Один параметр (например, `Consumer`):

```
Consumer<String> printer = s -> System.out.println("Вы передали: " + s);
printer.accept("Java");
```

Если параметр только один и его тип можно вывести, скобки можно опустить.
`String` — тип параметра `s`, который получает значение при вызове `accept()`.

3\. Несколько параметров (например, `Comparator`):

```
Comparator<Integer> cmp = (a, b) -> Integer.compare(a, b);
System.out.println(cmp.compare(10, 5)); // 1
```

`Integer` — тип обоих параметров `a` и `b`. Метод `Integer.compare()`
сравнивает числа без риска переполнения, возможного при вычитании `a - b`.

4\. Многострочное тело (нужны фигурные скобки и `return` для возврата значения):

```
Function<Integer, Integer> square = x -> {
    int result = x * x;
    return result;
};
System.out.println(square.apply(6)); // 36
```

В `Function<T, R>` первый параметр типа (`T`) — тип входного значения,
а второй (`R`) — тип результата. Здесь оба типа — `Integer`.

Для примеров с `Consumer`, `Comparator` и `Function` понадобятся импорты:

```
import java.util.Comparator;
import java.util.function.Consumer;
import java.util.function.Function;
```

### Сокращения и лаконичность

* Если тело — одно выражение, фигурные скобки и `return` можно опустить.
* Если параметров нет — пишем пустые скобки: `() -> ...`.
* Если один параметр с выводимым типом — можно без скобок: `x -> ...`.
* Если больше одного параметра — нужны скобки: `(a, b) -> ...`.

### Таблица-сводка

Посмотрим, как одна и та же идея записывается через лямбду и через анонимный класс.

| Интерфейс             | Лямбда-выражение (пример)         |
|-----------------------|-----------------------------------|
| `Runnable`            | `() -> System.out.println("Hi")`  |
| `Consumer<String>`    | `s -> System.out.println(s)`      |
| `Comparator<Integer>` | `(a, b) -> Integer.compare(a, b)` |

Эквивалентные анонимные классы (в том же порядке):

```
Runnable runnable = new Runnable() {
    @Override
    public void run() {
        System.out.println("Hi");
    }
};

Consumer<String> consumer = new Consumer<String>() {
    @Override
    public void accept(String s) {
        System.out.println(s);
    }
};

Comparator<Integer> comparator = new Comparator<Integer>() {
    @Override
    public int compare(Integer a, Integer b) {
        return Integer.compare(a, b);
    }
};
```

### Пример с собственным интерфейсом

Пусть у нас есть функциональный интерфейс:

```
@FunctionalInterface
interface Operation {
    int apply(int a, int b);
}
```

Раньше реализовывали так:

```
Operation sum = new Operation() {
    @Override
    public int apply(int a, int b) {
        return a + b;
    }
};
```

Теперь — современно:

```
Operation sum = (a, b) -> a + b;
System.out.println(sum.apply(3, 5)); // 8
```

### Примеры для стандартных интерфейсов

`Runnable`:

```
Runnable hello = () -> System.out.println("Hello from thread!");
new Thread(hello).start();
```

`Comparator`:

```
List<String> list = Arrays.asList("яблоко", "банан", "киви");
list.sort((a, b) -> Integer.compare(a.length(), b.length()));
System.out.println(list); // [киви, банан, яблоко]
```

`Function`:

```
Function<String, Integer> parse = s -> Integer.parseInt(s);
System.out.println(parse.apply("123")); // 123
```

Для примера сортировки также понадобятся `import java.util.List;`
и `import java.util.Arrays;`.

## 3. Область видимости и захват переменных

### Переменные из внешнего контекста (*effectively final*)

Лямбда-выражения могут использовать локальные переменные из окружающего метода.
Но есть правило: такие переменные должны быть `final` или *effectively final* —
то есть не переназначаться после инициализации.

Пример:

```
String prefix = "Результат: ";
Function<Integer, String> f = x -> prefix + (x * 2);
// prefix нельзя переназначить после захвата в лямбде
System.out.println(f.apply(5)); // Результат: 10
```

Если попытаться изменить `prefix` после использования в лямбде, компилятор выдаст ошибку.

### Почему так?

Лямбда-выражение может быть вызвано после выхода из метода, где была объявлена
локальная переменная. Поэтому Java требует, чтобы захваченная локальная переменная
не переназначалась. Если она содержит ссылку на изменяемый объект, само
содержимое объекта при этом может изменяться.

### Отличие от анонимных классов

В анонимных классах действует то же правило: захваченные локальные переменные
должны быть `final` или *effectively final*. Но есть нюансы с областью видимости:
внутри анонимного класса `this` ссылается на экземпляр анонимного класса,
а в лямбде — на объект окружающего класса.

```
public class Demo {
    public void test() {
        Runnable r1 = new Runnable() {
            @Override
            public void run() {
                System.out.println(this); // Объект анонимного класса
            }
        };

        Runnable r2 = () -> System.out.println(this); // Объект Demo

        r1.run();
        r2.run();
    }
}
```

При стандартной реализации `toString()` в выводе будут имена классов
с идентификаторами объектов. Точный формат имён анонимных классов и значения
идентификаторов не следует считать фиксированными.

### Лямбда и поля класса

Лямбда-выражение может обращаться к полям внешнего класса:

```
public class Counter {
    private int base = 10;

    public void printSum(int x) {
        Function<Integer, Integer> sum = y -> base + y + x;
        System.out.println(sum.apply(5));
    }
}
```

Здесь `base` — поле класса, его значение можно менять.
Параметр метода `x`, захваченный лямбдой, должен быть *effectively final*.
Для компиляции нужен импорт `java.util.function.Function`.

## 4. Практика: напишем несколько лямбда-выражений

### Пример: фильтрация списка чисел

```
List<Integer> nums = Arrays.asList(1, 2, 3, 4, 5, 6);

nums.stream()
    .filter(n -> n % 2 == 0)
    .forEach(n -> System.out.println("Чётное: " + n));
```

Подробнее про Stream API вы узнаете на 30-м уровне :P

### Пример: функция преобразования строки

```
Function<String, String> capitalize = s -> s.toUpperCase();
System.out.println(capitalize.apply("java")); // JAVA
```

### Пример: свой функциональный интерфейс

```
@FunctionalInterface
interface StringTransformer {
    String transform(String s);
}
```

```
StringTransformer exclaim = s -> s + "!";
System.out.println(exclaim.transform("Привет")); // Привет!
```

### Пример: использование переменных из внешнего контекста

```
int factor = 2;
List<Integer> numbers = Arrays.asList(1, 2, 3);
numbers.forEach(n -> System.out.println(n * factor));
// factor нельзя переназначить после захвата в лямбде
```

Для примеров со списками требуются импорты `java.util.List`, `java.util.Arrays`,
а для `Function` — `java.util.function.Function`.

## 5. Типичные ошибки при работе с лямбда-выражениями

### Ошибка № 1. Попытка изменить переменную, захваченную лямбдой

Такой код не скомпилируется: переменная `sum` должна быть *effectively final*.

```
int sum = 0;
List<Integer> numbers = Arrays.asList(1, 2, 3);
numbers.forEach(n -> sum += n); // Ошибка: sum не effectively final!
```

Если нужно накапливать значения — используйте массив или объект-обёртку.
Для чисел также можно использовать `stream().mapToInt(...).sum()`.

### Ошибка № 2. Путаница с областью видимости `this`

Внутри лямбда-выражения `this` ссылается на окружающий объект,
а не на лямбду (в отличие от анонимного класса). В статическом контексте
использовать `this` нельзя.

### Ошибка № 3. Забыли фигурные скобки и `return` в многострочном выражении

Если тело лямбды состоит из нескольких операторов, нужны фигурные скобки.
Если метод функционального интерфейса возвращает значение, необходимо
вернуть его с помощью `return`:

```
Function<Integer, Integer> square = x -> {
    int y = x * x;
    return y;
};
```

### Ошибка № 4. Неправильное определение типа лямбда-выражения

Лямбда-выражению нужен целевой тип — функциональный интерфейс. Нельзя просто написать:

```
var f = x -> x + 1; // Ошибка! Неизвестен целевой функциональный интерфейс.
```

Нужно явно указать тип:

```
Function<Integer, Integer> f = x -> x + 1;
```
