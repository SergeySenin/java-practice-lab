Проблемы точности и специальные значения

## 1. Введение

Кажется, что если компьютер «умный», то `0.1 + 0.2` должно быть просто `0.3`. Но это
не совсем так. Давайте разберёмся на простом примере.

```
double x = 0.1;
double y = 0.2;
double sum = x + y;

System.out.println(sum); // Что выведет программа?
```

Сложение вещественных чисел: ожидаем `0.3`, а что получится на самом деле?

А теперь попробуем сравнить результат с `0.3`:

```
System.out.println(sum == 0.3); // Тут будет true или false?
```

Если вы увидите `false`, не удивляйтесь.

### Причина кроется в представлении чисел в памяти

Компьютеры работают с числами в двоичной системе. Но далеко не все десятичные дроби можно
представить конечной двоичной дробью, так же как `1 / 3` нельзя точно записать конечной
десятичной дробью: `0.333...`. Например, `0.1` в двоичной системе — это бесконечная дробь,
и её приходится округлять для хранения.

Если перевести это на бытовой язык, то `double` иногда делает вид, что хранит ваше число
точно, но на самом деле хранит очень близкое приближённое значение.

## 2. Какие странности бывают при арифметике с `double`?

Давайте рассмотрим практические примеры.

### Пример: Классическая магия `0.1 + 0.2`

```
double a = 0.1;
double b = 0.2;
double sum = a + b;

System.out.println(sum);        // 0.30000000000000004
System.out.println(sum == 0.3); // false
```

Компьютер вывел не `0.3`, а `0.30000000000000004`. Разница маленькая, но если вы занимаетесь,
например, финансами, это уже может быть критично.

### Пример: Итеративное сложение

```
double result = 0;

for (int i = 0; i < 10; i++) {
    result += 0.1;
}

System.out.println(result); // 0.9999999999999999
```

Хотели получить `1.0`, а получили чуть меньше. Причина снова в округлении внутри `double`.

### Почему это важно в реальных задачах

Многие думают: «Какая разница? Ну небольшая ошибка, подумаешь!» Рассмотрим пример из мира
платежей.

Допустим, ваш интернет-банк складывает большое количество транзакций с дробными суммами.
Если программа будет постоянно накапливать даже маленькие погрешности, то на масштабе банка
они могут превратиться в заметную проблему. Вот тут к вам сразу придёт бухгалтер и спросит:
«Где наши деньги?»

## 3. Как правильно сравнивать вещественные числа

Поскольку `double` часто не может хранить именно то значение, которое вы ожидаете, прямое
сравнение через `==` может подвести. Вместо этого принято сравнивать **модуль разности чисел**
с некоторым **очень маленьким числом** — `epsilon`.

### Пример сравнения с допуском

```
double a = 0.1 + 0.2;
double b = 0.3;
double epsilon = 0.000001;

if (Math.abs(a - b) < epsilon) {
    System.out.println("Почти равно!"); // Так сравнивать безопаснее
}
```

Здесь мы говорим: «Если разница между числами меньше, чем одна миллионная, считаем, что числа
равны».

Примечание: функция `Math.abs(value)` возвращает абсолютное значение, то есть модуль
переданного в неё числа.

## 4. Специальные значения `double`: `Infinity`, `NaN`, `-Infinity`

Тип `double` хранит не только обычные числа, но и особые значения. Они возникают в ситуациях,
которые математик обычному студенту строго-настрого запрещает.

### Бесконечность: `Infinity`

Что будет, если поделить `1.0` на `0.0`?

```
double result = 1.0 / 0.0;
System.out.println(result); // Infinity
```

В Java деление на `0.0` для `double` не вызывает исключения. Вместо этого результат становится
специальным значением — положительной бесконечностью.

### Минус бесконечность: `-Infinity`

Если поделить отрицательное число на `0.0`, вы получите отрицательную бесконечность:

```
double result = -1.0 / 0.0;
System.out.println(result); // -Infinity
```

### Не число: `NaN` — Not a Number

Если сделать что-то совсем странное, например попытаться вычислить квадратный корень
из отрицательного числа, получится `NaN`:

```
double result = Math.sqrt(-1);
System.out.println(result); // NaN
```

Или, например, если разделить `0.0` на `0.0`:

```
double result = 0.0 / 0.0;
System.out.println(result); // NaN
```

`NaN` — это специальное значение для результата, который не является корректным числом.

### Проверка на специальные значения

В Java есть методы для проверки специальных значений:

```
System.out.println(Double.isInfinite(result)); // true, если бесконечность
System.out.println(Double.isNaN(result));      // true, если NaN
```

### Таблица: как `double` реагирует на необычные операции

| Операция        | Результат   | Что хранится в `double` |
|-----------------|-------------|-------------------------|
| `1.0 / 0.0`     | `Infinity`  | `+∞`                    |
| `-1.0 / 0.0`    | `-Infinity` | `-∞`                    |
| `0.0 / 0.0`     | `NaN`       | Не число                |
| `Math.sqrt(-1)` | `NaN`       | Не число                |

## 5. Типичные ошибки при работе с вещественными числами

### Сравнение дробных чисел через `==`

Самая распространённая ловушка — попытка проверить, равны ли два вычисленных числа
с плавающей точкой через обычное сравнение. Из-за накопления ошибок округления можно получить
неожиданный результат. Для вычисленных значений обычно используйте сравнение с допуском:
`epsilon`.

### Неожиданные `NaN` и `Infinity` в вычислениях

Если не контролировать деление на ноль или корни из отрицательных чисел, в программе могут
появиться `NaN` или `Infinity` и повлиять на все последующие расчёты. Проверяйте
подозрительные значения с помощью `Double.isNaN()` и `Double.isInfinite()` — это поможет
избежать неприятных сюрпризов.

### Использование `NaN` в качестве маркера

Некоторые новички используют `NaN` как специальное значение для проверки: например,
«если не найдено — вернём `NaN`». Но помните: `NaN` коварен, и сравнение через `==`
не сработает. Проверяйте его только через специальный метод `Double.isNaN()`.

```
double value = Double.NaN;

System.out.println(value == Double.NaN); // false
System.out.println(Double.isNaN(value)); // true
```

### Ожидание исключения при делении на `0.0`

В отличие от деления целых чисел, деление `double` на `0.0` не вызывает ошибку, а возвращает
`Infinity`, `-Infinity` или `NaN`. Это может привести к тихим и трудноуловимым багам:
результат есть, но он не такой, как вы ожидали.
