Использование `super`: вызов конструктора и методов базового класса

## 1. Использование `super` для вызова методов базового класса

Когда вы создаёте подкласс, иногда возникает ситуация, когда нужно обратиться
к полям или методам базового класса, особенно если вы переопределили метод
или скрыли поле в подклассе. Для этого в Java существует специальное
ключевое слово — `super`.

Если проводить аналогию, то `super` — это как «мама, помоги!», когда вы в подклассе
хотите явно обратиться к тому, что определено в родителе.

Представьте, что у вас есть класс `Animal` с методом `eat()`, который просто выводит
`Животное ест`. А в классе `Cat` вы хотите, чтобы кошка сначала делала что-то своё
(например, мяукала), а потом всё равно выполняла стандартное «животное ест».
Вот тут и пригодится `super.eat()`.

Когда в подклассе вы переопределяете метод, но хотите внутри него всё равно вызвать
реализацию этого метода из базового класса, используйте `super.имяМетода()`.

### Пример: расширяем поведение

```
class Animal {
    void eat() {
        System.out.println("Животное ест");
    }
}

class Cat extends Animal {
    @Override
    void eat() {
        System.out.println("Кошка нюхает еду...");
        super.eat(); // вызываем метод eat() из Animal
        System.out.println("Кошка довольно мурлычет");
    }
}
```

### Как это работает?

* Когда вызывается `eat()` у объекта типа `Cat`, сначала выполняется код
  из `Cat.eat()`, то есть собственный метод.
* Внутри этого метода мы явно вызываем `super.eat()`, то есть реализацию
  из родительского класса `Animal`.
* Это позволяет добавить дополнительное поведение, не забыв про «родительское».

### Практика: используем в приложении

Допустим, в нашем учебном приложении есть базовый класс `Animal` и подклассы `Dog`
и `Cat`. Мы хотим, чтобы при кормлении животного выполнялись как общие действия
(например, увеличение сытости), так и специфические для каждого животного.

```
class Animal {
    int satiety = 0;

    void eat() {
        satiety += 10;
        System.out.println("Животное ест. Сытость: " + satiety);
    }
}

class Dog extends Animal {
    @Override
    void eat() {
        System.out.println("Собака виляет хвостом перед едой");
        super.eat();
    }
}
```

Теперь, если вызвать `dog.eat()`, вы увидите оба сообщения, и `satiety`
увеличится корректно.

## 2. Использование `super` для доступа к полям базового класса

Если в подклассе вы объявили поле с тем же именем, что и в родительском классе,
оно **скрывает** поле родителя. Иногда нужно получить доступ к полю базового класса —
для этого и нужен `super.имяПоля`.

### Пример: скрытие поля

```
class Animal {
    String name = "Животное";
}

class Cat extends Animal {
    String name = "Кошка";

    void printNames() {
        System.out.println("Имя из Cat: " + name);
        System.out.println("Имя из Animal: " + super.name);
    }
}
```

Вызов `new Cat().printNames();` выведет:

```text
Имя из Cat: Кошка
Имя из Animal: Животное
```

В реальной практике скрывать поля не рекомендуется без крайней необходимости,
но знать про такую возможность стоит.

## 3. Вызов конструктора базового класса через `super(...)`

### Как создаются объекты в иерархии?

Когда вы создаёте объект подкласса, **сначала выполняется конструктор базового класса,
а уже потом — тело конструктора подкласса**. Между ними выполняются инициализаторы
полей и нестатические блоки подкласса. Это нужно, чтобы все части объекта
инициализировались в правильном порядке.

### Явный вызов конструктора базового класса

Если у базового класса есть доступный конструктор без параметров — всё просто:
Java сама вызовет его, если в конструкторе подкласса нет явного вызова `super(...)`
или `this(...)`. Но если у родителя **нет** доступного конструктора без параметров,
нужно явно вызвать подходящий конструктор через `super(...)` (возможно,
из конструктора, которому делегировали вызов через `this(...)`).

Пример:

```
class Animal {
    String name;

    Animal(String name) {
        this.name = name;
        System.out.println("Создано животное: " + name);
    }
}

class Cat extends Animal {
    Cat(String name) {
        super(name); // обязательно! Нет конструктора Animal() без параметров
        System.out.println("Создана кошка: " + name);
    }
}
```

Вызов `new Cat("Мурка")` напечатает:

```text
Создано животное: Мурка
Создана кошка: Мурка
```

Важно: в Java 17 вызов `super(...)` должен быть первым оператором конструктора
подкласса. Если попытаться написать перед ним, например, `System.out.println(...)`,
компилятор выдаст ошибку.

### Если не вызвать явно?

Если у родителя есть только конструктор с параметрами, а вы не вызвали его
явно через `super(...)` (или через другой конструктор подкласса), компилятор
выдаст ошибку, например `constructor Animal in class Animal cannot be applied to given types`.

## 4. Полезные нюансы

### Когда использовать `super`?

#### Для расширения, а не замещения поведения

Иногда вы хотите не полностью заменить поведение метода, а только «расширить» его.
Например, добавить что-то до или после родительской логики. В таких случаях
используйте `super.имяМетода()` в теле переопределённого метода.

#### Для инициализации унаследованных полей

Если у родителя есть обязательные для инициализации поля (например, имя животного),
вызывайте его подходящий конструктор с нужными параметрами через `super(...)`.

#### Для доступа к скрытым полям и переопределённым методам

Если вы по каким-то причинам скрыли поле или переопределили метод родителя
и вам всё же нужно обратиться к его реализации, используйте `super.имяПоля`
или `super.имяМетода()`.

### Ограничения и особенности использования `super`

* В Java 17 вызов конструктора родителя через `super(...)` допустим только
  в конструкторе подкласса и только первым оператором.
* Нельзя вызвать конструктор родителя вне конструктора подкласса.
* Если не вызвать `super(...)` или `this(...)` явно, Java попытается вызвать
  доступный конструктор родителя без параметров.
* `super` нельзя использовать в статическом контексте. Доступ к членам через
  `super` возможен в нестатических методах, конструкторах и инициализаторах экземпляра.
* Если поле или метод родителя — `private`, то `super` не поможет: к приватным
  членам из подкласса доступа нет.

## 5. Примеры для закрепления

### Пример 1. Расширяем метод с помощью `super`

```
class Animal {
    void makeSound() {
        System.out.println("Животное издаёт звук");
    }
}

class Dog extends Animal {
    @Override
    void makeSound() {
        super.makeSound(); // сначала делаем стандартное действие
        System.out.println("Собака лает: Гав-гав!");
    }
}
```

### Пример 2. Вызов конструктора базового класса

```
class Vehicle {
    String brand;

    Vehicle(String brand) {
        this.brand = brand;
        System.out.println("Транспорт: " + brand);
    }
}

class Car extends Vehicle {
    int year;

    Car(String brand, int year) {
        super(brand); // вызываем конструктор родителя
        this.year = year;
        System.out.println("Машина " + brand + ", год: " + year);
    }
}
```

Использование:

```
Car car = new Car("Toyota", 2023);
```

Вывод:

```text
Транспорт: Toyota
Машина Toyota, год: 2023
```

### Пример 3. Классическая ошибка: забыли вызвать `super(...)`

```
class Animal {
    String name;

    Animal(String name) {
        this.name = name;
    }
}

class Cat extends Animal {
    Cat() {
        // super();  // Ошибка! Нет конструктора Animal() без параметров
                     // Нужно явно вызвать подходящий конструктор Animal(String)
        super("Безымянная кошка");
    }
}
```

## 6. Типичные ошибки при работе с `super`

### Ошибка № 1. Вызов `super(...)` не первым оператором конструктора

В Java 17 вызов конструктора родителя через `super(...)` должен быть первым оператором
конструктора подкласса. Если вы попытаетесь сделать что-то до этого вызова
(например, распечатать сообщение), компилятор выдаст ошибку.

### Ошибка № 2. Нет подходящего конструктора у родителя

Если у базового класса нет конструктора без параметров, а вы не вызвали
другой конструктор через `super(...)`, компилятор не сможет добавить вызов
по умолчанию и сообщит об ошибке.

### Ошибка № 3. Попытка обратиться к приватным членам родителя через `super`

Ключевое слово `super` не даёт магического доступа к приватным полям или методам
родителя. Если что-то объявлено как `private`, оно остаётся недоступным для подкласса.

### Ошибка № 4. Скрытие полей и переопределение методов без понимания

Если вы объявили в подклассе поле или метод с тем же именем, что и у родителя,
и забыли про это, возможны неожиданные результаты. При необходимости обратитесь
к полю родителя через `super.имяПоля`, а к его переопределённому методу —
через `super.имяМетода()`.

### Ошибка № 5. Использование `super` в статическом методе

В статических методах нельзя использовать `super`, потому что они не принадлежат
конкретному объекту.
