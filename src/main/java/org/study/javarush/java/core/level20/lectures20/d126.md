Множественная реализация интерфейсов

## 1. Введение

В Java нельзя наследовать сразу несколько классов. Это помогает избежать
неоднозначностей, например знаменитой «проблемы ромба» (diamond problem):
если два родительских класса определяют один и тот же метод, непонятно,
какую реализацию брать. Но вот интерфейсов можно реализовывать сколько угодно!

Почему? До Java 8 интерфейсы содержали только контракты без реализации методов.
С Java 8 появились `default`- и `static`-методы с реализацией, поэтому
конфликты всё-таки возможны. Однако Java требует явно разрешить конфликт
унаследованных `default`-методов, а не выбирает одну реализацию произвольно.

Это похоже на ситуацию в реальной жизни: вы можете быть одновременно
«Водителем», «Пользователем компьютера» и «Пловцом». Каждый из этих
«интерфейсов» описывает определённые умения, но не заставляет вас быть
копией другого человека.

### Синтаксис множественной реализации интерфейсов

В Java класс может реализовывать несколько интерфейсов, перечислив их через
запятую после ключевого слова `implements`. Вот базовый пример:

```
// Movable.java
public interface Movable {
    void move(int x, int y);
}
```

```
// Chargeable.java
public interface Chargeable {
    void charge();
}
```

```
// Robot.java
public class Robot implements Movable, Chargeable {
    @Override
    public void move(int x, int y) {
        System.out.println("Робот двигается в точку (" + x + ", " + y + ")");
    }

    @Override
    public void charge() {
        System.out.println("Робот заряжается.");
    }
}
```

В этом примере `Robot` — универсальный парень: он и двигается, и заряжается.
Всё как в жизни: умеешь больше — тебя чаще зовут на собеседования!

## 2. Зачем это нужно? Практические примеры

### Пример 1. Разные «роли» объекта

Представьте, что вы проектируете игрового персонажа:

* Он может двигаться (`Movable`).
* Может атаковать (`Attackable`).
* Может сохраняться в файл (`Serializable` — такой интерфейс есть в стандартной
  библиотеке Java).

```
// Attackable.java
public interface Attackable {
    void attack();
}
```

```
// Hero.java
public class Hero implements Movable, Attackable, java.io.Serializable {
    @Override
    public void move(int x, int y) {
        System.out.println("Герой перемещается на новую позицию.");
    }

    @Override
    public void attack() {
        System.out.println("Герой наносит удар!");
    }
}
```

Здесь используется интерфейс `Movable` из первого раздела. Интерфейс
`Serializable` не объявляет методов: это интерфейс-маркер. Он указывает,
что объект предназначен для стандартного механизма сериализации Java.

Теперь ваш класс может использоваться в самых разных контекстах: его можно
передавать в методы, которые требуют любого из этих интерфейсов.

### Пример 2. Комбинирование стандартных интерфейсов

Очень часто в стандартной библиотеке Java встречаются интерфейсы `Comparable`
(для сравнения объектов) и `Serializable` (для сериализации объектов).
Иногда нужно, чтобы объект был и тем, и другим:

```
// Person.java
public class Person implements Comparable<Person>, java.io.Serializable {
    private String name;
    private int age;

    public Person(String name, int age) {
        this.name = name;
        this.age = age;
    }

    @Override
    public int compareTo(Person other) {
        return Integer.compare(this.age, other.age);
    }
}
```

Теперь объекты `Person` можно сортировать (например, в списке) и
сериализовать, в том числе для записи в файл.

## 3. Особенности и ограничения

### Одна реализация на метод

Если два интерфейса определяют метод с одинаковой сигнатурой и совместимым
возвращаемым типом, достаточно одной реализации. Пример:

```
// A.java
public interface A {
    void doSomething();
}
```

```
// B.java
public interface B {
    void doSomething();
}
```

```
// MyClass.java
public class MyClass implements A, B {
    @Override
    public void doSomething() {
        System.out.println("Реализация doSomething для обоих интерфейсов.");
    }
}
```

Java не будет ругаться — главное, чтобы требования обоих интерфейсов были
совместимы. Если методы отличаются по спискам параметров, это разные методы:
нужно реализовать каждый. Если их возвращаемые типы несовместимы, одной
реализацией удовлетворить оба контракта не получится.

### Нет «алмаза смерти»

В отличие от множественного наследования классов, при реализации нескольких
интерфейсов Java не выбирает произвольно между унаследованными реализациями.
До Java 8 в интерфейсах не было методов с реализацией, а с появлением
`default`-методов при конфликте обычно нужно явно переопределить метод
в реализующем классе.

### Нет состояния

Интерфейсы не могут содержать обычных полей экземпляра — только константы
`public static final`. Поэтому они не хранят отдельное состояние каждого
объекта. Однако у разных интерфейсов могут быть одноимённые константы:
обращение к ним без указания интерфейса иногда становится неоднозначным.

## 4. Пример: реализуем несколько интерфейсов в одном классе

Давайте добавим к нашему учебному приложению (например, к зоопарку) новые
возможности. Пусть у нас есть животные, которые могут двигаться и подавать голос.
Используем интерфейс `Movable` из первого раздела и объявим `Soundable`:

```
// Soundable.java
public interface Soundable {
    void makeSound();
}
```

```
// Dog.java
public class Dog implements Movable, Soundable {
    private String name;

    public Dog(String name) {
        this.name = name;
    }

    @Override
    public void move(int x, int y) {
        System.out.println(name + " бежит к (" + x + ", " + y + ")");
    }

    @Override
    public void makeSound() {
        System.out.println(name + " говорит: Гав-гав!");
    }
}
```

```
// Cat.java
public class Cat implements Movable, Soundable {
    private String name;

    public Cat(String name) {
        this.name = name;
    }

    @Override
    public void move(int x, int y) {
        System.out.println(name + " крадётся к (" + x + ", " + y + ")");
    }

    @Override
    public void makeSound() {
        System.out.println(name + " говорит: Мяу!");
    }
}
```

Теперь мы можем написать универсальные методы для работы с любым
«двигающимся» или «звучащим» объектом:

```
// ZooDemo.java
public class ZooDemo {
    public static void testMovable(Movable m) {
        m.move(10, 20);
    }

    public static void testSoundable(Soundable s) {
        s.makeSound();
    }

    public static void main(String[] args) {
        Dog rex = new Dog("Рекс");
        Cat murka = new Cat("Мурка");

        testMovable(rex);      // Рекс бежит к (10, 20)
        testSoundable(murka);  // Мурка говорит: Мяу!
    }
}
```

И, конечно, если объект реализует оба интерфейса, его можно передавать
и туда, и туда!

## 5. Полезные нюансы

### Если интерфейсы конфликтуют?

Иногда бывает, что два интерфейса определяют методы с одинаковой сигнатурой,
но с разным смыслом. Например, один интерфейс ожидает, что метод `reset()`
сбросит координаты, а другой — что этот же метод выключит устройство.
В этом случае придётся быть внимательным: реализовать метод всё равно
нужно один раз, и его поведение должно удовлетворять обоим контрактам.
Если это невозможно, стоит пересмотреть проектирование.

В реальной жизни такие ситуации редки, но если встретились — стоит задуматься
о корректности архитектуры.

### Пример с коллекцией объектов разных интерфейсов

Допустим, у нас есть массив объектов, реализующих один и тот же интерфейс
`Movable`. Мы можем перебрать их и вызвать нужные методы:

```
// MovableDemo.java
public class MovableDemo {
    public static void main(String[] args) {
        Movable[] movables = {
            new Dog("Шарик"),
            new Cat("Барсик"),
            new Robot()
        };

        for (Movable m : movables) {
            m.move(0, 0);
        }
    }
}
```

Здесь используются классы `Dog`, `Cat` и `Robot` из предыдущих разделов.
Аналогично можно сделать для любого интерфейса.

## 6. Типичные ошибки при множественной реализации интерфейсов

### Ошибка № 1. Не реализованы все методы интерфейсов

Если конкретный класс объявил, что реализует интерфейс, но не обеспечил
реализацию хотя бы одного обязательного абстрактного метода — компилятор
выдаст ошибку. Не забывайте про все методы, даже если они кажутся «лишними».

### Ошибка № 2. Конфликтующие методы с одинаковой сигнатурой

Если два интерфейса определяют одинаковые абстрактные методы с совместимыми
возвращаемыми типами, достаточно одной реализации. Но если смысл этих методов
разный, это может привести к путанице и багам. В этом случае лучше
переосмыслить архитектуру. Конфликт одинаковых `default`-методов также
требует явного разрешения.

### Ошибка № 3. Попытка наследовать интерфейс через `extends` в классе

В классе для реализации интерфейса используется `implements`, а не `extends`:

```
public class MyClass implements A, B { /* ... */ }  // Правильно
public class MyClass extends A, B { /* ... */ }     // Ошибка!
```

Синтаксис с `extends` здесь намеренно ошибочный.

### Ошибка № 4. Попытка создать объект интерфейса

Интерфейс — это контракт, его нельзя создать напрямую:

```
Movable m = new Movable(); // Ошибка компиляции
```

Создавать можно только объекты конкретных классов, реализующих интерфейс.
