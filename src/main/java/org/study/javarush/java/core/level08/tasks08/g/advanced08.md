Задание 08. Система обработки обращений техподдержки (Support Desk System)

Вы разрабатываете консольную систему обработки обращений пользователей в службу технической
поддержки.

Программа должна:

* получить сведения об обращении;
* нормализовать его заголовок;
* определить приоритет;
* проверить возможность принять обращение в обработку;
* обработать статистические данные;
* создать объект обращения;
* обновить его состояние;
* сформировать итоговый отчёт.

Главная цель задания — не поместить всю логику внутрь главного метода (`main`), а
**разделить программу на методы с понятной ответственностью** .

Каждый метод должен выполнять одну определённую задачу.

## 1. Структура программы

Создайте два Java-класса:

```
Solution
SupportRequest
```

Каждый публичный класс разместите в отдельном файле:

```
Solution.java
SupportRequest.java
```

Главный метод программы (`main`) должен находиться в классе `Solution`.

Используйте классическую сигнатуру:

```
public static void main(String[] args)
```

Для чтения пользовательских данных подключите класс «сканер» (`Scanner`) из пакета `java.util`.

## 2. Основной принцип задания

Метод `main` должен выполнять роль **координатора программы**.

В нём разрешается:

* считывать исходные данные;
* создавать массивы;
* создавать объекты;
* вызывать методы;
* сохранять возвращённые методами значения;
* передавать результат одного метода другому;
* выводить результаты диагностических экспериментов.

Основные вычисления и обработку данных необходимо вынести в отдельные методы.

Например, поиск суммы элементов массива должен выполняться методом для расчёта суммы, а не отдельным
циклом непосредственно внутри `main` .

## 3. Этап 1. Статистика работы системы

В классе `Solution`, но **за пределами всех методов**, создайте поле:

«количество обработанных обращений» (`processedRequestCount`) типа `int`.

Поле должно быть:

* приватным (`private`);
* статическим (`static`);
* первоначально равным `0`.

Это поле принадлежит самому классу `Solution` и должно использоваться разными статическими методами
класса.

## 4. Этап 2. Ввод обращения

В методе `main` получите следующие значения.

С помощью `nextLine()`:

* «исходный заголовок обращения» (`requestTitleInput`).

С помощью `nextInt()`:

* «идентификатор обращения» (`requestId`);
* «серьёзность проблемы» (`severityLevel`);
* «количество затронутых пользователей» (`affectedUsers`);
* «время ожидания в минутах» (`waitingMinutes`).

Для основного теста используйте:

```text
   Payment service unavailable   
501
4
120
95
```

Значения серьёзности для задания находятся в диапазоне:

```text
1–5
```

Дополнительную валидацию этого диапазона выполнять не требуется.

## 5. Этап 3. Метод нормализации заголовка

Создайте статический метод:

«нормализовать заголовок» (`normalizeTitle`).

Метод должен:

* принимать один параметр типа `String`;
* удалять пробелы в начале и конце строки методом `trim()`;
* возвращать обработанную строку;
* ничего не выводить самостоятельно.

Возвращаемый тип метода:

```
String
```

В `main` вызовите `normalizeTitle`, передав `requestTitleInput`.

Сохраните возвращённое значение в:

«заголовок обращения» (`requestTitle`).

Для основного теста:

```text
requestTitle → Payment service unavailable
```

Этот этап должен показать разницу между:

> метод что-то **возвращает**

и:

> метод сам что-то **выводит**.

`normalizeTitle` должен только возвращать результат.

## 6. Этап 4. Метод расчёта приоритета

Создайте статический метод:

«рассчитать приоритет» (`calculatePriority`).

Он принимает три параметра типа `int`:

* серьёзность (`severityLevel`);
* количество затронутых пользователей (`affectedUsers`);
* время ожидания (`waitingMinutes`).

Метод должен возвращать `int`.

Правила:

### Критический приоритет — `3`

Верните `3`, если выполняется хотя бы одно условие:

* `severityLevel >= 4`;
* `affectedUsers >= 100`.

### Средний приоритет — `2`

Если критический уровень не был определён, верните `2`, когда:

* `severityLevel >= 2`;
* **или** `waitingMinutes >= 60`.

### Обычный приоритет — `1`

Во всех остальных случаях верните:

```
1
```

Все возможные пути выполнения метода должны возвращать значение.

Для основных тестовых данных:

```text
priorityLevel → 3
```

Сохраните результат вызова метода в переменную:

«уровень приоритета» (`priorityLevel`).

## 7. Этап 5. Метод проверки обращения

Создайте статический метод:

«можно принять обращение» (`isRequestAccepted`).

Метод принимает:

* заголовок обращения (`requestTitle`) типа `String`;
* уровень приоритета (`priorityLevel`) типа `int`.

Возвращаемый тип:

```
boolean
```

Обращение считается допустимым, если одновременно:

* заголовок не является пустой строкой;
* приоритет находится в диапазоне от `1` до `3` включительно.

Метод должен возвращать результат логического выражения.

Он не должен выводить `"true"` или `"false"` самостоятельно.

Сохраните результат в переменную:

«обращение принято» (`isRequestAcceptedResult`).

Для основного теста:

```text
isRequestAcceptedResult → true
```

## 8. Этап 6. Досрочный `return` в `void`-методе

Создайте статический метод:

«вывести критическое предупреждение» (`printCriticalWarning`).

Метод принимает:

* уровень приоритета (`priorityLevel`) типа `int`;
* заголовок (`requestTitle`) типа `String`.

Метод ничего не возвращает:

```
void
```

Если приоритет **не равен `3`**, метод должен немедленно завершиться через:

```
return;
```

и ничего не выводить.

Если приоритет равен `3`, выведите:

```text
CRITICAL REQUEST: Payment service unavailable
```

Таким образом, здесь `return` используется не для возврата значения, а для
**досрочного завершения void-метода** .

## 9. Этап 7. Метод регистрации обработанного обращения

Создайте статический метод:

«зарегистрировать обработанное обращение» (`registerProcessedRequest`).

Метод принимает один параметр:

«обращение принято» (`isAccepted`) типа `boolean`.

Возвращаемый тип:

```
void
```

Если `isAccepted == false`, завершите метод через ранний:

```
return;
```

Если обращение принято, увеличьте статическое поле:

```
processedRequestCount
```

на единицу.

Для основного теста после одного принятого обращения:

```text
processedRequestCount → 1
```

## 10. Этап 8. Метод получения счётчика

Создайте статический метод:

«получить количество обработанных обращений» (`getProcessedRequestCount`).

Метод:

* не принимает параметров;
* возвращает значение типа `int`;
* возвращает текущее значение поля `processedRequestCount`.

В `main` получите значение через этот метод.

Не обращайтесь к `processedRequestCount` напрямую из основной логики после его первоначального
объявления.

## 11. Этап 9. Массив нагрузки

В `main` создайте массив:

«нагрузка за предыдущие периоды» (`requestLoads`) типа `int[]`.

Используйте быструю инициализацию:

```text
3, 7, 2, 5
```

То есть массив содержит количество обращений за четыре предыдущих временных периода.

## 12. Этап 10. Метод расчёта общей нагрузки

Создайте статический метод:

«рассчитать общую нагрузку» (`calculateTotalLoad`).

Метод принимает:

```
int[]
```

и возвращает:

```
int
```

Внутри метода:

1. создайте локальную переменную суммы;
2. переберите все элементы переданного массива;
3. прибавьте каждый элемент к сумме;
4. верните итоговое значение через `return`.

Для:

```text
[3, 7, 2, 5]
```

должно получиться:

```text
totalLoad → 17
```

Переменная суммы должна существовать только внутри `calculateTotalLoad`.

## 14. Этап 12. Изменение массива внутри метода

Создайте статический метод:

«улучшить время ответа» (`improveResponseTimes`).

Метод принимает:

* массив `responseTimes`;
* количество минут улучшения (`improvementMinutes`) типа `int`.

Возвращаемый тип:

```
void
```

Метод должен пройти по всем элементам массива и уменьшить каждый элемент на значение
`improvementMinutes` .

Для основного теста передайте:

```
5
```

До вызова:

```text
[40, 55, 30, 70]
```

После вызова:

```text
[35, 50, 25, 65]
```

Метод не должен создавать новый массив.

Он должен изменить элементы **переданного объекта-массива**.

После возврата из метода изменения должны быть видны в `main`.

## 15. Этап 13. Попытка заменить массив через параметр

Создайте ещё один статический метод:

«попытаться заменить время ответа» (`tryToReplaceResponseTimes`).

Метод принимает один параметр типа:

```
int[]
```

Внутри метода присвойте параметру **новый массив**, например:

```text
5, 5, 5, 5
```

Возвращаемый тип:

```
void
```

После вызова метода снова выведите `responseTimes` в `main`.

До вызова:

```text
[35, 50, 25, 65]
```

После вызова исходный массив в `main` должен остаться:

```text
[35, 50, 25, 65]
```

То есть присваивание параметру новой ссылки не должно заменить значение переменной `responseTimes` в

## 16. Этап 14. Правильная замена массива через return

«создать новый набор времени ответа» (`createReplacementResponseTimes`).

Он должен создать и вернуть новый массив:

```

В `main` вызовите метод и **присвойте возвращённый массив переменной `responseTimes`**.

вернуть новый объект и присвоить его вызывающей переменной
```

## 22. Этап 20. Публичный метод вывода карточки обращения

Таким образом:

## 30. Этап 28. Передача результата одного метода другому

При окончательном выводе отчёта
**не сохраняйте результат `buildRequestSummary()` в промежуточную переменную** .

Передайте его непосредственно как аргумент метода `printReport`.

То есть этот этап должен концептуально соответствовать цепочке:

Так один метод возвращает значение, которое сразу становится аргументом другого метода.

## 31. Этап 29. Основной порядок работы `main`

Метод `main` должен организовать программу примерно в следующем логическом порядке:

1. считать данные;
2. получить нормализованный заголовок через `normalizeTitle`;
3. получить приоритет через `calculatePriority`;
4. проверить обращение через `isRequestAccepted`;
5. вызвать `printCriticalWarning`;
6. зарегистрировать обращение через `registerProcessedRequest`;
7. получить счётчик через `getProcessedRequestCount`;
8. обработать массив `requestLoads`;
9. выполнить эксперименты с `responseTimes`;
10. выполнить эксперимент с `dailyRequestLimit`;
11. создать объект `SupportRequest`;
12. установить его поля;
13. вывести карточку;
14. изменить объект через `updateRequestTitle`;
15. проверить `tryToReplaceRequest`;
16. сформировать и вывести итоговый отчёт через методы.

В `main` не переносите обратно логику, для которой в задании указан отдельный метод.
