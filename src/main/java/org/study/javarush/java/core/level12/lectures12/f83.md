Учимся работать с API и следим за МКС

## 1. Введение

Сегодня почти любое современное приложение использует **данные из интернета**. Когда вы открываете
погоду в телефоне, заказываете такси или читаете новости, за этим часто стоит работа с **API**.
Программы «разговаривают» друг с другом, обмениваются сообщениями, и нередко эти сообщения
передаются в виде текста — в формате JSON.

JSON (JavaScript Object Notation) стал распространённым форматом обмена данными между сервисами.
Его любят и программисты, и машины: человек легко прочитает текст, а программа легко его разберёт.
В JSON всего несколько правил:

* данные могут быть представлены как **объекты-словари** — `{ "ключ": значение }`;
* как **массивы** — `[значение1, значение2]`;
* или как простые строки, числа, логические значения (`true`, `false`) и `null`.

Например, вот так может выглядеть JSON-объект, описывающий человека:

```json
{
  "name": "Alice",
  "age": 25,
  "skills": ["Java", "Python", "SQL"]
}
```

Мы видим ключи (`name`, `age`, `skills`) и их значения. Компактно, наглядно и универсально.

## 2. Знакомство с API

**API** (Application Programming Interface) — это «договор» или «контракт», который определяет,
как программы взаимодействуют друг с другом. Для веб-API он, например, говорит: если обратиться
по определённому адресу в интернете и указать нужные параметры, сервис вернёт ответ
в согласованном формате.

Адрес, по которому мы обращаемся для получения данных, называется **endpoint**. Это URL,
по которому доступна определённая функция сервиса. Часто в нём указываются параметры запроса —
так называемые **query-параметры**.

Например, вот такой URL запрашивает погоду по заданным координатам:

```text
https://api.open-meteo.com/v1/forecast?latitude=50.45&longitude=30.52&current_weather=true
```

Если присмотреться, то после знака `?` перечислены параметры:

* `latitude=50.45` — широта;
* `longitude=30.52` — долгота;
* `current_weather=true` — хотим получить текущую погоду.

Некоторые API требуют ещё и специальный «пароль» — **ключ API**. Тогда его могут передавать
в параметрах запроса, например `&apikey=ВАШ_КЛЮЧ`.

Документацию сервиса с погодой можно посмотреть на сайте [open-meteo.com][r1].

## 3. Как выглядит ответ API?

Когда мы делаем запрос к рассматриваемым веб-API, сервер может ответить JSON-текстом.
Иногда это JSON-объект, иногда — JSON-массив.

Пример ответа о погоде:

```json
{
  "latitude": 50.45,
  "longitude": 30.52,
  "current_weather": {
    "temperature": 21.3,
    "windspeed": 5.2,
    "weathercode": 1
  }
}
```

Пример ответа сервиса с координатами МКС:

```json
{
  "timestamp": 1717590000,
  "iss_position": {
    "latitude": "48.1234",
    "longitude": "12.5678"
  },
  "message": "success"
}
```

## 4. Первый пример: получаем погоду

Попробуем написать маленький фрагмент кода, который обратится к бесплатному API погоды
[open-meteo.com][r1] и просто выведет ответ в консоль.

```
String url = "https://api.open-meteo.com/v1/forecast?latitude=50.45"
        + "&longitude=30.52&current_weather=true";

HttpClient client = HttpClient.newHttpClient();
HttpRequest req = HttpRequest.newBuilder(URI.create(url)).GET().build();
HttpResponse<String> resp = client.send(req, HttpResponse.BodyHandlers.ofString());

System.out.println("HTTP статус: " + resp.statusCode());
System.out.println("Ответ сервера:");
System.out.println(resp.body());
```

Здесь мы:

1. Создаём клиент `HttpClient`.
2. Формируем GET-запрос (`HttpRequest`).
3. Отправляем его методом `client.send()`.
4. Получаем тело ответа в виде строки: `HttpResponse<String>`.

Если запрос выполнится успешно и сервер вернёт статус `200`, вы увидите JSON с погодой.

Метод `send()` может выбросить `IOException` или `InterruptedException`, поэтому в этих
фрагментах предполагается, что исключения обрабатываются или объявлены через `throws`.

## 5. Второй пример: следим за МКС

Теперь обратимся к API [open-notify.org][r2], которое предоставляет координаты Международной
космической станции (ISS).

```
String url = "http://api.open-notify.org/iss-now.json";

HttpClient client = HttpClient.newHttpClient();
HttpRequest req = HttpRequest.newBuilder(URI.create(url)).GET().build();
HttpResponse<String> resp = client.send(req, HttpResponse.BodyHandlers.ofString());

System.out.println(resp.body());
```

Результат будет выглядеть примерно так:

```json
{
  "timestamp": 1717590000,
  "iss_position": {
    "latitude": "48.1234",
    "longitude": "12.5678"
  },
  "message": "success"
}
```

Так можно получить координаты станции на момент обновления данных сервисом. Если запустить этот
код снова через минуту, числа могут быть уже другими.

## 6. Полезные нюансы

Когда вы начинаете работать с API, очень важно учитывать несколько вещей.

Во-первых, всегда смотрите на **статус ответа**: `resp.statusCode()`. Если это `200` — запрос
успешно обработан. Если `404` — запрошенный ресурс не найден. Если `401` — запрос не авторизован.
Если `429` — вы делаете слишком много запросов.

Во-вторых, помните о **лимитах**. Бесплатные сервисы могут ограничивать частоту запросов,
чтобы никто не перегружал их серверы.

В-третьих, JSON не всегда будет выглядеть красиво. Иногда это длинная строка в одну линию —
это нормально. Позже мы научимся подключать библиотеки (Jackson, Gson), чтобы «разбирать» JSON
на поля и работать с ними как с объектами.

### Ещё один маленький эксперимент

Возьмём API, которое отдаёт случайный факт о кошках:

```
String url = "https://catfact.ninja/fact";

HttpClient client = HttpClient.newHttpClient();
HttpRequest req = HttpRequest.newBuilder(URI.create(url)).GET().build();
HttpResponse<String> resp = client.send(req, HttpResponse.BodyHandlers.ofString());

System.out.println(resp.body());
```

Запустите этот фрагмент несколько раз, и обычно вы будете получать JSON с разными фактами
о кошках. Однако случайный выбор не гарантирует, что факты никогда не повторятся.

[r1]: https://open-meteo.com/
[r2]: http://api.open-notify.org/iss-now.json
