Method References (`::`): ссылки на методы

## 1. Введение

**Method reference** (или по-русски — ссылка на метод) — это специальный синтаксис в Java,
позволяющий использовать уже существующий метод (или конструктор) в качестве реализации
функционального интерфейса. Ссылку на метод можно передать туда, где ожидается функциональный
интерфейс, если метод совместим с его единственным абстрактным методом.

Синтаксис:

```
Класс::метод
объект::метод
Класс::new
```

Если лямбда — это мини-функция «на лету», то method reference — это просто «передай уже
имеющийся метод». Это похоже на то, как вместо переписывания рецепта вы даёте ссылку
на страницу с рецептом.

### Пример на пальцах

Вместо этого:

```
list.forEach(s -> System.out.println(s));
```

Можно так:

```
list.forEach(System.out::println);
```

Выглядит лаконично, не правда ли?

В этих примерах предполагается, что `list` — уже объявленная коллекция строк.

## 2. Виды method references

У ссылок на методы четыре основные формы. Вот они — и больше ничего не нужно.

### Ссылка на статический метод

Синтаксис: `Класс::статическийМетод`.

Пример:

```
Function<Integer, String> intToString = String::valueOf;
System.out.println(intToString.apply(123)); // 123
```

То же самое через лямбду:

```
Function<Integer, String> intToString = i -> String.valueOf(i);
```

Здесь нужен импорт `java.util.function.Function`.

### Ссылка на нестатический метод объекта

Синтаксис: `объект::метод`.

Пример:

```
PrintStream printer = System.out;
Consumer<String> consumer = printer::println;
consumer.accept("Привет, мир!");
```

Эквивалентно лямбде:

```
Consumer<String> consumer = s -> printer.println(s);
```

Для примера нужны импорты `java.io.PrintStream` и `java.util.function.Consumer`.

### Ссылка на нестатический метод класса

Синтаксис: `Класс::метод`.

Здесь первый аргумент функционального интерфейса становится объектом,
на котором вызывается метод.

Пример:

```
Function<String, Integer> stringLength = String::length;
System.out.println(stringLength.apply("Java")); // 4
```

Здесь `String::length` соответствует лямбде `(String s) -> s.length()`.

### Ссылка на конструктор

Синтаксис: `Класс::new`.

Пример:

```
Supplier<ArrayList<String>> listSupplier = ArrayList::new;
ArrayList<String> list = listSupplier.get();
```

Эквивалентно лямбде:

```
Supplier<ArrayList<String>> listSupplier = () -> new ArrayList<>();
```

Для примера нужны импорты `java.util.ArrayList` и `java.util.function.Supplier`.

## 3. Когда использовать method reference?

Method reference удобно применять, когда лямбда просто вызывает существующий метод
без дополнительной логики — так код становится короче и читабельнее.

### Пример: сортировка списка

Вместо этого:

```
List<String> names = Arrays.asList("Иван", "Петр", "Анна");
names.sort((a, b) -> a.compareToIgnoreCase(b));
```

Можно так:

```
names.sort(String::compareToIgnoreCase);
```

### Пример: обработка коллекций

Вместо:

```
list.forEach(s -> System.out.println(s));
```

Можно вообще коротко:

```
list.forEach(System.out::println);
```

### Пример: преобразование элементов

Вместо:

```
List<String> numbers = Arrays.asList("1", "2", "3");
List<Integer> ints = numbers.stream()
    .map(s -> Integer.parseInt(s))
    .collect(Collectors.toList());
```

Можно:

```
List<Integer> ints = numbers.stream()
    .map(Integer::parseInt)
    .collect(Collectors.toList());
```

Для примеров со списками нужны импорты `java.util.List` и `java.util.Arrays`,
а для `Collectors.toList()` — `java.util.stream.Collectors`.

Подробнее про Stream API и утилитный класс `Collectors` вы узнаете на уровне 30 :P

## 4. Сравнение method reference и лямбда-выражения

### Эквивалентность

Method reference и лямбда-выражение часто взаимозаменяемы. Оба позволяют предоставить
реализацию функционального интерфейса, если типы параметров и результата совместимы.

Пример:

```
Consumer<String> c1 = s -> System.out.println(s);
Consumer<String> c2 = System.out::println;
```

### Когда лучше использовать method reference?

* Когда лямбда просто вызывает существующий метод без дополнительной логики.
* Для повышения читаемости, особенно при длинных цепочках вызовов.
* Когда хочется явно показать: «здесь просто вызов метода».

### Когда method reference не подходит?

* Если нужна дополнительная логика (валидация, условия, обработка ошибок).
* Если параметры надо преобразовать перед вызовом метода.

Пример:

```
list.forEach(s -> {
    if (s != null) {
        System.out.println(s);
    }
});
```

Здесь простая ссылка `System.out::println` не заменит лямбду без изменения поведения:
она не содержит проверки на `null`.

## 5. Практика: переписываем лямбда-выражения с использованием method references

### Пример 1. Выводим имена животных

```
List<String> animals = Arrays.asList("Кот", "Собака", "Попугай");
animals.forEach(animal -> System.out.println(animal));
```

Становится:

```
animals.forEach(System.out::println);
```

### Пример 2. Преобразуем строки в числа

```
List<String> numbers = Arrays.asList("10", "20", "30");
List<Integer> ints = numbers.stream()
    .map(s -> Integer.parseInt(s))
    .collect(Collectors.toList());
```

Становится:

```
List<Integer> ints = numbers.stream()
    .map(Integer::parseInt)
    .collect(Collectors.toList());
```

### Пример 3. Сортировка объектов по имени

```
List<Animal> animalList = ...;
animalList.sort((a, b) -> a.getName().compareTo(b.getName()));
```

Становится:

```
animalList.sort(Comparator.comparing(Animal::getName));
```

Здесь `Animal::getName` — ссылка на нестатический метод класса.
Предполагается, что класс `Animal` имеет метод `getName()`, возвращающий `String`;
`animalList = ...` — незавершённый учебный шаблон. Нужен импорт `java.util.Comparator`.

### Пример 4. Создание объектов через конструктор

```
Supplier<Dog> dogFactory = () -> new Dog();
Dog dog = dogFactory.get();
```

Становится:

```
Supplier<Dog> dogFactory = Dog::new;
Dog dog = dogFactory.get();
```

Предполагается, что у `Dog` есть доступный конструктор без параметров.

## 6. Как работает сопоставление сигнатур

Method reference можно использовать, когда вызываемый метод совместим с единственным
абстрактным методом целевого функционального интерфейса: учитываются параметры,
допустимые преобразования типов и возвращаемое значение.

```
@FunctionalInterface
interface IntToString {
    String convert(int value);
}

public class Demo {
    public static String intToHex(int value) {
        return Integer.toHexString(value);
    }

    public static void main(String[] args) {
        IntToString converter = Demo::intToHex;
        System.out.println(converter.convert(255)); // ff
    }
}
```

Здесь `Demo::intToHex` подходит, потому что принимает `int` и возвращает `String`.

## 7. Method reference и конструкторы с параметрами

Если конструктор принимает параметры, method reference всё равно можно использовать —
при совместимости с методом функционального интерфейса.

```
@FunctionalInterface
interface AnimalFactory {
    Animal create(String name);
}

class Animal {
    private String name;

    public Animal(String name) {
        this.name = name;
    }

    public String getName() {
        return name;
    }
}
```

Использование:

```
AnimalFactory factory = Animal::new;
Animal cat = factory.create("Барсик");
System.out.println(cat.getName()); // Барсик
```

## 8. Типичные ошибки при использовании method references

### Ошибка № 1. Несоответствие сигнатур

Если метод несовместим с абстрактным методом функционального интерфейса,
компилятор выдаст ошибку. Например, интерфейс ожидает два параметра,
а ссылка указывает на метод с одним параметром без подходящего преобразования.

### Ошибка № 2. Неверный порядок аргументов в ссылке `Класс::метод`

Когда используете форму `Класс::метод`, первый параметр функционального интерфейса
становится объектом вызова. Если перепутать количество или порядок параметров —
получите ошибку сопоставления.

### Ошибка № 3. Использование method reference там, где нужна дополнительная логика

Если требуется условие, логирование или обработка исключений — используйте лямбду,
а не простую ссылку на метод.

### Ошибка № 4. Ссылки на перегруженные методы

Если у класса несколько методов с одинаковым именем, компилятор выбирает подходящий
по целевому функциональному интерфейсу. Если однозначно выбрать нельзя,
возникает ошибка компиляции. Иногда помогает явное указание типа интерфейса.

### Ошибка № 5. В целевом интерфейсе отсутствует параметр для объекта вызова

Например, `String::toUpperCase` корректно работает в `map`, потому что строка
передаётся как объект вызова. Но если целевой функциональный интерфейс
не предусматривает такого аргумента, ссылка будет несовместима с ним.
