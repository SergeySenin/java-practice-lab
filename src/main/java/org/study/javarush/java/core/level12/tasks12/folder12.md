## 230.

Сервер не всегда возвращает то, что у него просили: адрес мог смениться, лимит запросов —
закончиться, а внутри сервиса — случиться поломка. Поэтому первое, на что смотрит любое приложение
после обращения к API, — это код статуса ответа. Показывать пользователю тело ответа можно только
тогда, когда статус говорит об успехе.

Отправьте GET-запрос к адресу `https://catfact.ninja/fact` с помощью `HttpClient` и получите ответ
как `HttpResponse<String>`, использовав `BodyHandlers.ofString()`. Затем возьмите числовой
код статуса методом `statusCode()` и по нему решите, что именно вывести на экран:

* `200` — выведите тело ответа;
* `404` — выведите `"Адрес не найден"`;
* `429` — выведите `"Слишком много запросов"`;
* любой другой код — считайте ответ нештатным и выведите `"Ошибка: "` и сам код.

Например, если сервер ответил кодом `500`, на экране должно появиться:

```text
Ошибка: 500
```

Обратите внимание: тело ответа попадает на экран только при коде `200`. При любом другом статусе
программа выводит только соответствующее сообщение и тело ответа не печатает.

Требования:

* Программа должна с помощью `HttpClient` отправить GET-запрос по адресу
  `https://catfact.ninja/fact`.
* Ответ сервера должен быть получен как `HttpResponse<String>` с помощью `BodyHandlers.ofString()`.
* Программа должна получить числовой код статуса ответа методом `statusCode()`.
* В зависимости от кода статуса программа должна выбрать, что вывести: при `200` — тело ответа,
  при `404` — строку `"Адрес не найден"`, при `429` — строку `"Слишком много запросов"`, при любом
  другом коде — строку `"Ошибка: "` и сам код.
* При коде статуса, отличном от `200`, тело ответа на экран выводиться не должно.
