# Задание 05. Инспектор Java-окружения (`Java Environment Inspector`)

Вы создаёте небольшой учебный Java-проект, задача которого — продемонстрировать,
как Java организует исходный код и определяет, какой именно класс используется в программе.

В отличие от предыдущих заданий, основная цель здесь — не написать сложный алгоритм, а
правильно организовать **несколько Java-файлов в пакетах** (`packages`) и
использовать разные способы обращения к классам.

В проекте должно быть три самостоятельных запускаемых класса.

# Этап 1. Создание проекта

Создайте новый проект «инспектор Java-окружения» (`JavaEnvironmentInspector`).

Исходный код проекта должен находиться в папке исходников (`src`).

Для работы со структурой проекта откройте окно «Проект» (`Project`) (`Alt+1`).

Внутри `src` создайте следующие пакеты:

* «приложение» (`org.study.environment.app`);
* «ввод данных» (`org.study.environment.input`);
* «работа с датами» (`org.study.environment.date`).

Для создания пакета:

**Создать (`Alt+Insert`) → Пакет (`Package`)**.

После создания структура исходного кода должна иметь следующий вид:

```text
src/
└── org/
    └── study/
        └── environment/
            ├── app/
            ├── input/
            └── date/
```

# Этап 2. Главный класс приложения (`Main`)

В пакете «приложение» (`org.study.environment.app`) создайте Java-класс «главный» (`Main`).

Имя файла:

```text
Main.java
```

Имя публичного класса:

```text
Main
```

В начале файла должна находиться инструкция объявления пакета (`package`):

```text
package org.study.environment.app;
```

После объявления пакета подключите класс «сканер» (`Scanner`)
из пакета `java.util` с помощью обычной инструкции импорта (`import`).

В этом классе `Scanner` должен использоваться по **простому имени класса** (`simple class name`):

```text
Scanner
```

а не через полное имя `java.util.Scanner`.

## Логика класса

В главном методе программы (`main`):

1. создайте объект «консоль» (`console`) типа `Scanner`;
2. считайте одну строку методом `nextLine()`;
3. сохраните её в переменной «ввод приложения» (`applicationInput`) типа `String`;
4. выведите:

```text
Application input: [введённая строка]
```

## Тест

Введите:

```text
Java project
```

Ожидаемый результат:

```text
Application input: Java project
```

# Этап 3. Использование полного имени класса (`ScannerDemo`)

В пакете «ввод данных» (`org.study.environment.input`)
создайте Java-класс «демонстрация сканера» (`ScannerDemo`).

Имя файла:

```text
ScannerDemo.java
```

Имя публичного класса:

```text
ScannerDemo
```

В начале файла объявите пакет:

```text
package org.study.environment.input;
```

В этом файле отдельная инструкция:

```text
import java.util.Scanner;
```

отсутствует.

Вместо импорта при объявлении и создании объекта используйте
**полное имя класса** (`fully qualified class name`):

```text
java.util.Scanner
```

Создайте объект «консоль» (`console`), связанный со стандартным потоком ввода (`System.in`).

## Логика класса

В методе `main`:

1. создайте объект `Scanner`, указав полное имя класса;
2. считайте строку методом `nextLine()`;
3. сохраните результат в переменной «ввод через полное имя» (`fullyQualifiedInput`);
4. выведите:

```text
Fully qualified Scanner input: [введённая строка]
```

## Тест

Введите:

```text
java.util.Scanner
```

Ожидаемый результат:

```text
Fully qualified Scanner input: java.util.Scanner
```

Таким образом, в проекте должны присутствовать два разных способа использования одного класса:

```text
import java.util.Scanner;
Scanner
```

и

```text
java.util.Scanner
```

# Этап 4. Классы с одинаковым простым именем (`DateDemo`)

В пакете «работа с датами» (`org.study.environment.date`)
создайте Java-класс «демонстрация дат» (`DateDemo`).

Имя файла:

```text
DateDemo.java
```

Имя публичного класса:

```text
DateDemo
```

Объявите пакет:

```text
package org.study.environment.date;
```

В Java существуют два разных класса с одинаковым простым именем `Date`:

```text
java.util.Date
java.sql.Date
```

В этом файле явно импортируйте:

```text
java.util.Date
```

После этого класс `java.util.Date` должен использоваться по простому имени:

```text
Date
```

Создайте переменную «обычная дата» (`utilDate`) и новый объект `Date`.

## SQL-дата

Также создайте переменную «SQL-дата» (`sqlDate`).

Её тип:

```text
java.sql.Date
```

При объявлении переменной и создании объекта используйте **полное имя класса**:

```text
java.sql.Date
```

Для получения текущего времени используйте:

```text
System.currentTimeMillis()
```

Таким образом, в одном Java-файле должны одновременно использоваться:

```text
Date
```

и

```text
java.sql.Date
```

при этом Java должна однозначно понимать, о каком классе идёт речь.

# Этап 5. Вывод информации о датах

В `DateDemo` выведите:

```text
java.util.Date: [значение utilDate]
java.sql.Date: [значение sqlDate]
```

Конкретные значения даты и времени заранее фиксировать не требуется:
они зависят от момента запуска программы.

Важно, чтобы первая строка данных выводила объект `utilDate`, а вторая — объект `sqlDate`.

# Этап 6. Проверка структуры пакетов

После создания всех классов структура должна соответствовать следующей схеме:

```text
JavaEnvironmentInspector/
└── src/
    └── org/
        └── study/
            └── environment/
                ├── app/
                │   └── Main.java
                ├── input/
                │   └── ScannerDemo.java
                └── date/
                    └── DateDemo.java
```

И объявления пакетов должны соответствовать расположению файлов.

Для `Main.java`:

```text
org.study.environment.app
```

Для `ScannerDemo.java`:

```text
org.study.environment.input
```

Для `DateDemo.java`:

```text
org.study.environment.date
```

То есть путь к файлу и инструкция `package` должны описывать одну и ту же структуру.

# Этап 7. Проверка соответствия файла и публичного класса

Проверьте следующие пары:

```text
Main.java        ↔ public class Main
ScannerDemo.java ↔ public class ScannerDemo
DateDemo.java    ↔ public class DateDemo
```

Имя файла и имя публичного класса (`public class`) должны совпадать с учётом регистра.

# Этап 8. Практика рефакторинга в IntelliJ IDEA

После того как проект полностью работает, выполните небольшую проверку возможностей IDE.


* имя Java-файла.

После проверки выполните **Переименовать (`Shift+F6`)** ещё раз и верните:

```text

```

Выберите `ScannerDemo.java`.

Выполните:

```text

```

Проверьте, как изменилось объявление пакета (`package`) в начале файла.

После этого выполните **Переместить (`F6`)** ещё раз и верните класс в:

```text
org.study.environment.input
```

Финальная структура проекта должна снова соответствовать исходному ТЗ.

# Этап 9. Запуск каждого класса

Каждый из трёх классов должен иметь
собственный главный метод (`main`) и запускаться самостоятельно.

Последовательно запустите:

1. `Main`;
2. `ScannerDemo`;
3. `DateDemo`.

Для повторного запуска текущей конфигурации используйте:

**Запустить (`Shift+F10`)**.

Убедитесь, что каждый класс завершается без ошибки.

# Этап 10. Проверка результата компиляции

После запуска программы откройте окно «Проект» (`Project`) (`Alt+1`).

Найдите папку с результатами компиляции (`out`), если она отображается в структуре вашего проекта.

Исходные Java-файлы имеют расширение:

```text
.java
```

После компиляции Java создаёт файлы байт-кода:

```text
.class
```

Для каждого созданного класса должен существовать соответствующий скомпилированный класс.

Этот этап нужен для понимания связи:

```text
исходный код (.java)
        ↓
компиляция
        ↓
байт-код (.class)
        ↓
JVM
```

# Требования к расположению инструкций

В каждом Java-файле соблюдайте порядок:

```text
package
import
public class
```

если конкретному файлу требуется `import`.

Инструкция объявления пакета (`package`) должна находиться до инструкций импорта (`import`).

Инструкции `import` должны находиться до объявления класса.

# Требования к используемому синтаксису

В проекте должны присутствовать:

* папка исходников (`src`);
* три именованных пакета (`packages`);
* инструкция объявления пакета (`package`);
* инструкция импорта (`import`);
* публичные классы (`public class`);
* главный метод (`main`) в каждом классе;
* стандартный поток ввода (`System.in`);
* класс `Scanner`;
* простой способ обращения к классу (`Scanner`);
* полное имя класса (`java.util.Scanner`);
* явно импортированный класс (`java.util.Date`);
* полное имя конфликтующего класса (`java.sql.Date`);
* создание объектов с помощью `new`;
* вызов `System.currentTimeMillis()`;
* вывод через `System.out.println()`.

# Что именно должно быть продемонстрировано

## Обычный импорт

В `Main.java`:

```text
java.util.Scanner
```

подключается через `import`, после чего в коде используется короткое имя:

```text
Scanner
```

## Полное имя класса

В `ScannerDemo.java`:

```text
java.util.Scanner
```

используется непосредственно в коде без отдельного импорта этого класса.

## Конфликт одинаковых имён

В `DateDemo.java`:

```text
java.util.Date
```

подключается через `import` и используется как:

```text
Date
```

а второй класс:

```text
java.sql.Date
```

используется по полному имени.

## Пакеты

Каждый класс располагается в каталоге, соответствующем его инструкции `package`.

## Файлы и классы

Каждый публичный класс находится в отдельном одноимённом `.java`-файле.

# Критерии выполнения

Задание выполнено правильно, если:

1. проект создаётся и успешно компилируется;
2. все исходные Java-файлы находятся внутри `src`;
3. создано три требуемых пакета;
4. физическое расположение каждого файла соответствует его инструкции `package`;
5. `Main.java` содержит публичный класс `Main`;
6. `ScannerDemo.java` содержит публичный класс `ScannerDemo`;
7. `DateDemo.java` содержит публичный класс `DateDemo`;
8. в `Main` класс `Scanner` подключён через обычный `import`;
9. после импорта в `Main` используется простое имя `Scanner`;
10. в `ScannerDemo` используется полное имя `java.util.Scanner`;
11. `ScannerDemo` работает без отдельного импорта класса `Scanner`;
12. в `DateDemo` явно импортирован `java.util.Date`;
13. импортированный `java.util.Date` используется через простое имя `Date`;
14. `java.sql.Date` используется через полное имя класса;
15. два разных класса `Date` однозначно различаются компилятором;
16. каждый из трёх классов можно запустить отдельно;
17. ввод через `Scanner` корректно считывается и выводится;
18. `DateDemo` выводит оба объекта даты;
19. после временного переименования через `Shift+F6` имя класса и файла изменяются согласованно;
20. после перемещения через `F6` IntelliJ IDEA корректно
    обновляет расположение класса и объявление `package`;
21. после завершения проверки класс `ScannerDemo` возвращён в исходный пакет;
22. финальная структура проекта полностью совпадает с указанной в задании.
