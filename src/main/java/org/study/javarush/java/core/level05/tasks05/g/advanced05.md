Задание 05. Инспектор Java-окружения (Java Environment Inspector)

Создайте три самостоятельно запускаемых класса. Задание показывает, как Java связывает файлы
с пакетами и различает простые и полные имена классов, в том числе два разных класса `Date`.

## 1. Этап 1. Создание проекта

Можно создать отдельный проект или выполнить задание внутри этого репозитория.
Выберите один вариант и используйте его пакеты во всех следующих этапах.

### Отдельный проект

Создайте проект «инспектор Java-окружения» (`JavaEnvironmentInspector`) с папкой исходников `src`.
Внутри неё создайте три пакета:

| Назначение | Пакет |
|---|---|
| Приложение | `org.study.environment.app` |
| Ввод данных | `org.study.environment.input` |
| Работа с датами | `org.study.environment.date` |

### Внутри этого репозитория

Используйте существующую папку исходников `src/main/java`. Файлы задания разместите в каталоге:

`src/main/java/org/study/javarush/java/core/level05/tasks05/g/environment`

Для этого варианта нужны следующие полные имена пакетов:

| Класс | Пакет |
|---|---|
| `Main` | `org.study.javarush.java.core.level05.tasks05.g.environment.app` |
| `ScannerDemo` | `org.study.javarush.java.core.level05.tasks05.g.environment.input` |
| `DateDemo` | `org.study.javarush.java.core.level05.tasks05.g.environment.date` |

### Работа с пакетами в IntelliJ IDEA

Откройте окно «Проект» (Project) через `Alt+1`.
Для создания пакета используйте **Создать (`Alt+Insert`) → Пакет (Package)**.

В каждом файле сначала разместите `package` с выбранным полным именем пакета,
затем необходимые `import`, затем объявление `public class`.
Каждый публичный класс храните в отдельном одноимённом файле с учётом регистра.

В каждом из трёх классов создайте главный метод программы (`main`):

```
public static void main(String[] args)
```

Параметр «аргументы командной строки» (`args`) типа `String[]` здесь не используется.
Все описанные действия с вводом, объектами и выводом выполняйте внутри соответствующего `main`.
Объекты создавайте оператором `new`, строки выводите через `System.out.println()`.
Значения подставляйте конкатенацией (`+`); пробелы вывода записывайте внутри строковых литералов.

## 2. Этап 2. Главный класс приложения (`Main`)

В пакете приложения создайте файл `Main.java` с публичным классом «главный» (`Main`).
Укажите его пакет из выбранного варианта этапа 1.

Явно импортируйте `java.util.Scanner`. После импорта обращайтесь к классу «сканер» (`Scanner`)
по простому имени (simple class name) `Scanner`, без префикса `java.util`.

1. Создайте объект «консоль» (`console`) типа `Scanner`, связанный со стандартным потоком
   ввода (`System.in`).
2. Методом «считать строку» (`nextLine()`) получите «ввод приложения» (`applicationInput`)
   типа «строка» (`String`).
3. Выведите подпись `Application input:`, один пробел и значение `applicationInput`.

Тестовый ввод:

```text
Java project
```

Ожидаемый вывод:

```text
Application input: Java project
```

## 3. Этап 3. Использование полного имени класса (`ScannerDemo`)

В пакете ввода данных создайте файл `ScannerDemo.java` с публичным классом
«демонстрация сканера» (`ScannerDemo`). Укажите его пакет из этапа 1.

В этом файле **не добавляйте** `import java.util.Scanner;`.
При объявлении и создании объекта используйте полное имя класса (fully qualified class name)
`java.util.Scanner`.

1. Создайте «консоль» (`console`) типа `java.util.Scanner`, связанную с `System.in`.
2. Методом `nextLine()` получите «ввод через полное имя» (`fullyQualifiedScannerInput`)
   типа `String`.
3. Выведите подпись `Fully qualified Scanner input:`, один пробел
   и значение `fullyQualifiedScannerInput`.

Тестовый ввод:

```text
java.util.Scanner
```

Ожидаемый вывод:

```text
Fully qualified Scanner input: java.util.Scanner
```

Оба класса используют один и тот же `Scanner`: в `Main` полное имя задано импортом,
а в `ScannerDemo` — непосредственно при объявлении и создании объекта.

## 4. Этап 4. Классы с одинаковым простым именем (`DateDemo`)

В пакете работы с датами создайте файл `DateDemo.java` с публичным классом
«демонстрация дат» (`DateDemo`). Укажите его пакет из этапа 1.

Классы `java.util.Date` и `java.sql.Date` имеют одинаковое простое имя `Date`.
Явно импортируйте только `java.util.Date`, чтобы короткое имя однозначно обозначало этот класс.

В `main` создайте:

* «обычная дата» (`javaUtilDate`) типа `Date` — новый объект `Date` без аргументов;
* «SQL-дата» (`javaSqlDate`) типа `java.sql.Date` — новый объект `java.sql.Date`,
  которому передаётся текущее время из `System.currentTimeMillis()`.

Для SQL-даты и в типе переменной, и при создании объекта используйте полное имя `java.sql.Date`.

## 5. Этап 5. Вывод информации о датах

В `DateDemo` выведите объекты в указанном порядке и формате:

```text
java.util.Date: [значение javaUtilDate]
java.sql.Date:  [значение javaSqlDate]
```

Даты и время зависят от момента запуска; конкретные значения не фиксируйте.
Первая строка должна выводить `javaUtilDate`, вторая — `javaSqlDate`.

## 6. Этап 6. Проверка структуры пакетов

Для отдельного проекта итоговая структура должна быть такой:

```text
JavaEnvironmentInspector/
└── src/
    └── org/
        └── study/
            └── environment/
                ├── app/
                │   └── Main.java
                ├── input/
                │   └── ScannerDemo.java
                └── date/
                    └── DateDemo.java
```

В варианте этого репозитория три тех же подкаталога `app`, `input`, `date`
располагаются внутри каталога `environment`, указанного на этапе 1.
Путь каждого файла относительно папки исходников должен соответствовать его `package`.

## 7. Этап 7. Проверка соответствия файла и публичного класса

Проверьте точное совпадение имён с учётом регистра:

```text
Main.java        ↔ public class Main
ScannerDemo.java ↔ public class ScannerDemo
DateDemo.java    ↔ public class DateDemo
```

## 8. Этап 8. Практика рефакторинга в IntelliJ IDEA

После успешной компиляции и запуска выполните обе временные проверки.

### Переименование

Выберите `ScannerDemo` в пакете ввода данных и выполните **Переименовать (`Shift+F6`)**.
Временно задайте имя «демонстрация полного имени сканера» (`FullNameScannerDemo`).

Проверьте согласованное изменение имени класса и файла на `FullNameScannerDemo.java`.
Повторным `Shift+F6` верните имя `ScannerDemo` и файл `ScannerDemo.java`.

### Перемещение между пакетами

Выберите `ScannerDemo.java` и выполните **Переместить (`F6`)** в пакет приложения:
`org.study.environment.app` для отдельного проекта или соответствующий пакет `Main`
из таблицы этапа 1 для этого репозитория.

Проверьте перемещение файла и обновление `package`. Повторным `F6` верните класс
в исходный пакет ввода данных: `org.study.environment.input` либо пакет `ScannerDemo`
из таблицы этапа 1. Финальная структура должна совпасть с этапом 6.

## 9. Этап 9. Запуск каждого класса

По очереди запустите `Main`, `ScannerDemo` и `DateDemo`, каждый через собственный `main`.
Проверьте тестовые ввод и вывод этапов 2–3 и две строки дат из этапа 5.
Каждый класс должен завершиться без ошибки.

Для повторного запуска текущей конфигурации используйте **Запустить (`Shift+F10`)**.

## 10. Этап 10. Проверка результата компиляции

Откройте окно «Проект» (Project) через `Alt+1` и найдите результаты компиляции:
каталог `out`, если используется компилятор IDEA, или `build/classes/java/main`
при сборке этого проекта через Gradle.

Для исходников `Main.java`, `ScannerDemo.java` и `DateDemo.java` найдите соответствующие
`Main.class`, `ScannerDemo.class` и `DateDemo.class` в подкаталогах их пакетов.
Это файлы байт-кода, которые исполняет JVM:

```text
исходный код (.java)
        ↓
компиляция
        ↓
байт-код (.class)
        ↓
JVM
```
