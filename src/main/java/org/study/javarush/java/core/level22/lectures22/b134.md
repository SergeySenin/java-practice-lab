`record`: синтаксис, преимущества

## 1. Проблема «классов-DTO»: зачем нам record-классы?

Давайте честно: сколько раз вы писали вот такой класс?

```
// Point.java
import java.util.Objects;

public class Point {
    private final int x;
    private final int y;

    public Point(int x, int y) {
        this.x = x;
        this.y = y;
    }

    public int getX() {
        return x;
    }

    public int getY() {
        return y;
    }

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (o == null || getClass() != o.getClass()) return false;
        Point point = (Point) o;
        return x == point.x && y == point.y;
    }

    @Override
    public int hashCode() {
        return Objects.hash(x, y);
    }

    @Override
    public String toString() {
        return "Point{" + "x=" + x + ", y=" + y + '}';
    }
}
```

Вроде бы ничего сложного, но посчитайте строки! А теперь представьте, что у вас 10 таких
классов и в каждом по 5–6 полей. Даже IDE устаёт генерировать этот шаблонный код.
А если вы решите добавить новое поле — придётся править конструктор, геттеры,
`equals()`, `hashCode()`, `toString()`... Скука, рутина и источник ошибок.

Такие классы часто используют как DTO (Data Transfer Object) или Value Object.
DTO служат для передачи данных, а Value Object представляют значения и обычно
сравниваются по содержимому. Но из-за шаблонного кода поддерживать их тяжело.

Если вам кажется, что это не проблема, просто подождите, когда вам придётся менять
50 таких классов сразу. Тогда вы вспомните про record-классы с особой теплотой!

## 2. Введение в `record`: синтаксис и магия Java 16+

С Java 16 всё изменилось. Появился новый вид классов — `record`.
Они специально созданы для случаев, когда нужно хранить набор данных.
Синтаксис — почти как у кортежа в других языках.

### Как объявить `record`?

```
public record Point(int x, int y) { }
```

И... всё! Вы только что создали класс с двумя компонентами, конструктором, методами
доступа, `equals()`, `hashCode()` и `toString()`. Без лишней писанины.

### Что делает Java «под капотом»?

* Компоненты `x` и `y` становятся полями `private final`.
* Методы доступа создаются автоматически: `int x()` и `int y()`.
* Канонический конструктор: `public Point(int x, int y)`.
* `equals()` и `hashCode()` учитывают значения всех компонентов.
* `toString()` возвращает строку вида `Point[x=1, y=2]`.

Можно сказать, что `record` — это «DTO на стероидах»: меньше кода, больше гарантий,
меньше багов.

### Неизменяемость (immutability)

Все поля компонентов record-класса автоматически `final`. После создания объекта
нельзя присвоить им новые значения — это гарантирует компилятор.

Однако **неизменяемость поверхностная**: если компонент содержит ссылку на изменяемый
объект (например, список), содержимое этого объекта можно изменить.
Поэтому безопасность в многопоточном коде зависит и от типов компонентов.

Если вы попытаетесь написать сеттер, изменяющий компонент, или сделать поле компонента
не `final`, компилятор вас остановит. Такая забота о вашем спокойствии встречается нечасто!

## 3. Пример использования record-класса

Обычный класс (много кода):

```
// Client.java
public class Client {
    private final String name;
    private final int id;

    public Client(String name, int id) {
        this.name = name;
        this.id = id;
    }

    public String getName() { return name; }
    public int getId() { return id; }

    // equals, hashCode, toString ...
}
```

Record-класс (одна строка!):

```
// Client.java
public record Client(String name, int id) { }
```

Это альтернативные объявления `Client`: используйте один из вариантов.

Использование:

```
// Main.java
public class Main {
    public static void main(String[] args) {
        Client client = new Client("Иван", 123);
        System.out.println(client.name());  // Иван
        System.out.println(client.id());    // 123
        System.out.println(client);         // Client[name=Иван, id=123]
    }
}
```

Обратите внимание:

* Методы доступа к компонентам называются так же, как компоненты: `name()`, `id()`.
* Нет автоматически созданных `setName()` или `setId()` — изменить компоненты нельзя.

## 4. Преимущества record-классов: меньше кода, меньше ошибок

### Меньше кода — больше счастья

Зачем писать 40 строк, если можно обойтись одной? Record-классы экономят время и нервы,
особенно в больших проектах, где много DTO и value-объектов.

### Неизменяемость «по контракту»

* Record-классы всегда `final`, а их компоненты нельзя переназначить после создания.
* Состояние компонентов нельзя случайно заменить или «подделать» через присваивание.
* Меньше «странных» багов из-за изменения полей объекта в неожиданном месте.
* Их можно безопасно использовать в многопоточных программах, если компоненты
  сами неизменяемы и не раскрывают изменяемое состояние.

### Автоматическая генерация `equals()`, `hashCode()`, `toString()`

Не нужно вручную писать методы сравнения, вычисления хэша и красивого вывода.
Всё делается автоматически с учётом компонентов.

```
Client c1 = new Client("Анна", 42);
Client c2 = new Client("Анна", 42);

System.out.println(c1.equals(c2));                   // true
System.out.println(c1.hashCode() == c2.hashCode());  // true
System.out.println(c1);                              // Client[name=Анна, id=42]
```

### Идеально для коллекций и ключей

Record-объекты можно использовать как ключи в `HashMap`, элементы в `HashSet`
и т. д. — сравнение и хэширование компонентов уже реализованы. При этом компоненты
не должны изменять данные, от которых зависят `equals()` и `hashCode()`.

```
import java.util.HashMap;
import java.util.Map;

Map<Client, String> clients = new HashMap<>();
clients.put(new Client("Анна", 42), "VIP");

System.out.println(clients.get(new Client("Анна", 42))); // VIP
```

### Явное описание данных

Синтаксис record-класса сразу показывает, какие данные хранятся и что его компоненты
нельзя переназначить. Это делает код понятнее для других разработчиков
(и для вас через полгода).

## 5. Таблица: сравнение обычного класса и record-класса

| Особенность                    | Обычный класс           | Record-класс                      |
|--------------------------------|-------------------------|-----------------------------------|
| **Синтаксис**                  | Много кода              | Одна строка                       |
| **Неизменяемость**             | Нужно обеспечивать явно | `final`-компоненты                |
| **Автогенерация методов**      | Нет                     | `equals`, `hashCode`, `toString`  |
| **Можно добавить поля**        | Да                      | Только компоненты и `static`-поля |
| **Наследование**               | Может быть суперклассом | Всегда `final`                    |
| **Использование в коллекциях** | Нужны корректные методы | Работает «из коробки»             |

Примечание: запись `record` гарантирует поверхностную неизменяемость, но не глубокую.
Обычные классы также можно сделать неизменяемыми при правильном проектировании.

## 6. Развиваем учебное приложение: пример с record-классом

Допустим, в вашем учебном банковском приложении нужно хранить операции по счёту:
дату, сумму, тип операции (например, «пополнение» или «снятие»).

До Java 16:

```
// Transaction.java
import java.time.LocalDate;

public class Transaction {
    private final LocalDate date;
    private final double amount;
    private final String type;

    public Transaction(LocalDate date, double amount, String type) {
        this.date = date;
        this.amount = amount;
        this.type = type;
    }

    public LocalDate getDate() { return date; }
    public double getAmount() { return amount; }
    public String getType() { return type; }

    // equals, hashCode, toString ...
}
```

С Java 16 и `record`:

```
// Transaction.java
import java.time.LocalDate;

public record Transaction(LocalDate date, double amount, String type) { }
```

Это альтернативные версии `Transaction`, а не два определения для одного проекта.

Использование:

```
import java.time.LocalDate;

Transaction t = new Transaction(LocalDate.now(), 100.0, "deposit");
System.out.println(t);           // Дата в выводе зависит от дня запуска
System.out.println(t.amount());  // 100.0
```

В результате первая строка будет иметь вид
`Transaction[date=2024-06-01, amount=100.0, type=deposit]`, если запуск происходит
1 июня 2024 года. В другие дни дата будет иной.

Примечание: `double` здесь используется для простоты учебного примера.
Для реальных денежных сумм обычно применяют `BigDecimal`.

## 7. Визуализация: что генерирует `record`

Посмотрим на «развёрнутый» record-класс (примерно то, что создаёт компилятор):

```
// Упрощённая схема, не компилируемый Java-код.
public final class Point extends java.lang.Record {
    private final int x;
    private final int y;

    public Point(int x, int y) {
        this.x = x;
        this.y = y;
    }

    public int x() { return x; }
    public int y() { return y; }

    @Override
    public boolean equals(Object o) { /* сравнение по компонентам */ }

    @Override
    public int hashCode() { /* вычисление по компонентам */ }

    @Override
    public String toString() { /* красивый вывод */ }
}
```

Важно: напрямую объявить в исходном Java-коде класс с `extends java.lang.Record`
нельзя. Этот фрагмент показывает устройство record-класса концептуально.

### Кратко: когда стоит использовать `record`

* Когда нужен объект с неизменяемым набором ссылок и значений компонентов.
* Когда нужны `equals()`, `hashCode()` и `toString()` без ручной писанины.
* Когда вы делаете DTO, Value Object, пары, тройки, цвет, точку, диапазон,
  ключ для коллекции и т. п.

## 8. Типичные ошибки при работе с record-классами

### Ошибка № 1. Попытка добавить сеттер или изменить поле после создания

Record-класс не позволяет изменять поля компонентов. Если вы попробуете добавить
метод `setX(int x)`, который присваивает новое значение полю `x`, компилятор сообщит
об ошибке. Само имя `setX` не запрещено, но такой метод не сможет изменить компонент.
То же самое — если попытаться изменить поле напрямую.

### Ошибка № 2. Попытка добавить нестатическое поле

В record-классе можно объявлять компоненты (поля, указанные в скобках после имени
`record`) и статические поля. Дополнительные нестатические поля объявлять нельзя —
компилятор не даст этого сделать.

### Ошибка № 3. Использование `record` для mutable-логики

Record-классы не предназначены для объектов, у которых нужно переназначать компоненты.
Если вам нужно менять их после создания — используйте обычный класс.
Помните: объект, на который ссылается компонент, при этом может оставаться изменяемым.

### Ошибка № 4. Забыли, что `record` всегда `final`

Record-класс нельзя наследовать: он не может быть суперклассом другого класса.
Попытка нарушить это ограничение приведёт к ошибке компиляции. Ключевой признак —
не пытаемся «расширять» `record`: он задуман как законченный тип данных.

### Ошибка № 5. Игнорирование автогенерируемых методов

Если вы переопределяете `equals()`, `hashCode()` или `toString()`, будьте осторожны —
не нарушайте их контракт, иначе коллекции и сравнения будут работать некорректно.
