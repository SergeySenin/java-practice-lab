Интерфейсы из стандартной библиотеки: `Comparable`, `Serializable` и др.

## 1. Интерфейс `Comparable<T>`

Вы когда-нибудь сортировали список чисел или строк? Конечно, да! А теперь представьте,
что у вас есть список своих собственных объектов — например, список студентов, товаров
или котиков. Как Java поймёт, в каком порядке их сортировать? Именно для этого и нужен
интерфейс `Comparable<T>`.

Этот интерфейс определяет «естественный порядок» объектов — то есть тот порядок,
который логичен для данного типа данных. Например, для чисел — по возрастанию,
для строк — лексикографический порядок, для студентов — по фамилии или возрасту
(на ваш выбор).

### Как устроен `Comparable`

Интерфейс очень простой: у него один абстрактный метод (упрощённое объявление):

```
public interface Comparable<T> {
    int compareTo(T o);
}
```

Метод `compareTo()` должен возвращать:

* Отрицательное число, если текущий объект «меньше» другого.
* `0`, если объекты равны с точки зрения установленного порядка.
* Положительное число, если текущий объект «больше» другого.

### Пример: сортируем студентов по возрасту

Давайте добавим класс `Student` и реализуем для него интерфейс `Comparable<Student>`:

```
// Student.java
public class Student implements Comparable<Student> {
    private String name;
    private int age;

    public Student(String name, int age) {
        this.name = name;
        this.age = age;
    }

    // Геттеры для примера
    public String getName() { return name; }
    public int getAge() { return age; }

    @Override
    public int compareTo(Student other) {
        // Сортируем по возрасту (по возрастанию)
        return Integer.compare(this.age, other.age);
    }

    @Override
    public String toString() {
        return name + " (" + age + ")";
    }
}
```

Теперь мы можем легко отсортировать массив или список студентов:

```
// Main.java
import java.util.*;

public class Main {
    public static void main(String[] args) {
        List<Student> students = new ArrayList<>();
        students.add(new Student("Вася", 20));
        students.add(new Student("Петя", 18));
        students.add(new Student("Маша", 22));

        Collections.sort(students); // Работает благодаря Comparable!

        System.out.println("Отсортированные студенты:");
        for (Student s : students) {
            System.out.println(s);
        }
    }
}
```

Результат:

```text
Отсортированные студенты:
Петя (18)
Вася (20)
Маша (22)
```

### Важный нюанс

Если вы реализуете `Comparable`, старайтесь, чтобы `compareTo()` работал согласованно
с `equals()`. Желательно, чтобы при `a.compareTo(b) == 0` выполнялось `a.equals(b)`.
Это не обязательное требование компилятора, но несогласованность может неожиданно
повлиять на поведение упорядоченных коллекций, например `TreeSet`.

В нашем примере `Student.compareTo()` сравнивает только возраст, а `equals()` не переопределён:
два разных студента одного возраста будут равны с точки зрения сортировки,
но не с точки зрения `equals()`. А у вас появится повод для философских рассуждений
о смысле жизни программиста.

## 2. Интерфейс `Serializable`

Сериализация — это преобразование состояния объекта в последовательность байтов
(например, для сохранения в файл или передачи по сети) с возможностью последующего
восстановления. Представьте, что вы хотите сохранить состояние своей игры или отправить
объект на сервер — один из возможных способов сделать это связан с сериализацией.

В Java для стандартной объектной сериализации есть маркерный интерфейс `Serializable`.
Маркерный — значит, он не содержит методов, а просто «помечает» класс как сериализуемый.

```
// Student.java
import java.io.Serializable;

public class Student implements Serializable {
    private String name;
    private int age;

    public Student(String name, int age) {
        this.name = name;
        this.age = age;
    }

    @Override
    public String toString() {
        return name + " (" + age + ")";
    }
}
```

Здесь показана отдельная версия класса `Student` для примера сериализации.

### Как сериализовать объект

Для сериализации и десериализации используют классы `ObjectOutputStream`
и `ObjectInputStream`. Пример — сохраняем объект в файл и читаем обратно:

```
// Main.java
import java.io.*;

public class Main {
    public static void main(String[] args) throws Exception {
        Student s = new Student("Катя", 19);

        // Сохраняем объект в файл
        try (ObjectOutputStream out = new ObjectOutputStream(new FileOutputStream("student.dat"))) {
            out.writeObject(s);
        }

        // Читаем объект из файла
        try (ObjectInputStream in = new ObjectInputStream(new FileInputStream("student.dat"))) {
            Student loaded = (Student) in.readObject();
            System.out.println("Загружено: " + loaded);
        }
    }
}
```

Примечание: при стандартной сериализации объекты, на которые ссылаются сериализуемые
поля, также должны быть сериализуемыми (или обрабатываться специальным образом).
Примитивные поля сериализуются непосредственно; поля `static` и `transient`
обычно не сохраняются. Иначе возможна ошибка `NotSerializableException`.

### Зачем нужен маркерный интерфейс

Интерфейс `Serializable` не требует реализовывать методы — он сообщает механизму
объектной сериализации Java, что объект допускается сериализовать. Если класс
не реализует `Serializable`, попытка записать его объект через `ObjectOutputStream`
приведёт к исключению `NotSerializableException`.

## 3. Другие важные интерфейсы стандартной библиотеки

### Интерфейс `Cloneable`

Ещё один маркерный интерфейс. Его задача — разрешить копирование объекта через
`Object.clone()`. Если объект не реализует `Cloneable`, вызов `super.clone()`
выбросит `CloneNotSupportedException`. Сам по себе `Cloneable` не делает метод
`clone()` публичным: метод из класса `Object` имеет доступ `protected`.

Однако клонирование в Java — тема с подвохом. Клонирование по умолчанию поверхностное
(*shallow copy*), и часто вместо этого лучше писать собственные методы копирования.

```
public class Student implements Cloneable {
    private String name;
    private int age;

    @Override
    public Object clone() throws CloneNotSupportedException {
        return super.clone();
    }
}
```

### Интерфейс `AutoCloseable`

Этот интерфейс содержит метод `close()`. Любой класс, реализующий его,
может использоваться в конструкции `try-with-resources` для автоматического
закрытия ресурсов (например, файлов и потоков):

```
// MyResource.java
public class MyResource implements AutoCloseable {
    @Override
    public void close() {
        System.out.println("Ресурс закрыт!");
    }
}
```

```
// Main.java
public class Main {
    public static void main(String[] args) {
        try (MyResource res = new MyResource()) {
            System.out.println("Работаем с ресурсом");
        }
        // Здесь res.close() вызовется автоматически
    }
}
```

### Интерфейс `Iterable<T>`

Этот интерфейс позволяет вашему объекту быть «перебираемым» в цикле `for-each`.
Он определяет абстрактный метод `iterator()`, который возвращает `Iterator<T>`.

Упрощённый шаблон (хранилище и возвращаемый итератор ещё нужно реализовать):

```
public class MyList implements Iterable<String> {
    // ... внутреннее хранилище

    @Override
    public java.util.Iterator<String> iterator() {
        // Возвращаем итератор для перебора элементов
        return ...;
    }
}
```

Стандартные коллекции, такие как `ArrayList` и `HashSet`, реализуют `Iterable`,
поэтому их можно перебирать в `for-each`.

### Интерфейс `Comparator<T>`

Этот интерфейс позволяет сравнивать объекты по разным правилам, не меняя их самих.
Например, сортировать студентов по имени, а не по возрасту.
В следующем примере используется версия `Student` из раздела 1 с методом `getName()`.

```
import java.util.Comparator;

Comparator<Student> byName = new Comparator<Student>() {
    @Override
    public int compare(Student a, Student b) {
        return a.getName().compareTo(b.getName());
    }
};
```

В современной Java это обычно делается через лямбда-выражение:

```
Comparator<Student> byName = (a, b) -> a.getName().compareTo(b.getName());
```

### `Observer`, `EventListener`

Эти интерфейсы связаны с паттернами «наблюдатель» и «слушатель событий» —
когда один объект реагирует на события, происходящие в другом.
Например, в Swing обработчики действий используют `ActionListener` с методом
`actionPerformed()`.

При этом `java.util.Observer` помечен как устаревший (*deprecated*) начиная с Java 9,
а `java.util.EventListener` — маркерный интерфейс, на основе которого определяются
более специализированные слушатели событий.

## 4. Практика: реализуем `Comparable` и сериализуем объект

### Пример 1. `Comparable` для собственного класса

Давайте напишем класс `Book`, который можно сортировать по году издания:

```
// Book.java
public class Book implements Comparable<Book> {
    private String title;
    private int year;

    public Book(String title, int year) {
        this.title = title;
        this.year = year;
    }

    @Override
    public int compareTo(Book other) {
        return Integer.compare(this.year, other.year);
    }

    @Override
    public String toString() {
        return title + " (" + year + ")";
    }
}
```

```
// Main.java
import java.util.*;

public class Main {
    public static void main(String[] args) {
        List<Book> books = Arrays.asList(
            new Book("Java для чайников", 2018),
            new Book("Война и мир", 1869),
            new Book("Гарри Поттер", 1997)
        );
        Collections.sort(books);
        System.out.println(books);
    }
}
```

Результат:

```text
[Война и мир (1869), Гарри Поттер (1997), Java для чайников (2018)]
```

### Пример 2. Сериализация объекта

Здесь используется другая, отдельная версия класса `Book`, реализующая `Serializable`.

```
// Book.java
import java.io.*;

public class Book implements Serializable {
    private String title;
    private int year;

    // ... конструктор, геттеры, toString

    public Book(String title, int year) {
        this.title = title;
        this.year = year;
    }

    @Override
    public String toString() {
        return title + " (" + year + ")";
    }
}
```

```
// Main.java
import java.io.*;

public class Main {
    public static void main(String[] args) throws Exception {
        Book book = new Book("Java для чайников", 2018);

        // Сохраняем объект в файл
        try (ObjectOutputStream out = new ObjectOutputStream(new FileOutputStream("book.dat"))) {
            out.writeObject(book);
        }

        // Читаем объект из файла
        try (ObjectInputStream in = new ObjectInputStream(new FileInputStream("book.dat"))) {
            Book loaded = (Book) in.readObject();
            System.out.println("Загружено: " + loaded);
        }
    }
}
```

## 5. Таблица: основные интерфейсы стандартной библиотеки

| Интерфейс                    | Назначение                          | Ключевые методы          |
|------------------------------|-------------------------------------|--------------------------|
| `Comparable<T>`              | Естественный порядок объектов       | `int compareTo(T o)`     |
| `Comparator<T>`              | Пользовательское сравнение объектов | `int compare(T a, T b)`  |
| `Serializable`               | Сериализация объектов               | — (маркерный)            |
| `Cloneable`                  | Клонирование объектов               | — (маркерный)            |
| `AutoCloseable`              | Автоматическое закрытие ресурсов    | `void close()`           |
| `Iterable<T>`                | Перебор элементов в коллекциях      | `Iterator<T> iterator()` |
| `Observer` / `EventListener` | Реакция на события                  | См. пояснение ниже       |

| Интерфейс                    | Пример использования             |
|------------------------------|----------------------------------|
| `Comparable<T>`              | Сортировка списков               |
| `Comparator<T>`              | Сортировка по разным правилам    |
| `Serializable`               | Сохранение/загрузка объектов     |
| `Cloneable`                  | Создание копий объектов          |
| `AutoCloseable`              | `try-with-resources`             |
| `Iterable<T>`                | Цикл `for-each`                  |
| `Observer` / `EventListener` | Обработка событий в UI, паттерны |

Для `Observer` предусмотрен метод `update()`, а `EventListener` не содержит методов.
Метод `actionPerformed()` объявлен в специализированном интерфейсе `ActionListener`.

## 6. Типичные ошибки при работе со стандартными интерфейсами

### Ошибка № 1. Не реализован интерфейс, но требуется функционал

Например, забыли реализовать `Serializable`, а пытаетесь сериализовать объект —
получите `NotSerializableException`. Аналогично с `Cloneable` и вызовом `super.clone()`.

### Ошибка № 2. Нарушение контракта `Comparable` и `equals`

Если `a.compareTo(b) == 0`, но `a.equals(b)` возвращает `false`, поведение
упорядоченных коллекций может удивить. Например, `TreeSet` сочтёт такие объекты
эквивалентными при добавлении и не сохранит их как два отдельных элемента.

### Ошибка № 3. Поверхностное копирование при клонировании

Метод `clone()` по умолчанию копирует только «верхний слой» объекта.
Если у вас есть поля-ссылки на другие объекты, они не копируются глубоко.
Это может привести к загадочным багам.

### Ошибка № 4. Несоблюдение `try-with-resources`

Если класс реализует `AutoCloseable`, но вы не используете его в `try-with-resources`
и не закрываете ресурс вручную, вы рискуете забыть вызвать `close()` — и получить
утечку ресурса или блокировку файла.

### Ошибка № 5. Неправильная реализация `compareTo()` или `compare()`

Если возвращать только `0` или `1`, а не отрицательное, нулевое или положительное
число в зависимости от порядка объектов, можно нарушить контракт сравнения.
Из-за этого сортировка будет работать некорректно.
