Ошибки при объявлении классов и объектов

## 1. Ошибки при объявлении класса

### Отсутствие модификаторов доступа (`package-private` по умолчанию)

В Java, если не указывать модификатор доступа у верхнеуровневого класса, он становится
доступен **только внутри своего пакета**. Это называется `package-private`, или
«доступ по умолчанию». Само по себе отсутствие `public` не является ошибкой.
Например:

```
// Book.java
class Book {
    String title;
}
```

Такой класс нельзя использовать из другого пакета. Если вы хотите, чтобы класс был
доступен из других пакетов, объявите его `public`:

```
// Book.java
public class Book {
    String title;
}
```

Почему это важно?

Если забыть поставить `public` там, где он нужен, вы потом будете долго удивляться,
почему какой-нибудь `Library` из другого пакета не видит ваш класс. Но и делать
все классы публичными без необходимости не стоит.

### Несоответствие имени класса и имени файла

В Java имя файла с **публичным верхнеуровневым классом** должно совпадать с именем
этого класса (с учётом регистра!). Например:

```
// Book.java
public class Book {
    // ...
}
```

Если вы назовёте файл `book.java` (с маленькой буквы) или `BooK.java`, компилятор
выдаст ошибку. Это одна из причин, почему IDE так любит ругаться на вас,
если вы переименовали класс, но забыли переименовать файл.

### Ошибки синтаксиса: фигурные скобки и расположение методов

Java — строгий язык. Если забыть фигурную скобку или случайно объявить метод
внутри другого метода (так делать нельзя!), компилятор немедленно сообщит об ошибке.

Пример неправильного объявления:

```
// User.java — намеренная ошибка
public class User
    String name; // Ой! Пропущена открывающая фигурная скобка класса

    public void printName() {
        System.out.println(name);
    }
}
```

Правильный вариант:

```
// User.java
public class User {
    String name;

    public void printName() {
        System.out.println(name);
    }
}
```

Запомните:

* Поля и методы класса объявляются внутри его фигурных скобок.
* Объявлять один метод внутри другого в Java нельзя (хотя в некоторых языках можно).

## 2. Ошибки при создании объектов

### Неинициализированная переменная и `NullPointerException`

Одна из частых ошибок — попытка обратиться к объекту, который ещё не создан.
Но **неинициализированная локальная переменная** и **ссылка со значением `null`**
приводят к разным ошибкам.

Пример неинициализированной локальной переменной:

```
User user;
System.out.println(user.name); // Ошибка компиляции: переменная user не инициализирована
```

Локальная переменная `user` объявлена, но ей не присвоено значение. Компилятор
не разрешит прочитать такую переменную.

Пример с `NullPointerException`:

```
User user = null;
System.out.println(user.name); // NullPointerException
```

Здесь `user` инициализирована значением `null`, но объекта по этой ссылке нет.
При обращении к его полю или методу возникает `NullPointerException` (NPE).

Правильный подход:

```
User user = new User();
System.out.println(user.name); // Выведет null: поле name не инициализировано явно
```

У полей объекта ссылочного типа действительно есть значение по умолчанию `null`.
Создание объекта устраняет NPE при обращении к `user.name`, но само поле `name`
при этом может оставаться равным `null`.

### Ошибки вызова конструктора

Если у класса есть только конструктор с параметрами, попытка создать объект
без аргументов приведёт к ошибке компиляции.

```
// Book.java
public class Book {
    String title;

    public Book(String title) {
        this.title = title;
    }
}
```

```
Book book = new Book(); // Ошибка! Нет конструктора без параметров
```

**Решение**: добавить конструктор без параметров либо передавать нужные значения:

```
Book book = new Book("Java для чайников");
```

### Многократное создание объектов вместо повторного использования

Иногда новички создают новый объект каждый раз, когда нужно обратиться к нему,
вместо того чтобы использовать уже созданный.

```
Book book = new Book("Java для чайников");
System.out.println(book.title);

book = new Book("Java для чайников"); // Зачем? Уже был такой объект!
System.out.println(book.title);
```

Это не ошибка компиляции. При повторном присваивании переменная `book` перестаёт
ссылаться на первый объект. Если он больше нигде не используется, сборщик мусора
сможет освободить занимаемую им память. Но создание нового объекта оправданно,
если действительно нужен отдельный экземпляр.

## 3. Best practices: как не наступать на грабли

### Осознанно выбирайте модификаторы доступа

Не ленитесь указывать `public`, `private` или `protected` там, где они нужны:
это не только про безопасность, но и про читаемость кода. Для верхнеуровневого
класса допустимы `public` и доступ по умолчанию; `private` и `protected`
применимы к членам класса и некоторым вложенным типам.

Пример:

```
// User.java
public class User {
    private String name;
    // ...
}
```

### Следите за именованием классов

* Имя класса                   — с большой буквы, в стиле `UpperCamelCase`:
  `Book`, `LibraryUser`, `BookManager`.
* Имя файла с `public`-классом — строго как имя этого класса.

### Используйте конструкторы для инициализации обязательных полей

Если у объекта есть поля, которые **обязательно** должны быть заполнены при создании,
добавьте конструктор с параметрами. Это защитит от ошибок на этапе использования.

Пример:

```
// User.java
public class User {
    private String name;

    public User(String name) {
        this.name = name;
    }
}
```

Теперь нельзя создать `User` без аргумента — вызов `new User()` не скомпилируется.
Однако `new User(null)` допустим: если имя не может быть `null`, нужна проверка
в конструкторе.

## 4. Применяем знания: строим мини-приложение «Библиотека»

Давайте продолжим развивать наше учебное приложение. Пусть у нас есть
класс `Book` и класс `Library`, который управляет книгами.

### Пример правильного объявления класса

```
// Book.java
public class Book {
    private String title;
    private String author;

    // Конструктор с параметрами
    public Book(String title, String author) {
        this.title = title;
        this.author = author;
    }

    // Геттеры
    public String getTitle() {
        return title;
    }

    public String getAuthor() {
        return author;
    }
}
```

### Пример правильного создания объекта

```
Book book = new Book("Java для чайников", "Джон Доу");
System.out.println(book.getTitle() + " - " + book.getAuthor());
```

### Пример класса-менеджера

```
// Library.java
import java.util.ArrayList;

public class Library {
    private ArrayList<Book> books = new ArrayList<>();

    public void addBook(Book book) {
        books.add(book);
    }

    public void printAllBooks() {
        for (Book book : books) {
            System.out.println(book.getTitle() + " - " + book.getAuthor());
        }
    }
}
```

### Использование в `main()`

```
// Main.java
public class Main {
    public static void main(String[] args) {
        Library library = new Library();
        Book book1 = new Book("Java для чайников", "Джон Доу");
        Book book2 = new Book("ООП на пальцах", "Иван Иванов");

        library.addBook(book1);
        library.addBook(book2);

        library.printAllBooks();
    }
}
```

## 5. Иллюстрации и схемы

### Схема: где объявлять что?

```text
+-----------------------------+
|         Book.java           |
|-----------------------------|
| public class Book {         |
|     private String title;   |  <--- поля (внутри класса)
|     ...                     |
|     public Book(...) {...}  |  <--- конструктор (внутри класса)
|     public String getTitle()|  <--- методы (внутри класса)
| }                           |
+-----------------------------+

+-----------------------------+
|        Main.java            |
|-----------------------------|
| public class Main {         |
|     public static void main |
|         // Создание объектов|
|         Book book = new Book|
| }                           |
+-----------------------------+
```

## 6. Разбор типичных ошибок

### Ошибка № 1. Несоответствие имени класса и файла

```
// Libraryuser.java — намеренная ошибка
public class LibraryUser { // Имя класса с большой U, файл с маленькой!
    // ...
}
```

Сообщение компилятора:

```text
class LibraryUser is public, should be declared in a file named LibraryUser.java
```

### Ошибка № 2. Обращение к методу по ссылке со значением `null`

```
Book book = null;
System.out.println(book.getTitle()); // NullPointerException!
```

Если вместо `Book book = null;` написать только `Book book;`, при следующем обращении
к переменной возникнет ошибка **компиляции**, а не `NullPointerException`.

### Ошибка № 3. Забыли фигурные скобки

```
// Book.java — намеренная ошибка
public class Book
    private String title; // Поля обычно делают private для инкапсуляции
    // ...
}
```

Одно из сообщений `javac`:

```text
'{' expected
```

### Ошибка № 4. Объявление метода внутри метода

```
// User.java — намеренная ошибка
public class User {
    public void printName() {
        void sayHello() {
            System.out.println("Hello!"); // Нельзя объявлять метод внутри метода!
        }
    }
}
```

Одно из сообщений `javac`:

```text
illegal start of expression
```
