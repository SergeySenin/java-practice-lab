Задание 12. Система управления контентом маркетплейса (Marketplace Content Manager)

Программа помогает сотруднику контент-отдела подготовить каталог товаров маркетплейса:
обновить список товаров и остатки, подсчитать поисковые запросы покупателей,
собрать задачи по проверке карточек и сохранить результат в текстовый и бинарные файлы.
Отдельная программа загружает демонстрационные изображения и проверяет ответы внешнего API.

Задание закрепляет динамические списки (`ArrayList`), словари (`HashMap`),
чтение и запись файлов, бинарные данные, сетевые потоки и HTTP-запросы.
Используйте Java 17 или Java 21. Сторонние библиотеки не требуются.

## 1. Структура проекта

Создайте два файла в одном пакете задания:

* `Solution.java`          — публичный класс «решение» (`Solution`):
  каталог, остатки, поисковая статистика, локальные файлы и демонстрационная строка JSON;
* `RemoteContentDemo.java` — публичный класс
  «демонстрация загрузки удалённого контента» (`RemoteContentDemo`): изображения и HTTP.

В обоих классах создайте главный метод программы (`main`):

```
public static void main(String[] args)
```

Параметр «аргументы командной строки» (`args`) типа `String[]` здесь не используется.
Все предусмотренные вспомогательные методы объявляйте `public static`.
Имена, типы и порядок параметров сохраняйте по соответствующим этапам.
Дополнительные вспомогательные методы не требуются.

В `Solution` подключите `java.util.ArrayList`, `java.util.HashMap`, `java.util.Map`,
`java.util.Scanner`, `java.util.Arrays`, `java.nio.file.Path`, `java.nio.file.Files`,
`java.nio.charset.StandardCharsets` и `java.io.IOException`.
Для `RemoteContentDemo` используйте классы из `java.net`, `java.net.http`, `java.io`
и `java.nio.file`, названные в сетевых этапах.

Сначала реализуйте `Solution`: этапы 1–13, затем независимый JSON-пример этапа 20.
После этого отдельно реализуйте и запустите `RemoteContentDemo` по этапам 14–19.
Работа сети не должна влиять на локальный каталог.
В `main` организуйте вызовы методов и выполните действия, прямо отнесённые к нему.
Алгоритмы вывода списка, подсчёта остатка и формирования текста разместите в заданных методах.

Схемы со знаком `→` показывают контрольные значения, а не обязательные строки консоли.
Блоки с подписью «Вывод» задают буквальное оформление сообщений.
В шаблонах сообщений заменяйте обозначения в квадратных скобках фактическими значениями;
сами скобки и поясняющий текст внутри них не печатайте.
Параметры обработчиков `catch` называйте «исключение» (`exception`).

## 2. Этап 1. Создание динамического списка товаров

В `Solution.main` создайте «названия товаров» (`productNames`) типа `ArrayList<String>`
через `new`. Методом `add()` последовательно добавьте:

```text
Mechanical Keyboard
Wireless Mouse
USB Hub
```

Выведите размер списка через `size()`.

Вывод:

```text
Initial product count: 3
```

У обычного массива используется `length`, а у `ArrayList` — `size()`.

## 3. Этап 2. Добавление и изменение товаров

В `Solution.main` выполните операции в указанном порядке:

1. Методом `add()` добавьте `"Webcam"` в конец списка.
2. Методом `get()` получите второй элемент, с индексом `1`, и сохраните
   в «исходное название мыши» (`originalMouseName`) типа `String`.
3. Методом `set()` замените элемент с индексом `1` на `"Gaming Mouse"`.
4. Методом `remove()` удалите `"USB Hub"` по его текущему индексу `2`.
5. Методом `contains()` проверьте наличие `"Gaming Mouse"` и сохраните результат
   в «игровая мышь присутствует» (`hasGamingMouse`) типа `boolean`.
6. Методом `contains()` проверьте наличие `"USB Hub"` и сохраните результат
   в «USB-концентратор присутствует» (`hasUsbHub`) типа `boolean`.

Итоговый список:

```text
[Mechanical Keyboard, Gaming Mouse, Webcam]
```

Контрольные значения:

```text
originalMouseName   → Wireless Mouse
hasGamingMouse      → true
hasUsbHub           → false
productNames.size() → 3
```

После удаления следующие элементы автоматически смещаются.
Самостоятельно переставлять их не требуется.

## 4. Этап 3. Обход `ArrayList`

Создайте метод «вывести список товаров» (`printProductList`):

```
public static void printProductList(ArrayList<String> productNames)
```

Параметр «названия товаров» (`productNames`) — список для вывода.
Метод ничего не возвращает. Используйте индексный `for`, методы `size()` и `get()`
и переменную «индекс товара» (`productIndex`) типа `int`.

Вызовите метод из `main` для итогового списка.

Вывод:

```text
0: Mechanical Keyboard
1: Gaming Mouse
2: Webcam
```

Затем в `main` отдельным циклом `for-each` выведите только названия товаров,
по одному на строку. Переменную цикла «название товара» (`productName`) объявите как `String`.
Это имя используйте и в остальных циклах по названиям товаров.

Индексный `for` позволяет получить позицию элемента;
`for-each` удобен, когда требуется только значение.
Не используйте `productNames[index]`: элемент списка получают через `get()`.

## 5. Этап 4. Словарь остатков товаров

В `Solution.main` создайте «остатки товаров по названию» (`stockByProductName`)
типа `HashMap<String, Integer>` через `new`.
Ключ — точное название товара (`String`), значение — количество единиц (`Integer`).
Через `put()` добавьте:

| Товар                 | Остаток |
|-----------------------|--------:|
| `Mechanical Keyboard` |      12 |
| `Gaming Mouse`        |       7 |
| `Webcam`              |       5 |
| `USB Hub`             |       2 |

Затем выполните:

1. Повторный `put()` с ключом `"Gaming Mouse"` и значением `8`.
2. `remove("USB Hub")`.
3. `containsKey("Gaming Mouse")`.
4. `containsKey("USB Hub")`.
5. `get("USB Hub")`.

Результаты последних трёх операций сохраните соответственно в:

* «мышь есть в словаре» (`hasMouseStock`) типа `boolean`;
* «USB-концентратор есть в словаре» (`hasUsbHubStock`) типа `boolean`;
* «остаток удалённого товара» (`removedProductStock`) типа `Integer`.

Для вывода остатка мыши используйте `get("Gaming Mouse")`.

Вывод:

```text
Gaming Mouse stock:  8
hasMouseStock:       true
hasUsbHubStock:      false
removedProductStock: null
```

Повторный `put()` с существующим ключом заменяет значение, а не создаёт вторую запись.
`get()` для отсутствующего ключа возвращает `null`.

## 6. Этап 5. Подсчёт общего количества товаров на складе

Создайте метод «рассчитать общий остаток» (`calculateTotalStock`):

```
public static int calculateTotalStock(
        ArrayList<String> productNames,
        HashMap<String, Integer> stockByProductName)
```

Параметры — «названия товаров» (`productNames`)
и «остатки товаров по названию» (`stockByProductName`).
Метод возвращает сумму и сам ничего не печатает.

Внутри метода:

1. Создайте «общий остаток» (`totalStock`) типа `int` со значением `0`.
2. Переберите `productNames` через `for-each` с переменной `productName` типа `String`.
3. Для каждого названия получите через `get()` «остаток товара» (`stockCount`)
   типа `Integer` и прибавьте его к `totalStock`.
4. Верните `totalStock` через `return`.

Считайте, что каждому товару из `productNames` соответствует значение в словаре,
отличное от `null`. Нулевой остаток допустим; дополнительная проверка здесь не требуется.
Учитывайте только товары из списка, а не все ключи словаря.

Контрольные значения:

```text
Mechanical Keyboard → 12
Gaming Mouse        → 8
Webcam              → 5
```

В `main` вызовите метод и сохраните результат в «общий остаток» (`totalStock`) типа `int`.

Вывод:

```text
Total stock: 25
```

Значение `Integer`, полученное через `get()`, участвует в арифметике с `int`
благодаря автораспаковке (unboxing).

```
public static void printStockEntries(
```

Параметр «остатки товаров по названию» (`stockByProductName`) — словарь для вывода.

Шаблон строки:

В `main` вызовите метод для итогового словаря: должны появиться ровно три записи.
**Порядок вывода `HashMap` не гарантируется.** Проверяйте набор записей, а не их расположение.
Для упорядоченного каталога используйте порядок `productNames`.

## 8. Этап 7. Статистика поисковых запросов

В `Solution.main` создайте «журнал поисковых запросов» (`searchLog`) типа `String`:

```text
mouse keyboard mouse webcam mouse
```

Разделите строку методом `split(" ")` и сохраните результат
в «поисковые слова» (`searchWords`) типа `String[]`.
Создайте «частоту поисковых слов» (`searchFrequency`)
типа `HashMap<String, Integer>` через `new`.

Для каждого «поискового слова» (`searchWord`) типа `String` из `searchWords`:

1. Получите через `get()` «прежнее количество» (`previousCount`) типа `Integer`.
2. Если получен `null`, добавьте слово со значением `1`.
3. Иначе увеличьте прежнее количество на `1` и сохраните новое значение через `put()`.

Учитывайте автоматическую упаковку и распаковку значений `Integer`.
Для проверки выведите значения именно этих трёх ключей в указанном порядке
через отдельные вызовы `get()`. Оформление строк здесь свободное.

Контрольные значения:

```text
mouse    → 3
keyboard → 1
webcam   → 1
```

Сам словарь не обязан сохранять порядок ключей.

## 10. Этап 9. Формирование текстового каталога

Создайте метод «сформировать текст каталога» (`buildCatalogText`):

```
public static String buildCatalogText(
        ArrayList<String> productNames,
        HashMap<String, Integer> stockByProductName)
```

Параметры — «названия товаров» (`productNames`)
и «остатки товаров по названию» (`stockByProductName`).
Метод возвращает текст каталога и сам ничего не печатает.

Создайте «построитель каталога» (`catalogBuilder`) типа `StringBuilder`.
Перебирайте `productNames` в исходном порядке с переменной `productName` типа `String`.
Для каждого названия получайте через `get()` «остаток товара» (`stockCount`)
типа `Integer`. Между названием и количеством записывайте `;`.

Между строками используйте `\n`. После последней строки также должен быть ровно один `\n`.
Не добавляйте пустые строки между товарами.
Количество товаров получайте через `size()`, общий остаток — через `calculateTotalStock()`;

Верните результат `toString()` для `catalogBuilder`.

## 11. Этап 10. Сохранение текстового каталога

В `Solution.main` создайте «путь к каталогу» (`catalogPath`) типа `Path`
через `Path.of("catalog.txt")`.
Вызовите `buildCatalogText()` для итоговых списка и словаря
и сохраните результат в «текст каталога» (`catalogText`) типа `String`.

Запишите текст через `Files.writeString()` с кодировкой `StandardCharsets.UTF_8`.
Относительные пути в этом задании относятся к рабочему каталогу процесса.
При необходимости проверьте **Run Configuration → Working directory** в IntelliJ IDEA.
Если файл уже существует, замените его содержимое.

Все файловые операции этапов 10–13 выполняйте последовательно в одном блоке `try`
внутри `main`. Перехватите `IOException` параметром `exception` и выведите:

```text
Local file operation failed: [сообщение исключения]
```

Сообщение исключения получите через `getMessage()`.
При ошибке оставшиеся операции этого блока не выполняются.
После обработчика продолжите независимый JSON-пример этапа 20.
Уже напечатанные результаты сохраняются;
сообщения об успехе невыполненных операций выводить нельзя.

Не сохраняйте текст путём ручного приведения отдельных символов к `byte`.

## 12. Этап 11. Чтение и проверка текстового файла

Внутри того же блока `try` считайте `catalog.txt` через `Files.readString()`
с кодировкой `StandardCharsets.UTF_8`.
Результат сохраните в «прочитанный текст каталога» (`savedCatalogText`) типа `String`.

Сравните `catalogText` и `savedCatalogText` через `equals()`
и сохраните результат в
«текст совпадает» (`isCatalogTextMatching`) типа `boolean`.
Через `Files.exists()`
получите «файл каталога существует» (`catalogFileExists`) типа `boolean`,
а через `Files.size()` — «размер каталога в байтах» (`catalogFileSize`) типа `long`.

Вывод:

```text
Catalog file exists:  true
Catalog text matches: true
Catalog file size:    [фактическое число] bytes
```

Размер получите программно, не подставляйте заранее рассчитанное значение.
Количество символов строки и размер файла в байтах — разные величины.

## 13. Этап 12. Бинарная сигнатура каталога

В том же блоке `try` создайте «байты сигнатуры» (`catalogSignatureBytes`) типа `byte[]`:

```text
77, 75, 84, 49
```

Этим ASCII-кодам соответствует текст:

```text

```

Создайте «путь к сигнатуре» (`signaturePath`) типа `Path`
через `Path.of("catalog_signature.bin")` и запишите массив с помощью `Files.write()`.
Прочитайте файл через `Files.readAllBytes()`
в «прочитанную сигнатуру» (`savedSignatureBytes`) типа `byte[]`.

Циклом `for-each` выведите каждый прочитанный байт как символ (`char`).
Переменную цикла «байт сигнатуры» (`signatureByte`) объявите как `byte`.
Для разделения символов используйте «разделитель сигнатуры» (`signatureSeparator`)
типа `String`: перед первым символом — пустая строка, перед остальными — один пробел.
После последнего символа перейдите на новую строку.

Вывод:

```text

```

Файл должен содержать ровно четыре байта.
Повторная запись заменяет содержимое файла.

## 14. Этап 13. Резервная копия бинарного файла

Прочитайте резервную копию в «байты резервной копии» (`backupSignatureBytes`)

Через `Files.size()` получите «размер резервной копии в байтах» (`backupFileSize`)

## 17. Этап 16. Загрузка JPEG через `transferTo()`

```
public static void downloadJpegWithTransfer() throws IOException
```

Метод ничего не возвращает и не принимает параметров.
Создайте «адрес источника» (`sourceUrl`) типа `URL` с адресом JPEG из этапа 14
и «путь назначения» (`targetPath`) типа `Path` через `Path.of("product_gallery.jpg")`.

В одном `try-with-resources` объявите:

* «входной поток» (`inputStream`) типа `InputStream`, открытый через `sourceUrl.openStream()`;
* «выходной поток» (`outputStream`) типа `OutputStream`,
  открытый через `Files.newOutputStream(targetPath)`.

Передайте содержимое входного потока в выходной через `inputStream.transferTo()`.
При повторном запуске содержимое файла заменяется.
Оба потока должны автоматически закрываться, а `IOException` — передаваться вызывающему коду.
Не читайте изображение как текст и не преобразовывайте JPEG-байты в `String`.

Вывод после успешной передачи и закрытия потоков:

## 18. Этап 17. Загрузка WebP через `HttpClient`

Создайте метод «скачать WebP через HTTP-клиент» (`downloadWebpWithHttpClient`):

```
public static void downloadWebpWithHttpClient() throws IOException, InterruptedException
```

Метод ничего не возвращает и не принимает параметров.
Через `HttpClient.newHttpClient()` создайте «HTTP-клиент» (`httpClient`) типа `HttpClient`.
Создайте «HTTP-запрос» (`request`) типа `HttpRequest`: GET-запрос к адресу WebP из этапа 14.
Для адреса используйте `URI.create()`.

Через `send()` получите «HTTP-ответ» (`response`) типа `HttpResponse<byte[]>`,
используя `HttpResponse.BodyHandlers.ofByteArray()`.
Оба объявленных исключения передавайте вызывающему коду.

### Проверка статуса

Через `response.statusCode()` получите «HTTP-статус» (`httpStatusCode`) типа `int`.
Если он не равен `200`, выведите сообщение и завершите метод:

```text
WebP download failed: HTTP [код]
```

Тело такого ответа не сохраняйте как изображение.

### Тип и размер содержимого

При статусе `200` получите «тип содержимого» (`contentType`) типа `String`
через `headers().firstValue("Content-Type")` для ответа.
При отсутствии заголовка используйте запасное значение `"unknown"` через `orElse()`.

Вывод:

```text
Content type: [полученное значение]
```

Сохраните `response.body()` в «байты ответа» (`responseBytes`) типа `byte[]`.
Получите длину массива и сохраните её
в «количество загруженных байтов» (`downloadedByteCount`) типа `int`.

Вывод:

```text
Downloaded bytes: [количество]
```

### Сохранение изображения

Если `contentType` начинается с `"image/"`, создайте «путь назначения» (`targetPath`)
типа `Path` через `Path.of("product_optimized.webp")`
и запишите `responseBytes` через `Files.write()`, заменяя прежнее содержимое.

Вывод после успешной записи:

```text
WebP download completed: product_optimized.webp
```

Если тип не начинается с `"image/"`, не сохраняйте тело ответа и выведите:

```text
WebP download failed: content type is not image.
```

При отклонении ответа из-за статуса или типа существующий файл не изменяйте.
Файл от прошлого запуска сам по себе не подтверждает успешность новой загрузки.

Не фиксируйте ожидаемое количество байтов: удалённый ресурс может изменяться.
Проверка `Content-Type` не доказывает соответствие байтов формату WebP.
В этом задании достаточно проверить заявленную сервером категорию `"image/"`;
проверять внутреннее устройство изображения не требуется.

## 20. Этап 19. Обработка сетевых исключений

В `RemoteContentDemo.main` последовательно вызовите:

## 21. Этап 20. Ручное извлечение значений из демонстрационного JSON

Вернитесь в `Solution`. В `main` после блока обработки файловых операций
создайте «демонстрационный ответ поставщика» (`supplierResponseText`) типа `String`:

```text
{"product":"Gaming Mouse","stock":"8"}
```

Содержимое строки должно в точности совпадать с образцом.
Создайте метод «извлечь строковое поле» (`extractJsonTextField`):

```
public static String extractJsonTextField(
        String jsonText,
        String fieldName)
```

Параметры — «текст JSON» (`jsonText`) и «имя поля» (`fieldName`).
Метод возвращает строковое значение поля или `null`, если ключ отсутствует.
Сам метод ничего не печатает.

Входной формат фиксирован приведённым образцом: значения строковые,
имена и значения заключены в двойные кавычки, экранированных кавычек внутри значений нет.
Через `indexOf()` найдите имя поля вместе с окружающими его кавычками
и границы значения; извлеките значение через `substring()`.
Для поиска используйте:

* «имя поля в кавычках» (`fieldMarker`) типа `String`;
* «позицию поля» (`fieldIndex`)         типа `int`;
* «позицию двоеточия» (`colonIndex`)    типа `int`;
* «начало значения» (`valueStartIndex`) типа `int`: индекс первого символа значения;
* «конец значения» (`valueEndIndex`)    типа `int`: индекс закрывающей кавычки.

Если ключ отсутствует, верните `null` до дальнейшего поиска границ и вызова `substring()`.
Не обращайтесь к строке по отрицательному индексу.
Для ключа `"product"` метод должен вернуть `"Gaming Mouse"`, для `"stock"` — `"8"`.
Дополнительные проверки произвольных JSON-документов не требуются.

В `main` вызовите метод для этих двух ключей и сохраните результаты
в «товар поставщика» (`supplierProduct`) и «остаток поставщика» (`supplierStock`)
типа `String`. Этот пример выполняется и после обработанной ошибки локального файла.

Вывод:

```text
Supplier product: Gaming Mouse
Supplier stock:   8
```

Это упражнение на поиск фрагментов строки, а **не универсальный JSON-парсер**.
Не применяйте этот метод к произвольным внешним JSON-ответам со сложной структурой,
в том числе к ответу API из сетевой программы.
