`StringBuilder` и `StringBuffer`

## 1. Неизменяемость строки: друг или враг?

В Java класс `String` — неизменяемый (immutable). Это значит, что после создания объект строки
нельзя изменить. Каждый раз, когда вы «изменяете» строку, например добавляете к ней что-то через
`+` или `concat()`, создаётся новый объект `String`, а исходный объект остаётся неизменным.

Пример:

```
String s = "Hello";
s = s + " world!";
System.out.println(s); // Hello world!
```

Выглядит так, будто строка `s` изменилась, но на самом деле переменная стала ссылаться на новый
объект `String` со значением `"Hello world!"`. Если таких операций много, например в цикле, это
может привести к лишним выделениям памяти и дополнительной работе сборщика мусора.

Представьте, что вы строите башню из кубиков, и каждый раз, когда хотите добавить новый кубик, вам
приходится перестраивать всю башню заново. Не очень экономно, правда? Примерно так же ведёт себя
обычный `String` при множественных изменениях.

## 2. `StringBuilder`: быстрый «строитель» строк

Класс `StringBuilder` из пакета `java.lang` — это специальный инструмент для эффективной сборки и
изменения строк. Импортировать его не нужно. Он изменяемый (mutable): можно добавлять, удалять и
вставлять символы и подстроки, изменяя один объект.

Аналогия: если `String` — это бетонная плита, то `StringBuilder` — конструктор LEGO: добавляете и
убираете детали сколько угодно, не разбирая всё заново.

### Как создать `StringBuilder`

```
StringBuilder sb = new StringBuilder(); // Пустой.
StringBuilder sb2 = new StringBuilder("Начальное значение");
```

### Основные методы

| Метод                      | Описание                                                          |
|----------------------------|-------------------------------------------------------------------|
| `append(...)`              | Добавить в конец строку, число, символ и т. д.                    |
| `insert(index, ...)`       | Вставить значение в указанную позицию.                            |
| `delete(start, end)`       | Удалить символы от `start` включительно до `end` не включительно. |
| `replace(start, end, str)` | Заменить часть строки другим содержимым.                          |
| `reverse()`                | Развернуть строку задом наперёд.                                  |
| `toString()`               | Преобразовать содержимое в обычную строку.                        |
| `setLength(newLen)`        | Обрезать или дополнить строку до заданной длины.                  |

| Метод                      | Пример использования        |
|----------------------------|-----------------------------|
| `append(...)`              | `sb.append("Java");`        |
| `insert(index, ...)`       | `sb.insert(0, "Hello ");`   |
| `delete(start, end)`       | `sb.delete(0, 5);`          |
| `replace(start, end, str)` | `sb.replace(0, 4, "Hi");`   |
| `reverse()`                | `sb.reverse();`             |
| `toString()`               | `String s = sb.toString();` |
| `setLength(newLen)`        | `sb.setLength(3);`          |

### Пример использования

```
StringBuilder sb = new StringBuilder();
sb.append("Привет, ");
sb.append("мир!");
System.out.println(sb);       // Привет, мир!

sb.insert(7, "Java ");        // Вставим "Java " после "Привет, ".
System.out.println(sb);       // Привет, Java мир!

sb.replace(8, 12, "другой");  // Заменим "Java" на "другой".
System.out.println(sb);       // Привет, другой мир!

sb.reverse();
System.out.println(sb);       // !рим йогурд ,тевирП
```

## 3. `StringBuffer`: старший брат с защитой от многопоточности

В чём разница между `StringBuilder` и `StringBuffer`?

* `StringBuilder` — быстрый, но его методы не синхронизированы для совместного изменения из
  нескольких потоков.
* `StringBuffer` — синхронизирован и потому обычно медленнее.

Если приложение работает в одном потоке или объект не изменяется совместно из нескольких потоков,
обычно используют `StringBuilder`. Если требуется синхронизированный изменяемый буфер строк,
можно использовать `StringBuffer`.

## 4. Когда использовать `StringBuilder` вместо `String`?

### Сценарии

* Частые изменения строки: добавление, удаление и вставка в цикле или при сборке больших текстов.
* Сборка строки из массива или списка, например CSV, HTML или отчётов.
* Парсинг и обработка текста с большим числом операций над строкой.

Пример: сборка строки из массива

Плохой способ через `String` и `+`:

```
String[] names = {"Иван", "Пётр", "Мария"};
String result = "";

for (int i = 0; i < names.length; i++) {
    result += names[i];
    if (i < names.length - 1) {
        result += ", ";
    }
}

System.out.println(result);
```

Хороший способ через `StringBuilder`:

```
String[] names = {"Иван", "Пётр", "Мария"};
StringBuilder sb = new StringBuilder();

for (int i = 0; i < names.length; i++) {
    sb.append(names[i]);
    if (i < names.length - 1) {
        sb.append(", ");
    }
}

System.out.println(sb.toString());
```

Разница: в первом случае при конкатенациях создаются новые строки, а во втором мы наращиваем один
объект `StringBuilder`.

## 5. Сравнение производительности: `String` и `StringBuilder`

```
// Через String.
long t1 = System.currentTimeMillis();
String s = "";
for (int i = 0; i < 10000; i++) {
    s += i + " ";
}
long t2 = System.currentTimeMillis();
System.out.println("String: " + (t2 - t1) + " мс");

// Через StringBuilder.
t1 = System.currentTimeMillis();
StringBuilder sb = new StringBuilder();
for (int i = 0; i < 10000; i++) {
    sb.append(i).append(" ");
}
s = sb.toString();
t2 = System.currentTimeMillis();
System.out.println("StringBuilder: " + (t2 - t1) + " мс");
```

Итог: при множественных конкатенациях `StringBuilder` обычно позволяет избежать большого числа
промежуточных объектов и может работать значительно эффективнее.

## 6. Полезные нюансы

### Можно ли использовать методы `String`?

У `StringBuilder` свои методы. Чтобы получить обычную строку, вызывайте `toString()`.

```
StringBuilder sb = new StringBuilder("Hello");
String s = sb.toString(); // Теперь s — обычная строка.
```

### Можно ли сравнивать `StringBuilder` через `equals()`?

Осторожно: `sb1.equals(sb2)` сравнивает объекты по ссылочной идентичности, а не содержимое.
Сравнивайте, например, так:

```
if (sb1.toString().equals(sb2.toString())) {
    // Содержимое совпадает.
}
```

### Можно ли передать `StringBuilder` в `System.out.println()`?

Да. `System.out.println()` вызовет `toString()` автоматически.

### Можно ли читать символы по индексу?

Да, используйте `charAt(int index)`, как у обычной строки.

## 7. Типичные ошибки при работе с `StringBuilder` и `StringBuffer`

### Ошибка №1. Сравнение двух `StringBuilder` через `equals()` или `==`

Эти проверки не сравнивают текстовое содержимое. Для сравнения содержимого можно сначала получить
обычные строки с помощью `toString()`.

### Ошибка №2. Отсутствие `toString()` там, где ожидается `String`

Не забывайте вызывать `toString()` при возврате из метода, логировании или передаче в API, если
конкретный API ожидает именно `String`.

### Ошибка №3. `StringBuilder` для пары простых конкатенаций

Запись вида `"Hello, " + name` нормально читается и подходит для простой конкатенации.

### Ошибка №4. Конкатенация `String` в цикле через `+`

Это может быть неэффективно по времени и памяти. Для множества последовательных изменений лучше
использовать `StringBuilder`.

### Ошибка №5. Путаница между `StringBuffer` и `StringBuilder`

Если нет совместной модификации из нескольких потоков, обычно выбирают `StringBuilder`.

### Ошибка №6. Бездумное использование `setLength()`

Проверяйте корректность новой длины: данные после неё при уменьшении длины будут потеряны.
