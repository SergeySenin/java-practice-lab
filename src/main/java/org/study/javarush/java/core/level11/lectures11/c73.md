Синтаксис `try-catch`

## 1. Зачем нужен `try-catch`?

Как вы уже знаете, в программировании ошибки случаются постоянно: деление на ноль,
неправильный ввод, отсутствие файла и т. д. Если не обработать такие ситуации,
программа может аварийно завершиться.

**Конструкция `try-catch`** позволяет «поймать» исключение указанного типа и обработать его,
чтобы программа могла продолжить работу.

### Синтаксис конструкции `try-catch`

```
try {
    // Код, который может выбросить исключение
} catch (ТипИсключения имяПеременной) {
    // Код для обработки исключения
}
```

Пояснение:

* `try` — «попробуй выполнить этот код».
* `catch` — «если возникнет исключение указанного типа, обработай его здесь».

### Как это работает?

Если в блоке `try` возникает исключение, выполнение этого блока сразу прерывается,
и управление переходит в первый подходящий блок `catch`. Если исключения не возникло —
блок `catch` пропускается.

## 2. Пример: деление на ноль

### Без обработки исключения

```
int a = 10;
int b = 0;
int result = a / b;                          // Здесь программа завершится с ошибкой!
System.out.println("Результат: " + result);  // До этой строки не дойдём
```

Результат:

```text
Exception in thread "main" java.lang.ArithmeticException: / by zero
    at Main.main(Main.java:3)
```

### С обработкой через `try-catch`

```
int a = 10;
int b = 0;

try {
    int result = a / b; // Здесь может возникнуть исключение
    System.out.println("Результат: " + result);
} catch (ArithmeticException e) {
    System.out.println("Ошибка: деление на ноль невозможно!");
}

System.out.println("Программа продолжила работу.");
```

Результат:

```text
Ошибка: деление на ноль невозможно!
Программа продолжила работу.
```

Объяснение:

* Как только Java встречает целочисленное деление на ноль, она «выбрасывает» исключение.
* Выполнение блока `try` прерывается, и управление переходит в `catch`.
* После обработки исключения программа продолжает выполнение.

## 3. Как работает блок `catch`

В скобках после `catch` указывается **тип исключения** (например, `ArithmeticException`)
и **имя переменной** (обычно `e`).

Внутри блока `catch` можно узнать подробности об ошибке:

* `e.getMessage()` — короткое описание ошибки.
* `e.printStackTrace()` — подробная информация (для отладки).

Пример:

```
try {
    int[] arr = new int[2];
    int x = arr[10];                                  // Ошибка: индекса нет
} catch (ArrayIndexOutOfBoundsException e) {
    System.out.println("Ошибка: " + e.getMessage());  // Выводим сообщение об исключении
    e.printStackTrace();                              // Печатаем в консоль
                                                      // подробную информацию об ошибке
}
```

## 4. Поток выполнения при исключении

Если в блоке `try` **исключение не возникло** — блок `catch` пропускается.

Если в блоке `try` **возникло исключение** — выполнение блока прерывается в месте его
возникновения, и управление сразу переходит в первый подходящий `catch`. Всё, что находится
после вызвавшей исключение операции в блоке `try`, уже не выполнится!

Иллюстрация:

```
try {
    System.out.println("1. Начало try");
    int a = 10 / 0;                          // Ошибка!
    System.out.println("2. После деления");  // Не выполнится
} catch (ArithmeticException e) {
    System.out.println("3. В блоке catch");
}
System.out.println("4. После try-catch");
```

Результат:

```text
1. Начало try
3. В блоке catch
4. После try-catch
```

## 5. Типичные ошибки при использовании `try-catch`

### Ошибка № 1. Слишком широкий `catch`

Если использовать `catch (Exception e)`, можно перехватить множество неожиданных исключений,
которые вы не умеете корректно обрабатывать.

Решение: перехватывайте только те исключения, которые действительно ожидаются в данном месте
(например, `IOException`, `SQLException`).

### Ошибка № 2. Пустой `catch`

Писать `catch (Exception e) {}` — значит скрыть проблему. Программа может позже завершиться
с ошибкой или вести себя странно.

Решение: хотя бы зарегистрируйте ошибку (`e.printStackTrace()` или логгер).

### Ошибка № 3. Вера в то, что `try-catch` исправит любую проблему

Если ошибка в логике программы (например, деление на ноль, неверный алгоритм),
`try-catch` может перехватить соответствующее исключение, но не исправит причину ошибки.

Решение: используйте `try-catch` для действительно ожидаемых ситуаций,
а не для маскировки ошибок в коде.
