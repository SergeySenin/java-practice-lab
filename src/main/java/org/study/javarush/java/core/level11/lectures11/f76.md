Стек вызовов (Stack Trace)

## 1. Введение

Stack Trace (стек вызовов) — это список активных вызовов методов в момент возникновения
исключения. Когда исключение остаётся необработанным, Java обычно выводит информацию о нём
и стек вызовов в консоль. Это как «следы на снегу»: вы видите, какими вызовами программа
пришла к проблеме.

**Аналогия**: представьте, что вы идёте по лабиринту и вдруг упираетесь в стену.
Stack Trace — это карта, показывающая, по каким коридорам вы шли, прежде чем заблудиться.

### Как выглядит Stack Trace?

Когда возникает необработанное исключение, Java может вывести примерно такое сообщение:

```text
Exception in thread "main" java.lang.ArithmeticException: / by zero
    at Main.divide(Main.java:10)
    at Main.main(Main.java:5)
```

Что здесь написано?

* `Exception in thread "main"` — поток, в котором исключение осталось необработанным
  (часто это `main`).
* `java.lang.ArithmeticException: / by zero` — тип исключения и его сообщение.
* `at Main.divide(Main.java:10)` — метод `divide` в классе `Main`, строка `10`.
* `at Main.main(Main.java:5)` — метод `main` в классе `Main`, строка `5`.

Каждая строка `at ...` — это кадр стека вызовов. Обычно первая такая строка показывает место,
где исключение было создано или выброшено. Ниже находятся методы, которые привели к этому
вызову, вплоть до начала цепочки.

## 2. Как читать Stack Trace?

### Шаг 1. Найдите тип исключения и сообщение

Строка с названием исключения обычно содержит его тип и, если сообщение есть, его описание:

```text
java.lang.ArithmeticException: / by zero
```

Это уже подсказка: ошибка связана с делением на ноль.

### Шаг 2. Смотрите на первую строку `at ...`

Она обычно указывает место, где **было выброшено исключение**:

```text
at Main.divide(Main.java:10)
```

Значит, исключение возникло в методе `divide` класса `Main` на 10-й строке.
Но сама причина проблемы может находиться в коде, который вызвал этот метод.

### Шаг 3. Проследите цепочку вызывающих методов

Следующая строка показывает, кто вызвал этот метод:

```text
at Main.main(Main.java:5)
```

Значит, метод `main` вызвал `divide`, и исключение передалось выше по цепочке вызовов.
Номер строки — `5`.

### Шаг 4. Ищите свои классы

В длинном стеке вызовов часто бывают системные методы (например, из пакетов `java.util`,
`java.io`).

**Ищите свои классы в цепочке вызовов**, даже если они находятся не в самом начале списка.
Смотрите на имена классов и файлов: они помогут найти участок своего кода, связанный с ошибкой.

## 3. Пример: разбор реального Stack Trace

Код:

```
public class Main {
    public static void main(String[] args) {
        int result = divide(10, 0);
        System.out.println("Результат: " + result);
    }

    public static int divide(int a, int b) {
        return a / b;
    }
}
```

Ошибка:

```text
Exception in thread "main" java.lang.ArithmeticException: / by zero
    at Main.divide(Main.java:8)
    at Main.main(Main.java:3)
```

Разбираем:

* Ошибка — деление на ноль (`ArithmeticException`).
* Произошла в методе `divide` на строке `8`.
* Метод `divide` был вызван из `main` на строке `3`.

Что делать?

Открываем файл `Main.java`, смотрим строку `8` — находим деление на ноль. Исправляем!

## 4. Stack Trace с несколькими методами

Код:

```
public class Main {
    public static void main(String[] args) {
        process();
    }

    public static void process() {
        calculate();
    }

    public static void calculate() {
        int[] arr = {1, 2, 3};
        System.out.println(arr[10]); // Ошибка!
    }
}
```

Ошибка:

```text
Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException: Index 10 out of bounds for length 3
    at Main.calculate(Main.java:12)
    at Main.process(Main.java:7)
    at Main.main(Main.java:3)
```

Разбираем:

* Ошибка — выход за границы массива (`ArrayIndexOutOfBoundsException`).
* Произошла в `calculate` (строка `12`).
* Метод `calculate` был вызван из `process` (строка `7`).
* Метод `process` был вызван из `main` (строка `3`).

Вывод: Stack Trace показывает цепочку вызовов, по которой программа пришла к ошибке.

## 5. Типичные ошибки при работе со Stack Trace

### Ошибка № 1. Игнорирование Stack Trace

Новички часто просто смотрят на «красную ошибку» и не читают стек вызовов. Не делайте так!
Stack Trace — это подсказка, где искать баг.

### Ошибка № 2. Путают строку с ошибкой и строку с местом ошибки

Важно: строка с типом исключения сообщает, что произошло, а первая строка `at ...` обычно
показывает место, где исключение было выброшено.

### Ошибка № 3. Ищут ошибку в системных классах

Если видите строки вроде `at java.base/java.util.Scanner.nextInt(Scanner.java:123)`,
не спешите лезть в исходники Java. Смотрите, кто вызвал этот метод в вашем коде.

### Ошибка № 4. Не используют номера строк

Номер строки — ваш лучший друг. Откройте файл, найдите нужную строку — и увидите место,
связанное с исключением.

### Ошибка № 5. Не понимают, что Stack Trace — это «путь»

Stack Trace показывает, как программа пришла к ошибке. Иногда баг не в самой верхней строке,
а в том, как вы вызвали метод.
