Функциональные интерфейсы: `@FunctionalInterface`

## 1. Введение

**Функциональный интерфейс** — это интерфейс, который содержит ровно один
абстрактный метод (то есть метод без реализации). Именно такой интерфейс можно
использовать для краткой записи реализации метода — с помощью лямбда-выражений
(краткий пример приведён ниже).

### Почему только один метод?

Потому что функциональный интерфейс описывает ровно одну операцию. Если бы
абстрактных методов было два и более, стало бы непонятно, какой именно метод
нужно реализовать с помощью лямбда-выражения. Поэтому правило простое:
один функциональный интерфейс — один абстрактный метод.

### Примеры из стандартной библиотеки

* `Runnable` — для задач в потоках (`void run()`).
* `Callable<V>` — для задач, которые возвращают результат (`V call()`).
* `Comparator<T>` — для сравнения объектов (`int compare(T o1, T o2)`).
* `Consumer<T>` — «потребитель» значения (`void accept(T t)`).
* `Supplier<T>` — «поставщик» значения (`T get()`).
* `Function<T, R>` — функция из `T` в `R` (`R apply(T t)`).
* `Predicate<T>` — проверка условия (`boolean test(T t)`).

Вот, например, упрощённое объявление интерфейса `Runnable`:

```
public interface Runnable {
    void run();
}
```

А вот упрощённое объявление интерфейса `Comparator`:

```
public interface Comparator<T> {
    int compare(T o1, T o2);
    // Есть и default- и static-методы, но абстрактная операция сравнения одна!
}
```

Важный момент: `default`- и `static`-методы не считаются абстрактными, поэтому
их может быть сколько угодно. При подсчёте абстрактных методов функционального
интерфейса также не учитываются методы, соответствующие публичным методам
класса `Object` (например, `equals(Object)`).

## 2. Аннотация `@FunctionalInterface`

Java — строгая и принципиальная дама. Чтобы не было путаницы, она позволяет
явно пометить интерфейс как функциональный с помощью аннотации
`@FunctionalInterface`. Это как наклейка «Работает только с одной кнопкой!» —
чтобы никто не добавил лишнего.

```
// Operation.java
@FunctionalInterface
public interface Operation {
    int apply(int a, int b);
}
```

Теперь если вы вдруг добавите второй абстрактный метод, компилятор сообщит
об ошибке:

```
// Oops.java — намеренная ошибка компиляции
@FunctionalInterface
public interface Oops {
    void doIt();
    void doSomethingElse(); // Ошибка! Два абстрактных метода
}
```

### Обязательна ли аннотация?

Нет, это не обязательно. Интерфейс будет функциональным и без неё, если
содержит ровно один абстрактный метод. Но с аннотацией вы явно показываете
своё намерение и защищаете себя от случайных ошибок.

### Можно ли добавлять `default`- и `static`-методы?

Да, можно! Главное, чтобы был только один абстрактный метод. Все остальные
методы могут быть `default` или `static`, сколько душе угодно.

Пример:

```
// FancyOperation.java
@FunctionalInterface
public interface FancyOperation {
    int apply(int a, int b);

    default void printInfo() {
        System.out.println("Я — fancy операция!");
    }

    static void description() {
        System.out.println("Функциональный интерфейс для арифметики.");
    }
}
```

## 3. Примеры объявления и использования

Допустим, вы хотите описать операцию над двумя числами. Вот так это делается:

```
// Operation.java
@FunctionalInterface
public interface Operation {
    int apply(int a, int b);
}
```

Теперь этот интерфейс можно реализовать по-разному.

### Реализация через обычный класс

```
// SumOperation.java
public class SumOperation implements Operation {
    @Override
    public int apply(int a, int b) {
        return a + b;
    }
}
```

Использование:

```
Operation sum = new SumOperation();
System.out.println(sum.apply(2, 3)); // 5
```

### Реализация через анонимный класс

```
Operation multiply = new Operation() {
    @Override
    public int apply(int a, int b) {
        return a * b;
    }
};
System.out.println(multiply.apply(2, 3)); // 6
```

### Кратко о лямбдах

Начиная с Java 8 реализацию единственного абстрактного метода функционального
интерфейса можно записать лямбдой: `параметры -> действие`. Сами функциональные
интерфейсы существовали и раньше.

Пример с уже объявленным `Operation`:

```
Operation sum = (a, b) -> a + b;
System.out.println(sum.apply(2, 3)); // 5
```

Здесь `a` и `b` — параметры метода `apply`, а выражение `a + b` задаёт возвращаемый
результат. Если параметр один, скобки вокруг него можно опустить. Для метода без
возвращаемого значения справа можно записать вызов `System.out.println(...)`.
Этого синтаксиса достаточно для коротких задач этого сборника.

## 4. Практика: напиши свой функциональный интерфейс

### Задание 1. Сделай свой `Action`!

Создайте интерфейс `Action`, который принимает строку и ничего не возвращает.
Реализуйте его через анонимный класс, который печатает строку в верхнем регистре.

```
// ActionDemo.java
@FunctionalInterface
interface Action {
    void act(String s);
}

public class ActionDemo {
    public static void main(String[] args) {
        Action shout = new Action() {
            @Override
            public void act(String text) {
                System.out.println(text.toUpperCase());
            }
        };

        shout.act("я учу java!"); // Я УЧУ JAVA!
    }
}
```

Этот анонимный класс также можно заменить лямбдой по схеме из предыдущего раздела.

### Задание 2. Фильтр чисел

Создайте интерфейс `NumberPredicate` с методом `boolean test(int n)`.
Реализуйте проверку на чётность с помощью анонимного класса.

```
// PredicateDemo.java
@FunctionalInterface
interface NumberPredicate {
    boolean test(int n);
}

public class PredicateDemo {
    public static void main(String[] args) {
        NumberPredicate isEven = new NumberPredicate() {
            @Override
            public boolean test(int n) {
                return n % 2 == 0;
            }
        };

        System.out.println(isEven.test(4));  // true
        System.out.println(isEven.test(7));  // false
    }
}
```

### Задание 3. Используем стандартные интерфейсы

Вместо собственного интерфейса можно использовать готовый `Predicate<Integer>`:

```
import java.util.function.Predicate;

Predicate<Integer> isPositive = new Predicate<Integer>() {
    @Override
    public boolean test(Integer x) {
        return x > 0;
    }
};

System.out.println(isPositive.test(10)); // true
System.out.println(isPositive.test(-5)); // false
```

### Таблица: функциональные интерфейсы из стандартной библиотеки

| Интерфейс        | Метод               | Описание                           |
|------------------|---------------------|------------------------------------|
| `Runnable`       | `void run()`        | Задача без аргументов и результата |
| `Callable<V>`    | `V call()`          | Задача с результатом               |
| `Comparator<T>`  | `int compare(T, T)` | Сравнение двух объектов            |
| `Consumer<T>`    | `void accept(T)`    | «Потребитель» значения             |
| `Supplier<T>`    | `T get()`           | «Поставщик» значения               |
| `Function<T, R>` | `R apply(T)`        | Функция из `T` в `R`               |
| `Predicate<T>`   | `boolean test(T)`   | Проверка условия                   |

| Интерфейс        | Пример применения                       |
|------------------|-----------------------------------------|
| `Runnable`       | Потоки, таймеры                         |
| `Callable<V>`    | Потоки, `ExecutorService`               |
| `Comparator<T>`  | Сортировка коллекций                    |
| `Consumer<T>`    | Перебор коллекции                       |
| `Supplier<T>`    | Ленивая инициализация, генерация данных |
| `Function<T, R>` | Преобразование данных                   |
| `Predicate<T>`   | Фильтрация коллекций                    |

## 5. Типичные ошибки при работе с функциональными интерфейсами

### Ошибка № 1. Добавили второй абстрактный метод

Если в интерфейсе больше одного абстрактного метода, он перестаёт быть
функциональным. Компилятор при наличии `@FunctionalInterface` сообщит об ошибке.

### Ошибка № 2. Забыли, что `default`- и `static`-методы не считаются абстрактными

Можно смело добавлять их в функциональный интерфейс — это не нарушит правило
«одного абстрактного метода».

### Ошибка № 3. Неверно реализовали сигнатуру метода

Например, интерфейс требует два аргумента, а вы написали метод только с одним.
Всегда проверяйте сигнатуры.

### Ошибка № 4. Не используете `@FunctionalInterface` и случайно портите интерфейс

Если не пометить интерфейс аннотацией, можно случайно добавить лишний метод —
и потом долго искать, почему код не работает. Лучше добавлять аннотацию
для явности и проверки компилятором.
