Отличие интерфейсов от абстрактных классов

## 1. Абстрактный класс: повторим основы

Перед тем как перейти к сравнению, освежим в памяти, что же такое абстрактный класс.

Абстрактный класс — это класс, экземпляр которого нельзя создать напрямую (нельзя написать
`new Animal()`, если `Animal` абстрактный), но который может содержать как обычные
(с реализацией), так и абстрактные (без реализации) методы. Абстрактный класс часто
используется как основа для других классов, которые наследуют его поведение и/или
обязаны реализовать некоторые методы.

Например, если в нашем приложении есть разные виды транспорта, можно завести
абстрактный класс `Transport`:

```
// Transport.java
public abstract class Transport {
    private String model;

    public Transport(String model) {
        this.model = model;
    }

    public String getModel() {
        return model;
    }

    // Абстрактный метод — реализации нет, только объявление
    public abstract void move();

    // Обычный метод — реализация есть
    public void printInfo() {
        System.out.println("Модель транспорта: " + model);
    }
}
```

Особенности абстрактного класса:

* Может содержать поля (состояние).
* Может содержать реализованные методы.
* Может содержать абстрактные методы (обязательные к реализации в конкретных наследниках).
* Нельзя создать экземпляр напрямую.
* Используется для общего поведения и состояния.

## 2. Интерфейс: повторим основы

Интерфейс — это контракт, определяющий возможности класса. Интерфейс не описывает
состояние отдельного объекта: в нём нет обычных полей экземпляра, только константы.
До Java 8 интерфейсы не содержали методов с реализацией, а начиная с Java 8 могут
содержать и такие методы. «Если ты реализуешь меня, ты обязан уметь делать вот это» —
главный смысл интерфейса.

Пример интерфейса:

```
// Movable.java
public interface Movable {
    void move(int x, int y);
}
```

Особенности интерфейса:

* Не содержит состояния экземпляра (только поля `public static final`).
* До Java 8 — только абстрактные методы; с Java 8 появились `default`- и `static`-методы,
  а с Java 9 — ещё и `private`-методы с реализацией.
* Методы без тела по умолчанию являются `public abstract`.
* Класс может реализовать несколько интерфейсов.
* Используется для описания возможностей: «что умеет делать» класс.

## 3. Таблица сравнения: абстрактный класс vs интерфейс

Пора сравнить эти два инструмента лицом к лицу! Вот наглядные таблицы.

| Особенность                | Абстрактный класс                  |
|----------------------------|------------------------------------|
| Синтаксис                  | `abstract class`                   |
| Можно создавать экземпляр? | Нет                                |
| Методы с реализацией       | Да                                 |
| Абстрактные методы         | Да                                 |
| Поля (состояние)           | Поля экземпляра и статические поля |
| Конструкторы               | Да                                 |

| Особенность                | Интерфейс                                           |
|----------------------------|-----------------------------------------------------|
| Синтаксис                  | `interface`                                         |
| Можно создавать экземпляр? | Нет                                                 |
| Методы с реализацией       | С Java 8 — `default`/`static`; с Java 9 — `private` |
| Абстрактные методы         | Да                                                  |
| Поля (состояние)           | Только `public static final`                        |
| Конструкторы               | Нет                                                 |

| Особенность               | Абстрактный класс             |
|---------------------------|-------------------------------|
| Наследование              | Класс наследует один класс    |
| Модификаторы методов      | Разные, с ограничениями       |
| Ключевое слово для класса | `extends`                     |
| Обычно используется       | Общая реализация и состояние  |
| Примеры из JDK            | `AbstractList`, `AbstractMap` |

| Особенность               | Интерфейс                              |
|---------------------------|----------------------------------------|
| Наследование              | Класс реализует несколько интерфейсов  |
| Модификаторы методов      | Без тела — `public abstract`; см. ниже |
| Ключевое слово для класса | `implements`                           |
| Обычно используется       | Возможности и роли                     |
| Примеры из JDK            | `Comparable`, `Runnable`               |

Модификаторы методов интерфейса: абстрактные методы неявно `public abstract`.
С Java 8 доступны `default`- и `static`-методы с реализацией, а с Java 9 —
`private`-методы для внутренней логики интерфейса. Абстрактные методы класса
не могут быть `private`, `static` или `final`.

## 4. Когда использовать интерфейс, а когда абстрактный класс?

### Интерфейс используйте, когда:

* Вы хотите описать «что умеет делать» класс, не заботясь о том, как он это делает.
* Вам нужно, чтобы класс мог реализовать несколько независимых возможностей.
* Пример: `Comparable` (можно сравнивать), `Serializable` (можно сериализовать),
  `Runnable` (можно передать задачу для выполнения в потоке).

### Абстрактный класс используйте, когда:

* Вы хотите задать общую реализацию и состояние, которые будут у всех наследников.
* Вам нужно, чтобы наследники имели определённые поля или методы с реализацией.
* У класса может быть только один непосредственный суперкласс (обычный или абстрактный).
  При этом у одного родительского класса может быть несколько наследников.

### Жизненные аналогии

Интерфейс — это как «водительские права»: если у тебя они есть, ты *можешь*
водить машину, но никто не говорит, на какой именно машине и как ты это делаешь.

Абстрактный класс — это как «общий чертёж автомобиля»: у всех машин есть руль,
педали, двигатель, но каждая марка реализует детали по-своему.

## 5. Примеры из стандартной библиотеки Java

### Интерфейс: `Comparable`

Упрощённое объявление интерфейса из стандартной библиотеки:

```
public interface Comparable<T> {
    int compareTo(T o);
}
```

Любой конкретный класс, который реализует этот интерфейс, должен обеспечить
реализацию метода `compareTo()`. Например, `String`, `Integer`, `LocalDate` и
многие другие классы реализуют `Comparable`.

### Абстрактный класс: `AbstractList`

Упрощённая схема объявления (без деталей реализации):

```
public abstract class AbstractList<E> extends AbstractCollection<E>
        implements List<E> {
    // Реализация некоторых методов List по умолчанию
    // Некоторые методы остаются абстрактными
}
```

`AbstractList` уже реализует часть поведения коллекций, но оставляет ряд операций
для реализации наследникам. Некоторые готовые методы могут выбрасывать
`UnsupportedOperationException`, если операция не поддерживается.

## 6. Примеры кода: сравнение на практике

### Интерфейс

Создадим интерфейс и класс, который его реализует.

```
// Printable.java
public interface Printable {
    void print();
}
```

```
// Document.java
public class Document implements Printable {
    @Override
    public void print() {
        System.out.println("Печатаю документ...");
    }
}
```

### Абстрактный класс

Теперь абстрактный класс и его наследник.

```
// Machine.java
public abstract class Machine {
    public void turnOn() {
        System.out.println("Машина включена.");
    }

    public abstract void work();
}
```

```
// Printer.java
public class Printer extends Machine {
    @Override
    public void work() {
        System.out.println("Принтер печатает...");
    }
}
```

### Класс наследует абстрактный класс и реализует интерфейс

```
// SmartPrinter.java
public class SmartPrinter extends Machine implements Printable {
    @Override
    public void work() {
        System.out.println("Умный принтер работает...");
    }

    @Override
    public void print() {
        System.out.println("Умный принтер печатает...");
    }
}
```

## 7. Множественная реализация интерфейсов: зачем это круто

В Java класс может наследовать только один класс (`abstract` или обычный),
но реализовывать сколько угодно интерфейсов! Это позволяет создавать гибкие,
расширяемые архитектуры.

```
// Scannable.java
public interface Scannable {
    void scan();
}
```

```
// MultiFunctionPrinter.java
public class MultiFunctionPrinter extends Machine implements Printable, Scannable {
    @Override
    public void work() {
        System.out.println("МФУ работает...");
    }

    @Override
    public void print() {
        System.out.println("МФУ печатает...");
    }

    @Override
    public void scan() {
        System.out.println("МФУ сканирует...");
    }
}
```

### Когда что выбирать?

Если вы проектируете базовый функционал с общим состоянием (например, поля),
используйте абстрактный класс.

Если вы хотите навесить на объекты «ярлыки возможностей» (например,
«умеет печатать», «умеет сравниваться», «умеет сериализоваться») — используйте интерфейсы.

Если вы не уверены — часто разумно начать с интерфейса: он позволяет задать
контракт без привязки к единственному базовому классу. Но выбор зависит от задачи.

## 8. Типичные ошибки и подводные камни

### Ошибка № 1. Пытаетесь наследовать несколько классов — Java не даст!

Класс может наследовать только один класс, но реализовывать много интерфейсов.
Например, `class A extends B, C` — ошибка, а вот
`class A extends B implements X, Y, Z` — допустимый синтаксис, если типы объявлены.

### Ошибка № 2. Путаете поля интерфейса и класса

В интерфейсе можно объявлять только поля `public static final`.
Нельзя объявить обычное состояние, например `private int count;`, — компилятор
тут же вас остановит.

### Ошибка № 3. Не реализовали все методы интерфейса

Если класс не реализует обязательные абстрактные методы интерфейса
(сам или через наследование), он должен быть объявлен как `abstract`,
иначе компилятор выдаст ошибку.

### Ошибка № 4. Пытаетесь создать экземпляр интерфейса или абстрактного класса

Оба этих типа нельзя создать напрямую:

```
Printable p = new Printable();  // Ошибка!
Machine m = new Machine();      // Ошибка!
```

Их можно использовать как типы ссылок на объекты конкретных классов.

### Ошибка № 5. Думаете, что интерфейс может иметь конструктор

У интерфейсов не может быть конструкторов: интерфейс не является классом,
экземпляр которого создаётся напрямую. Конструкторы бывают только у классов
(обычных и абстрактных).
