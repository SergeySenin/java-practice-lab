Задание 04. Исследовательская миссия автономного дрона

Вы разрабатываете консольную программу управления исследовательским дроном.
Оператор настраивает запуск, затем программа выполняет обратный отсчёт,
обрабатывает показания датчика, проверяет контрольные точки маршрута
и выводит карту области и отчёт миссии.

## 1. Структура программы

В файле `Solution.java` создайте класс «решение» (`Solution`) и главный метод программы (`main`):

```
public static void main(String[] args)
```

Параметр «аргументы командной строки» (`args`) имеет тип `String[]` и здесь не используется.
Все действия выполняйте внутри `main`, используя указанные английские имена переменных.
Каждый этап выполняйте указанным видом цикла: цель задания —
закрепить различия между `do-while`, `while` и `for`. Не заменяйте их друг другом.

Подключите класс «сканер» (`Scanner`) из пакета `java.util`. Создайте объект «консоль» (`console`)
типа `Scanner`, читающий стандартный поток ввода (`System.in`). Название миссии считайте методом
«считать строку» (`nextLine()`), все целые числа — методом «считать целое число» (`nextInt()`).

Для строк вывода используйте метод «вывести с переходом на новую строку» (`System.out.println()`),
кроме отдельных клеток карты. Подставляйте переменные конкатенацией (`+`).
Подписи и пробелы берите из основного образца;
пробелы выравнивания записывайте внутри строковых литералов.

## 2. Этап 1. Название миссии

Считайте «исходное название миссии» (`missionNameInput`) типа «строка» (`String`).
Методом «удалить пробелы по краям» (`trim()`) удалите пробелы в начале и конце и сохраните
результат в «название миссии» (`missionName`) типа `String`.

## 3. Этап 2. Проверка заряда аккумулятора

Объявите «уровень заряда в процентах» (`batteryLevelPercent`) типа «целое число» (`int`).
Циклом «с постусловием» (`do-while`) запросите заряд **хотя бы один раз**:

* считайте значение в `batteryLevelPercent`;
* если оно меньше `20` или больше `100`, оператором `if`
  выведите `Invalid battery level.` и повторите ввод;
* завершите цикл при значении от `20` до `100` включительно.

После условия `do-while` поставьте точку с запятой.
Этот вид цикла используйте только для проверки заряда.

После цикла выведите строку с подписью `Battery accepted:`, значением `batteryLevelPercent`
и знаком `%`, как в основном образце.

## 4. Этап 3. Параметры маршрута

Последовательно считайте пять переменных типа `int`:

* «количество контрольных точек» (`checkpointCount`);
* «номер искомой контрольной точки» (`targetCheckpointNumber`);
* «длина стороны карты» (`mapSideLength`);
* «индекс строки маяка» (`beaconRowIndex`);
* «индекс столбца маяка» (`beaconColumnIndex`).

Считайте, что `checkpointCount > 0`, `mapSideLength > 0`, искомая точка находится
от `1` до `checkpointCount` включительно, а оба индекса маяка — от `0` до
`mapSideLength - 1`. Дополнительная проверка этих значений не требуется.

## 5. Этап 4. Обратный отсчёт перед запуском

Используйте цикл «со счётчиком» (`for`).
Объявите в нём «счётчик обратного отсчёта» (`launchCountdown`) типа `int` со значением `3`.
На каждой итерации выводите его значение и уменьшайте оператором «декремент» (`--`).
Последнее выведенное число — `1`. После завершения цикла выведите `LAUNCH`:

```text
3
2
1
LAUNCH
```

## 6. Этап 5. Получение показаний датчика

Датчик передаёт неизвестное заранее количество расстояний до объектов в метрах. Создайте:

* «показание расстояния датчика» (`sensorDistanceReading`) типа `int`;
* «количество показаний» (`sensorReadingCount`) типа `int` со значением `0`;
* «сумма расстояний» (`sensorDistanceSum`) типа `int` со значением `0`;
* «количество опасных объектов» (`dangerousObjectCount`) типа `int` со значением `0`.

Первое показание считайте в `sensorDistanceReading` перед циклом «с предусловием» (`while`).
Выполняйте цикл, пока показание неотрицательное. Внутри каждой итерации:

1. Увеличьте `sensorReadingCount` на единицу оператором «инкремент» (`++`).
2. Прибавьте текущее расстояние к `sensorDistanceSum`.
3. Если расстояние меньше или равно `100` (оператор `<=`),
   увеличьте `dangerousObjectCount` на единицу оператором `++`.
4. Считайте следующее показание в ту же переменную `sensorDistanceReading`.

Любое отрицательное число завершает ввод и не участвует
ни в количестве показаний, ни в сумме, ни в подсчёте опасных объектов.
Поэтому при отрицательном первом показании тело `while` не выполняется ни разу.

После цикла выведите три строки в следующем порядке:

| Подпись              | Значение                    | Переменная             |
|----------------------|-----------------------------|------------------------|
| `Sensor readings:`   | Количество показаний        | `sensorReadingCount`   |
| `Sensor sum:`        | Сумма расстояний            | `sensorDistanceSum`    |
| `Dangerous objects:` | Количество опасных объектов | `dangerousObjectCount` |

В основном тесте показания `450`, `90`, `210`, `40` дают количество `4`,
сумму `790` и `2` опасных объекта; завершающее значение `-1` не учитывается.

## 7. Этап 6. Проверка контрольных точек маршрута

Перед циклом создайте «маяк найден» (`isTargetFound`) типа «логический» (`boolean`)
со значением `false`. Он понадобится для поиска на следующем этапе.

Циклом `for` перебирайте точки от `1` до `checkpointCount` включительно.
Объявите в нём «номер текущей контрольной точки» (`checkpointNumber`)
типа `int` с начальным значением `1`; увеличивайте его оператором `++`.

Каждая четвёртая точка (`4, 8, 12, 16 ...`) закрыта для сканирования.
В начале каждой итерации проверьте оператором `if`, равен ли
остаток от деления `checkpointNumber` на `4` нулю; используйте `%` и `==`.

Для закрытой точки выведите `Checkpoint [номер]:      RESTRICTED`, подставив
`checkpointNumber`, и выполните «перейти к следующей итерации» (`continue`).
Используйте `continue` именно для закрытых точек:
никакая обработка ниже него на этой итерации выполняться не должна.

## 8. Этап 7. Поиск маяка

Продолжите **тот же цикл `for`** после проверки закрытой зоны.
Для каждой непропущенной точки:

1. Выведите `Checkpoint [номер]:      scanning`, подставив `checkpointNumber`.
2. Сравните `checkpointNumber` с `targetCheckpointNumber` оператором `==`.
3. Если номера совпадают, присвойте `isTargetFound` значение `true`,
   выведите `TARGET FOUND AT CHECKPOINT [номер]` с текущим номером
   и немедленно завершите цикл оператором «прервать цикл» (`break`).

Используйте `break` только после успешного обнаружения искомой точки.
После него оставшиеся точки не проверяются.

Если искомая точка — `4`, `8` или другая закрытая, сначала срабатывает `continue`:
маяк не будет найден, а перебор продолжится. Не меняйте порядок проверок ради результата `true`.

## 9. Этап 8. Результат поиска

После цикла создайте «статус поиска цели» (`targetSearchStatus`) типа `String`.
Тернарным оператором (`?:`) выберите `"FOUND"`, если `isTargetFound` равно `true`,
иначе `"NOT FOUND"`.

Выведите `Search status:` и значение `targetSearchStatus`.

## 10. Этап 9. Построение карты области

Выведите квадратную карту размером `mapSideLength × mapSideLength`
**двумя вложенными циклами `for`** с отдельными счётчиками типа `int`:

* «индекс строки карты» (`mapRowIndex`)     — счётчик внешнего цикла;
* «индекс столбца карты» (`mapColumnIndex`) — счётчик внутреннего цикла.

Оба счётчика начинают с `0`, увеличиваются через `++` и принимают значения
меньше `mapSideLength`. Объявите `mapColumnIndex` в заголовке внутреннего цикла:
для каждой новой строки перебор столбцов должен заново начинаться с `0`.
Например, для стороны `5` оба индекса изменяются от `0` до `4`.

Во внутреннем цикле оператором `if` проверьте одновременное равенство
`mapRowIndex` и `beaconRowIndex`, а также `mapColumnIndex` и `beaconColumnIndex`.
Используйте `==` и логическое «И» (`&&`). При совпадении выведите `"B"` — маяк,
иначе `"."` — обычную клетку.

Клетки выводите методом «вывести без перехода на новую строку» (`System.out.print()`).
После внутреннего цикла вызовите `System.out.println()`, чтобы перейти к следующей строке.
Карту стройте по введённым координатам маяка независимо от результата поиска на маршруте.

## 11. Этап 10. Итоговый отчёт миссии

После карты выведите строки отчёта в указанном порядке, подставляя значения из переменных:

| Подпись              | Значение                    | Переменная               |
|----------------------|-----------------------------|--------------------------|
| `Mission:`           | Название миссии             | `missionName`            |
| `Battery:`           | Заряд со знаком `%`         | `batteryLevelPercent`    |
| `Sensor readings:`   | Количество показаний        | `sensorReadingCount`     |
| `Dangerous objects:` | Количество опасных объектов | `dangerousObjectCount`   |
| `Target checkpoint:` | Искомая точка               | `targetCheckpointNumber` |
| `Search status:`     | Статус поиска               | `targetSearchStatus`     |
| `Map size:`          | Размер карты                | `mapSideLength`          |

В строке `Map size:` подставьте `mapSideLength` дважды,
разделив значения латинской буквой `x` без пробелов, например `5x5`.

## 12. Основной тест

Скомпилируйте и запустите программу. Последовательно введите:

```text
   Arctic Explorer   
10
75
10
7
5
2
3
450
90
210
40
-1
```

Пробелы по краям названия миссии должны удалиться. Заряд `10` отклоняется, затем принимается `75`.
Точка `4` пропускается как закрытая; после обнаружения маяка в точке `7`
точки `8`, `9` и `10` уже не проверяются.

Ожидаемый вывод:

```text

Battery accepted:  75%
3
2
1
LAUNCH
Sensor readings:   4
Sensor sum:        790
Dangerous objects: 2
Checkpoint 1:      scanning
Checkpoint 2:      scanning
Checkpoint 3:      scanning
Checkpoint 4:      RESTRICTED
Checkpoint 5:      scanning
Checkpoint 6:      scanning
Checkpoint 7:      scanning
TARGET FOUND AT CHECKPOINT 7
Search status: FOUND
.....
.....
...B.
.....
.....
Mission:           Arctic Explorer
Battery:           75%
Sensor readings:   4
Dangerous objects: 2
Target checkpoint: 7
Search status:     FOUND

```

Дополнительно проверьте значения, не выводимые отдельными полями:
`checkpointCount` равно `10`, а `isTargetFound` равно `true`.

Приглашения к вводу (`Введите...`) можно добавлять по своему усмотрению.
При сравнении результата ориентируйтесь на содержательные строки образца.

## 13. Дополнительные тесты для самопроверки

В каждом тесте возьмите данные основного теста и измените только указанные ниже значения.

### Тест 2. Заряд сразу корректный

Вместо двух попыток заряда `10` и `75` введите сразу `75`.
Тело `do-while` должно выполниться ровно один раз, сообщение об ошибке не выводится.
Это проверяет свойство `do-while`: тело выполняется хотя бы один раз.

### Тест 3. Маяк расположен в закрытой контрольной точке

Оставьте `checkpointCount = 10`, замените `targetCheckpointNumber` на `8`.
Точки `4` и `8` должны получить статус `RESTRICTED`, сообщение `TARGET FOUND...`
не выводится, а цикл продолжает работу до точки `10` включительно.
Ожидаются `isTargetFound = false` и `targetSearchStatus = "NOT FOUND"`.

Этот тест проверяет, что `continue` выполняется **до** проверки искомой точки.

### Тест 4. Маяк найден сразу

Замените `targetCheckpointNumber` на `1`. После первой точки должен сработать `break`;
строки проверки точек со `2` и далее не выводятся.

### Тест 5. Нет показаний датчика

Вместо последовательности `450`, `90`, `210`, `40`, `-1` введите только `-1`.
Тело `while` не должно выполниться ни разу: `sensorReadingCount`, `sensorDistanceSum`
и `dangerousObjectCount` остаются равными `0`.
Этот тест показывает отличие `while` от `do-while`.
